## 4. 车道 prompt 的固定件(每份都要有)

```
【★ 收工判据】报告「跑完」之前必须:① `git status` 为空 ② 已合进 main ③ 交回带**提交号**。
```

★ 这条不是客套 —— 2026-08-07/08 两天内**六次**东西躺在工作树里差点丢
(doctor ⑫ 环 · V11 两份产物 · V15 四份 · V13 一批 · V19 · **V21**),
而 **V21 是连报两遍**的:它自己在决议包里写着「这一轮两次报告『跑完』,而 git 里一条提交都没有」。

### ★★★ 而且:**「跑完」必须用机器判据,不看车道的自述**

上面那条是给车道的**要求**;下面这条是给你的**验法** —— 两者不是一回事。
**六次里没有一次是车道主动说"我没提交"的**,全都是报告「跑完了」。
⇒ 交回的那一刻,协调层**第一件事**跑这两条,**在读它的交回正文之前**:

```bash
git -C <worktree> status --porcelain | wc -l     # 必须是 0
git rev-list --count main..<branch>              # 必须 > 0
```

> **两个数不是 `0` 和 `>0` ⇒ 当作没跑完。** 不管交回写得多详细、数字多好看。

★ 为什么要"在读正文之前":交回正文里那些实跑数字**是真的**——
它们就是在那个没提交的工作树里跑出来的。**先读正文会让你相信它跑完了,而那与"提交了没有"无关。**
★★ 这两条命令是**机器判据**,而交回正文是**自述**。
本项目对这一对的裁决一向是同一句:**判据看得见的,不问它自称是什么。**
★ 临时目录会被清理 —— 一份没提交的活,和没干过的区别只在你什么时候发现。
