  而程序目录多大又取决于运行时(§7 待核实 1,**未知**)。**三层未知叠着,估出来的数没有量程。**

**能给的是【比较的基准】**(实测,`dist/`,2026-08-11 出包那一轮):

|---|---|

### 3.2 许可义务 —— MIT 的义务只有一条,但**今天它没有地方落**

**义务本身**(设计 :350–353 已核过一轮口径):MIT 允许商业使用、修改、集成进闭源产品、
再分发与销售,**唯一义务 = 保留版权与许可声明**。⇒ 不是 signal-cli 那种 AGPLv3 的网络源码义务。

**但落地要做三件,今天一件都没有**:

1. **安装目录里要多出一个文本文件**(第三方版权与许可声明)。
   ★ 实测确认:`dist\client\安装说明.txt`、`dist\README.txt` **通篇没有任何许可文字**;
2. ★ **它不能手写进 `dist\README.txt`** —— 那个文件第一行自己写着
   「本文件由 `90-ops\build-client.ps1` **每次出包重新生成**,不要手改」。
   ⇒ **要改的是 `build-client.ps1`,不是那个 txt。** 手写一次,下次出包就没了;
3. **MIT 只覆盖本体**(设计 :582)—— 不覆盖依赖树、内置 Skills/Plugins、模型权重、
   在线服务条款、商标。⇒ **依赖树 license checker 是 DD-16 的唯一硬前置**,
   查出 AGPL/GPL 传染项 ⇒ 退回「引导用户自取」(此时才是 signal-cli 的**真**理由)。

### 3.3 构建链

- 今天的构建链:.NET(客户端/管理端/host)+ Python(网关/记忆)+ PowerShell(ops)。
  Hermes 进来 = **第二运行时台账**(D65 代价栏已明写,依赖 · 更新 · CVE 另立);
- ★ **出包这条路今天已经很紧**:`build-client.ps1` 单趟约 **13–15 分钟**(单文件+压缩),
  而 **D124 裁定③** 逐字记着它**没有并发闸**,并且在这棵每几分钟就动一次的树上
  「**构建结构性地不可能成功**」。⇒ 往这条已经是瓶颈的脚本上再加一件产物,
  **应当排在 D124 那条治本(钉死提交的临时 worktree 出包)之后**,不要抢在它前面。

### 3.4 钉 commit 怎么钉

- **没有 Authenticode 可用**:worker 是容器镜像 / 发行版 tar / 程序目录,
  不是官方签名的 exe ⇒ VB-CABLE 那套「装前验官方签名」**信任模型不能照抄**,必须回到**钉死 SHA-256**;
- **可以照抄的是形状**:`AudioDriverManifest.cs`(可覆盖清单 + **编译进程序的域白名单** +
  **失败不给"仍然继续"**);★ 那份文件里那条纪律一并继承:
  「**凭印象写一串十六进制不是默认值,是伪造证据 —— 那比没有更危险。**」
- ★ **DD-16 让这一格变简单**:自带分发 ⇒ 产物是**我方构建的** ⇒ 哈希由构建过程产出、确定可知,
  **不需要"从官方域下载"这条链,也没有留空哈希的理由**;
- **版本闸的语义是「是否 = 我方钉定的 commit」,不是「是否最新」**(DD-13 ①),
  不匹配 ⇒ 拒绝启动并说清要做什么(照 `start-stack.ps1` 显存闸那个已被验证的形状)。

### 4.2 替身能补的五格 —— 都不需要 Hermes 本体

### 4.3 ★★ 替身**验不到**的是什么(这一节必须和上面分开读)

1. **替身证明的是「这道门对【某一类】程序关着还是开着」;
   它证明不了「**Hermes** 在里面活得下来」。**
   决定后者的,是 Hermes 实际会碰哪些东西 —— 而 §7 待核实 1(**运行时与语言**)至今未答。
   ⇒ **我们连"替身该做成什么样"都还没有依据。**
2. ★ **顺序反了会白做**:一个 **.NET self-contained** 的替身,
   对一个 **Electron 应用**几乎没有预测力(单例锁、沙箱子进程、GPU 进程全在它之外);
   对一个 **Python 应用**也没有(要看解释器与 site-packages 落在哪、可不可见)。
   ⇒ **先取 §7-1,再做替身。** 反过来做,做出来的数只描述了替身自己。
3. **承重项(§7-3:工具能否由调用方注入、自带注册表能否完全清空)替身一格都碰不到。**
   这条不成立 ⇒ **D65 作废,退回选项 D**。它只能靠读 Hermes 的配置与源码来答。
4. 替身也答不了 §7 的 2(API 契约)、4(Memory 能否关)、4b(**多会话是否串**)、
   4c(起停延迟)、5(依赖许可)、6(commit)、8(体积)。

**一句话**:**替身能把「这道门对什么样的程序关着」量出来;量不出「我们要塞进去的是什么样的程序」。**
前者今天就能做,后者必须先取证。

### 4.4 做替身的成本与副作用(如实说)

- **改 spike 不会让任何测试变红或变绿**:它自己的 README 前 22 行就写明
  「不进门禁」,`run-tests.ps1` 的扫描根**写死 `10-core` 且只收 `test_*.py`」⇒
  `90-ops/spikes/` 下的东西**永远不会被跑**。它的产出是一张表,不是一个绿灯;
- **要动机器状态的只有一格**:回环豁免列表(两个 `.cmd` 自己恢复,进场非空则**拒绝清空**);
  ★ 上一轮在这上面出过两次事故并已复原(包 §1.2 / §1.3),还留了 **5 个删不掉的 0 字节 socket 文件**(§1.4.1);
- **`--lan` 别顺手开**(会弹防火墙框并留下持久规则);
- ★ **本机 `EnableLUA=0`**,一切进程皆 High ⇒ 两个 `.cmd` 的「提权/非提权」区分**在这台机器上是失效的**。

> ⇒ **这是唯一一个能让 DD-16「自带分发」当场作废的数,而它今天没有人量过。**
