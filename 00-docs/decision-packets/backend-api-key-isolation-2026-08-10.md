## 2. ★★ 那一格未测的:`/health` 受不受 key 约束

**答案:不受。** 实测(llama-server 10107,本机真起了带 key 的实例逐个打):

| 端点 | 不带 key | 错 key | 对的 key |
|---|---|---|---|
| `/health` | **200** | — | 200 |
| `/v1/models` | **200** | — | 200 |
| `/props` | **401** | 401 | 200 |
| `/v1/chat/completions` | **401** | **401** | **200** |

⇒ **好消息**:动工前最担心的那一格排除了 —— 加 key **不会**让 `curl -sf /health`
的就绪闸变红,栈不会起不来。

⇒ **坏消息,而且更重要**:`/health` 看不见「钥匙对不对」。
钥匙不匹配时栈会**报「已就绪」**,然后每一次对话都 401 ——
**失败发生在启动,却要等用户第一次开口才显形**。§12.3 明令禁止这种形状。
**所以两处就绪闸都补了一次带鉴权的 `/props` 探测。** 这是本次唯一一处
「因为实测结果而多做的事」,也是这一格实测最大的收益。

### 2b. ★★★ 另外两条实测,一条是**真陷阱**

- `--api-key-file` 指向**不存在**的文件 ⇒ llama-server **拒绝启动**(fail-closed,好)。
- `--api-key-file` 指向**空文件** ⇒ llama-server **照常启动,而且完全不鉴权**
  (空 key 起的实例,不带 key 打 `/props` 回 **200**)。
  ⇒ **一个 0 字节的文件会静默地把门重新打开,而所有「启动成功」的迹象都还在。**
  ⇒ 对策落在 `backend_key.py`:写入走 `os.replace` 原子落盘,
    读取端逐条校验(长度 ≥ 32 · 单行 · ASCII),**没过校验的内容绝不交出去**。
- key 文件的行尾 llama-server 会自己剥(CRLF 文件配无 `\r` 的 key,实测 200)。
  我们仍按**无行尾**写 —— 少一个「两边各自 strip 得不一样」的机会。

## 3. ★★ 钥匙放哪 —— 协调层给的落点会让栈起不来

**实测**:`runas /trustlevel:0x20000`(中等完整性令牌)去读 `{state}\secrets` ⇒ **READ_DENIED**。

原因:该目录只授 `SYSTEM / BUILTIN\Administrators / ai-mem`,而 **UAC 过滤令牌里
`Administrators` 是 deny-only 组**,那条 allow ACE 不生效。

而网关**就是**中等完整性进程,并且是**有意的**:
`20-client-win/admin/Program.cs` 的 D46 护栏在发现自己被提权时会**主动降权重开**
(TPM/CNG 用户密钥绑定铸造时的完整性等级),网关由它拉起 ⇒ 继承 medium。

⇒ 钥匙放进 `secrets` = **用户第二天双击管理端,栈起不来** ——
正是本车道最担心的那个后果,只是成因不是 `/health`,是 ACL。

**也不能「给 secrets 加一条机主 ACE」**:那会让机主身份下**任何**中等完整性进程
都能读到 CA 私钥与 L4 批准密钥 —— 为了一把可再生的口令,拆掉一道真的墙。

**也不能新增一步提权**:`HostProvision` 里有一条断言明写「全文件只允许**一处**提权」
(只给防火墙那一步),而 D46 禁止身份继承 High。

### 落点与手法(实测可行,零提权、零用户步骤)

```
{state}\backend-auth\llama-api.key          # paths.toml [state] backend_auth
```

- **建目录 + 断继承 + 设 DACL,中等完整性令牌做得到** —— 实测:
  `MKDIR_OK / INHERIT_R_OK / GRANT_OK / WRITE_OK`,结果 DACL 恰好三条:
  `SYSTEM` · `Administrators` · 机主。**没有 `Authenticated Users`、没有 `Users`。**
- ⚠ `{state}` 根继承下来的是 `Authenticated Users:(M)` ⇒ **不断继承就等于没设锁**。
- ACL **每次用之前重新施加并回来核验**,不假定装机时设过
  (「假定前提从来没被建立过」正是 start-stack.ps1 里 sysmem-fallback 那段的教训)。
  施加失败 ⇒ **拒绝交出钥匙**,不起后端。
- 判据拿 **SID** 比,不拿显示名比(显示名在别的语言版 Windows 上是另一串字)。

### 为什么它**语义上**也不属于 secrets

`secrets` 是「长期第三方凭据与私钥」——丢了会被**接管**,必须重新签发。
本密钥是**本机自产、随时可重新生成**的进程间口令,丢了的代价只有一个:
已经在跑的后端要跟着重启一次。两类东西恢复语义不同,
混在一个目录里迟早有人按错的那套规矩处置它。

### 生成时机 · 轮换 · 丢了怎么办

| 问题 | 答案 |
|---|---|
| 生成时机 | **起后端之前**(`ensure_key_file()`)。已存在且合法就原样保留,**不重生成** |
| 为什么不每次重生成 | 会让此刻还在跑的、被 `ModelLoader` 认领的后端当场变成 401,而那件事 `/health` 看不见 |
| 自动轮换 | **不做**。钥匙从不离开本机、没有可撤销的对端;自动轮换只会制造「轮换那一秒对话全 401」的窗口 |
| 手工轮换 | 停栈 → 删文件 → 起栈 |
| **丢了怎么办** | 删掉即可,下一次起栈自动重新生成。**代价只有一个**:此刻还在跑的后端握着旧钥匙 ⇒ 网关 401。**而这一格由带鉴权的就绪探测当场报出来**(§2),消息里直说「把后端一起重启」 |
| 进不进备份 | **不进**(backup.ps1 `$excludeAbs`)。理由与 secrets **不同**:不是「丢了会被接管」,是「备了没用(换机后对不上任何新后端)+ 多一份泄露面(备份盘 exFAT 不加密,D21)」 |

## 4. 判据 —— 本车道的全部价值

### ★ 正向

`10-core/gateway/test_backend_key.py`:带对钥匙 → 200,且**出站请求上真的有**

| 在哪 | 判据 |
|---|---|
| `test_backend_key.py` | 错钥匙 → **401**;把 `headers=` 摘掉 → **401**;且后端确实收到一个没有 Authorization 的请求 |

所以「摘掉钥匙」在桩上和在真后端上是同一个结果。

### ★★★ 元断言:凡起模型后端的地方都必须带上钥匙

`90-ops/gate/check_backend_auth.py`,**三个遍历源都不是它自己的表**:

1. **kind 反向全表** —— 遍历源是 `model_loader.SUPPORTED_KINDS`。
   新支持一种后端 kind 而不登记 ⇒ **红**。(盖住「语音 / 画图 / 第三处」)
2. **起法逐处** —— 遍历源是**全仓扫 `'-ngl'`**。
   新加一处 llama 起法而不带 `--api-key-file` ⇒ **红**;带了但没登记 ⇒ **也红**。
   (盖住「第二个 llama 实例」)
3. **消费侧** —— 每一处出站转发都必须带 Authorization;取不到钥匙必须 503。

★ 登记表只当**期望值**,绝不当遍历源(ASSERTION-PITFALLS 3b)。
★ 提取器**两个方向都被钉住**(能抓 + 不误抓 + 不吃散文)。
★ 守卫放 `90-ops/gate/` 而不是 `10-core/`:它同时检查 PowerShell 与 Python 两侧,
  放进任何一侧,那一侧就成了自己的裁判。
★ 它**自排除本文件**(第 ⑤ 组的正反样本里就写着 `'-ngl'`,不排除会当场绊倒自己),
  而自排除表被钉成**恰好一条且必须是它自己** —— 排除表就是个藏东西的地方,不许长。

## 6. 没做的(如实记账)

1. **`/v1/models` 不受 key 约束** —— 别名/模型清单对同机进程仍可见。
   不构成「能用模型」,但也别当它被锁上了。verify 脚本会把这条**打印出来**。
2. **`speech` 后端没有鉴权**(见 §5)。
3. **`model_loader` 的按需装载路径没做真 8B 实机装载** ——
   它的起法 args、就绪闸行为、`_auth_ok` 正反两向都被断言钉住,
   且 `_auth_ok` **对着真后端跑过一次**(对钥匙 True / 错钥匙 False);
   但「Broker 真的装一次 8B 并带上钥匙」没有实机跑过。
   `start-stack.ps1` 那条路径**是实机跑通的**(端到端 200 + 直连 401)。
4. **本车道不消解 D65 待决 6** —— B 与 A/C 不互斥,C(AppContainer,禁回环)
   那一格仍待测。B 消掉的是**技术债本身**,并且对跑腿程序之外的其它低信任进程同样有效。
5. **同用户、同完整性等级的进程读得到这把钥匙** —— 这是 NTFS ACL 的固有边界,
   不是实现缺陷:网关跑在机主身份下,任何同身份同完整性的进程与它平级。
   B 真正、完整堵死的是**跨账户**那一面(`ai-exec` / `ai-asset`),而那正是 D65 点名的威胁。
