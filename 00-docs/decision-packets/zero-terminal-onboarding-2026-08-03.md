# 零命令行上手:一个客户端程序,主副机共用,自己找到对方(决议草案 · 取号待定)

> 日期:2026-08-03
> 提出:用户 —— 「最终目的就是让主机和副机共用同一个客户端程序,无痛丝滑,
> 不需要跑任何命令栏和设置什么,直接找到对方然后安全匹配连接」;
> 澄清:「不跑命令栏和设置**是指用户**,我们程序可以来跑这些」。
> 车道:**client** 实现绝大部分;**core** 需要加两个接口(§3、§5.1)。
> 性质:**草案**,取号按 D75 办。

---

## 1. 目标态

一个 exe,装到任意一台机器上。首次运行问**一次**「这台当中枢主机,还是连到已有的主机」,
之后不再需要终端、不再需要读文档。

## 2. 拆开看:每一步谁来做

| 步骤 | 今天 | 结论 |
|---|---|---|
| 铸中枢身份 | `dist\host\重置并铸身份.cmd` | **客户端来做** —— 见 §2.1,这不只是方便,是**更正确** |
| 放行防火墙 8443 | `90-ops/lan/lan-firewall.ps1`(需管理员) | **客户端触发一次 UAC**,只提这一个脚本 —— 见 §2.2 |
| 启动 LAN Edge | 已做成按钮(`fa60ea8`) | 客户端来做 |
| 启动后端 + 网关 | `90-ops/start-stack.ps1` | 客户端来做(同 Edge 的办法) |
| 主机自配对 | 1 次点击(`50a1afe`) | core 补 §5.1 后降到 0 |
| 副机找到主机并配对 | 2 次点击 | 加敲门(§3)后副机侧 **0** 次点击 |

### 2.1 ★ 铸身份【应该】由客户端做,而不只是"可以"

CA 私钥绑定**创建它时的完整性等级**。客户端按 D46 **恒为普通用户**
(`Services/Elevation.cs` 用 Mandatory Label SID 判,不是 `IsInRole`)。
⇒ 由客户端拉起 `localai-identity init`,铸出来的身份**必然**在正确的上下文里。

反过来,人自己开终端跑就有一半概率开的是提权终端 —— 那会铸出一个
**普通用户的 Edge 永远打不开**的身份,而且**不可回退**(只能重置重铸、所有设备重配)。
`identity-elevation-guard-2026-08-03.md` 记着这个缺口。

★ 所以这一条不是"省一步",是**把一个不可回退的错误从可能变成不可能**。

### 2.2 唯一需要提权的一步,要单独隔离

防火墙规则必须管理员。做法:`ProcessStartInfo { Verb = "runas" }` **只对
`lan-firewall.ps1` 一个脚本**弹 UAC。

★ 三条纪律:
- **绝不**把 identity / Edge / 网关一起放进那个提权进程 —— 一旦它们继承 High,身份就毁了;
- 提权进程做完就退,不常驻;
- 用户拒绝 UAC 是**正常路径**,不是错误:如实说"没放行,副机会连不上 8443",并给出手动办法。

## 3. ★ 敲门(用户提议,采纳)—— 需要 core 加接口

### 3.1 为什么这条路成立,而我先前判错了

我先前说「主机没法知道局域网上有个客户端开着」。**那是错的**,只对一个方向成立:
主机去**发现**客户端 —— 那确实要给每台客户端开监听面(比 D43 推迟 mDNS 的理由更重)。

用户把方向反过来:**客户端主动去报到**。这样客户端**不需要监听任何端口**,仍是纯客户端。
成本只有中枢侧一个匿名接口。

### 3.2 协议

**`POST /pair/hello`**(业务口,匿名 —— 与 `/pair/*` 其余路由同级)

```
请求  { displayName, clientVersion, protocolVersion, csrSpkiSha256 }
响应  { invited: bool, inviteNonce?: string }
```

中枢记一条 `Knock { ip, displayName, clientVersion, csrSpkiSha256, firstSeen, lastSeen }`,
**TTL 15 秒**(副机每 5 秒敲一次 ⇒ 掉线三次就消失)。

**`GET /admin/pairing/knocks`**(回环管理面)—— 列出当前敲门者。

**`POST /admin/pairing/invite { ip, csrSpkiSha256 }`**(回环管理面)——
主机在列表里点「匹配」时调。它**同时**:开配对窗口、并把这一条标记为 invited。

副机下一次敲门(≤5 秒)拿到 `invited: true` ⇒ **自动开始 enroll**,六个词出现在两边屏幕上。

### 3.3 ★ 安全边界(必须写进代码注释,不是只写在这里)

- **敲门内容全部是自报的**,与 `displayName` 同级:**只作显示,永不进 prompt,永不作判据**;
- **必须限流 + 封顶**(参照 `Pairing.MaxPending = 8`)—— 这是一个**匿名写入**接口,
  局域网上任何人都能调。封顶后满了就丢新的,并在管理面如实显示"敲门列表已满";
- **敲门永远不弹窗**。弹窗只留给真正的 enroll 请求(带六个词)。
  否则局域网上任何人都能让主机屏幕上跳出东西,那是社工入口;
- **窗口开着时也不放松六词**:invite 把窗口按 IP + CSR 指纹收窄,减少竞争,但**不替代**比对。

### 3.4 ★ 六个词【仍然】不能省

诱人的说法是:"主机已经在列表里挑了那一台,还比什么词?"——不成立:

- 列表里的名字是**自报**的,可以写成「Zori 的笔记本」;身份只有一个 IP;
- 两条同名条目,主机操作者**分不出哪条是自己的**;
- 六个词覆盖 **CSR SPKI 指纹** —— 它才是把「你选的那一条」和「真正拿到证书的那台机器」
  绑在一起的东西。

⇒ 少了它,主机就是在**按名字点批准**。保留现有做法:确认按钮的文字本身就是那句断言,不提供跳过。

## 4. 首次运行:问一次,只问一次

```
没有中枢身份、局域网上也没扫到中枢
   → 「这台当中枢主机」 / 「连到已有的主机」
有中枢身份            → 直接走主机路径
局域网上扫到中枢       → 默认副机路径,但保留「其实这台才是主机」的入口
```

★ 这是**产品决策**,只有人能定 —— 但它是一个选项卡,不是一条命令。

选「主机」后客户端自己按顺序做:铸身份 → 一次 UAC 放行防火墙 → 起后端/网关/Edge →
自配对 → 完成。**每一步都要显示自己在做什么、失败时说真原因**(今天反复在修的就是这一类)。

## 5. 请 **core 车道**做的

### 5.1 回环 self-enroll(已在 `one-key-pairing-2026-08-03.md` §5.1 提过)
让主机自配对**一个局域网窗口都不用开**。

### 5.2 敲门三接口(§3.2)
`POST /pair/hello`、`GET /admin/pairing/knocks`、`POST /admin/pairing/invite`。

### 5.3 `/admin/devices` 透出 `LastSeenAt`(已在 `one-key-pairing` §5.2 提过)
并确认它**真的在更新** —— 如果它其实是配对那天写下就没动过,那这个字段比没有更坏。**要有断言。**

## 6. 三件去不掉的事(如实写在这里,免得后人以为还能再压)

1. **首次运行那一次选择** —— 产品决策;
2. **一次 UAC** —— 防火墙规则必须管理员。可以做到一次点击、不进终端,但那个框去不掉;
3. **六个词的人工比对** —— §3.4。这是整套准入唯一的人肉环节,去掉就等于按名字放行。

## 7. 分期

| 期 | 内容 | 依赖 |
|---|---|---|
| A | 客户端跑 identity init / 防火墙(一次 UAC)/ 后端+网关 | 无 |
| B | 首次运行向导 | A |
| C | 敲门:副机侧 5 秒一敲、主机侧列表 + 「匹配」 | core §5.2 |
| D | 主机自配对降到 0 次点击 | core §5.1 |

(「这台中枢还不支持敲门,请用现在的流程」),不假装功能存在。
