## 2. 角色分四种,一种都不许合并

```
Unknown     还没探完 —— 不猜,界面如实说"正在确认"
Host        回环管理面答话且 hubId 一致。★ 唯一的【肯定证据】
HostHubDown 探不到管理面,但本机装着主机端程序 ⇒ 多半是主机,只是 Edge 没起
Client      探不到,也没有主机端程序
```

★ `HostHubDown` 必须单列。把它并进 `Client`,就正好回到 2026-08-03 那个坑:
**主机上显示「这台不是主机」**,人跑去怀疑配错了机器,而唯一要做的是把 Edge 起起来。
自检里有断言钉住枚举是四个值。

★ 顺序也钉住了:**先看肯定证据,再看线索**。反过来的话线索会盖过证据。

## 3. 「未连接的副机」:一半做不到,不许含糊

- **已在册的副机**:`/admin/devices` 已有 ✓
- **「在册但现在离线」**:能做,但要 core 配合 —— `10-core/identity/Store.cs` 的 `Device`
  **已经有 `LastSeenAt`**(第 26 行),只是 `/admin/devices` 的投影没带上它。见 §5.2。
- **「启动了客户端但还没配对的副机」:做不到。**
  客户端不监听任何端口、也不广播,主机没有任何途径知道局域网上有个客户端开着。
  要做到就得给**每台客户端**开一个广播/监听面 —— 而 D43 当初推迟 mDNS,
  正是因为不想给**主机**多开一个"谁问都答"的面;给每台客户端开只会更重。

  ★ 界面上**不许**把「点了开始配对之后出现在待批准列表」说成「启动了客户端」——
  那是两件事。副机开着但没人点时主机这边是空的,混着说会让人去查网络。
  现在设备列表下面有一行明说「这里列的是【在册】,不是【在线】」。

## 4. 配对窗口:三道闸,各自独立

用户的追问是关键:**「只有主机没有副机,岂不是窗口永远开着关不了?」**
所以闸必须互相独立,谁先到谁生效,**没有任何一道依赖"用户记得关"或"客户端还活着"**:

1. **收起这一块 / 页面不可见 / 控件卸载** → 关(`Unloaded` + `IsVisibleChanged`);
2. **宽限有上限**(`GraceSeconds = 90`),而且到点**无条件**关。
   ★ 绝不能写成"队列非空就不关" —— 局域网上任何人塞一条(或一条卡住的请求)就能把窗口按住。
   宽限存在的唯一理由是:副机可能正卡在 enroll 那几秒,别当场掐断;
3. **中枢侧的分钟上限**(`WindowMinutes = 10`)自己到点失效 —— 和客户端在不在、页面在哪、
   进程有没有崩全都无关。**这是最后一道,也是唯一不依赖客户端的一道。**

### 4.1 触发器:用「展开」而不是「滚动位置」

用户提的是"滚到这个区域"。改成 **「＋ 添加一台新电脑」默认收起,展开才开窗**,两个理由:

- 滚动位置太脆:窗口缩放、页面短到整页可见、误触滚轮都会开窗;
- ★ 更要紧的:**只有主机、没有副机的人根本不会走到开窗那一步**。他滚过去看到的是
  「已配对的电脑」,纯展示。这正面回答了用户那个追问。

展开这个动作本身就是明确意图,不用再去别处找开关 —— 一键化的目标没有损失。

★ 保留既有审查结论:窗口**不随开机自动打开**。"展开即开"是**有人正看着屏幕**,
与"开机自启无人值守敞开"是两回事。但界面必须显示"已打开 + 多久后自动关"。

## 5. 请 **core 车道**做的两件事

### 5.1(要紧)回环 self-enroll —— 让主机自配对**一个窗口都不用开**

现在主机自配对的做法是:开窗 1 分钟 → enroll → 用回环管理面批准自己那条 → 关窗。
**那几秒局域网上的 8443 也接受请求。** 这是可以完全消除的:

给 `lan-edge` 加一条**只在回环管理口上存在**的 `/admin/pairing/self-enroll`,
内部调用 `Pairing.Enroll` 时**绕过窗口检查**。理由:

- 管理面的门禁是「端口 + 回环」,能调它的人已经在这台机器上了;
- 他本来就能 `/admin/pairing/approve` 批准任何请求 —— **不增加任何权限**;
- 换来的是:局域网上的准入窗口**一秒都不用开**。

★ 落地后 client 车道把 `SelfPairAsync` 从"开窗"改成走这条,并把界面上那句
"会把配对窗口开几秒"的说明去掉。

### 5.2 `/admin/devices` 透出 `LastSeenAt`

`Store.Device.LastSeenAt`(`10-core/identity/Store.cs:26`)已经有了,
`10-core/lan-edge/Program.cs` 的 `/admin/devices` 投影没带。加一个字段即可,
client 侧就能把「在册」升级成「在册 / 现在在线 / 最后一次是什么时候」。

★ 同时请确认 `LastSeenAt` 是**真的在更新**(每次 mTLS 业务请求都刷)——
如果它其实是配对那天写下就再没动过,那这个字段比没有更坏,
界面会拿一个假的"最后在线"去误导人。**这一条要有断言。**

## 6. ★ 唯一不许一键化的那一步:六个词

弹窗可以做,**但不能给个「确定」就完事**。

客户端本来就会独立算一遍 SAS 并和主机返回的比,对不上就中止 ——
**中间人那一层是自动挡住的,不需要人参与。**
六个词在**主机批准**这一步管的是**另一件事**:

> 确认【你批准的这条请求,就是你那台机器发出来的】。

局域网上任何人都能往待批准队列里塞一条,而 `displayName` 是**自报**的,
可以写成「Zori 的笔记本」。没有这一比,弹窗就退化成"来了个请求,点批准" ——
准入就交给了**谁先按弹窗**。

实现上:确认按钮的文字**本身就是那句断言**(「六个词逐字一样 —— 批准」),不是中性的"确定";
另一个按钮是「不一样 / 先不批」(走 `DenyAsync`);**不提供任何跳过**。自检里三条断言钉住。
