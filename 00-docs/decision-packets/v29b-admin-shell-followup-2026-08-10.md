### 5.3 ★★★ 第三条:`RetireModelTask`「唯一入口」—— **误报**,而且判据在我地盘

- **归属自证**:在**干净的 main(`9a12ae4`)**上跑 `admin --selftest` ⇒ **FAIL=1**,同一条。
  我一个字都没改。`RetireModelTask` 是 **V30b** 加的(`3d4b660`)。
- **它是误报**:那个函数**有**生产调用点 —— `app/Services/ModelReadiness.cs:270`
  `RetireModelTask(a, now);`。断言却说「全仓生产源码里一个调用点都没有」。
- **根因在 `admin/SelftestMoved.cs`(我的地盘)**:`QualifiedCallSites` 只数**限定形式**
  `\.Method\(`。它自己的注释写着理由:「**这几个入口本来就都是静态工具函数**,
  全仓都写成 `Type.Method(...)`」—— 而 V30b 那个是 `private` **实例**方法,
  在自己类里被**无限定**调用 ⇒ 数到 0。
- **修法**:改成「数所有 `Method(`,再减去它自己的**声明**」。声明的形状是
  「行首 → 可选特性 → 可选修饰符 → 一个返回类型 token → 方法名 → `(`」,
  而调用点前面没有类型 token ⇒ 两者仍然分得开,只是不再假设入口一定是静态的。
  旧理由**原样留着**,加了时态。

**红测**:把 `StackBoot.cs:141` 那条唯一的生产调用点拿掉 ⇒ **当场红**(`EnsureStackAsync`)。
★ 第一次红测**我做错了**:我加了个 `RedTestTempAsync` 转调 `EnsureStackAsync`,
那本身就是一个新的调用点 ⇒ 判据没红,而我差点据此以为修松了。
**记一笔:红测本身也会写错,而写错的红测长得像"判据坏了"。**

⇒ 修完 `admin --selftest` **FAIL=0**(见 §7)。
