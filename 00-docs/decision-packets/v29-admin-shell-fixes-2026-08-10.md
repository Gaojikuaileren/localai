## 1. ① 滚轮全局可滚

### 真凶(网格量出来的)

真窗口上打 4×5 网格:逐点命中测试 → 逐点发一次滚轮(**先隧道 Preview 再冒泡**)→ 逐点读根 `VerticalOffset`。

| 页 | 20 个点里滚不动的(修前) |
|---|---|
| 主机中枢 | 0 |
| **模型** | **12** ★ |
| 记忆库 | 0 |
| 客户端与栈 | 0 |

死因:内层那个 `Ui.Page` 的 ScrollViewer **高度由内容撑满,`ScrollableHeight == 0`** ——
**一个像素都滚不动,却把每一个滚轮都吞掉**。这正是 `WPF-PITFALLS` 第 4 条点名的最阴那一种:
「起手就已经在边界上,于是开屏第一下就是死的」。

### 修法 —— **一网打尽**,不是逐处挂

`admin/Views/AdminScroll.cs`:给 `ScrollViewer` 挂一个**类处理器**监听 `ScrollChangedEvent`,
第一次排版时就把 `Wheel.PassThrough()` 装上,用附加属性保幂等。

- 让路逻辑**一个字都没重写** —— csproj `<Compile Link>` 了 `app/Views/Wheel.cs`(+ 它依赖的 `WheelPicker.cs`,`Wheel.cs:28` 要 `WheelColumn.IsInsideWheel`)。
- **两个条件**(都是踩出来的,写进 `ShouldTame`):只给**内层**装(最外那个没有"外层"可让,装了会让页面滚到底时连文本框也不动);**得真有父级可抛**(`Parent is UIElement`,否则 `e.Handled=true` 之后抛不出去,滚轮当场消失)。
- 锚点为什么不是 `Loaded`:三个候选都实测过 —— `Loaded` **抓不到后加进树的** ScrollViewer,而异步填完才进树的列表正是用户真正会去滚的那些。

### 普查:**几处?**

用户问的是"普查了几处"。诚实的答案分两层:

- **网格**:四页 **64 个点**(80 个格点里有 16 个命中落空),修后**死 0 个**;
- **树内普查**:四页走过 **6 个** ScrollViewer(窗口根 ×1 · ModelsView 的页中页 ×1 · TextBox 模板内的 `PART_ContentHost` ×4 次遍历命中),漏挂 **0 个**;
- ★ 而**真正需要改的只有 1 处**(ModelsView 的页中页)。之所以仍然做成一网打尽,是因为用户那句「一个修法漏改一处,缺陷就完整地留在那一处」—— 今天只有一页中招,是因为管理端今天只有四页;「新写的页顺手调一下 `Ui.Page`」是最容易再犯的一步,它编得过、看着对、只是滚不动。

### 护栏红测(要求「而且要能红」)

`admin/SelftestWheel.cs`,三条主判据 + 四条元断言。**红测做过**(反向 Edit 摘掉 `AdminScroll.Install()`,不是 `git checkout`):

```

      model(60,120)→TextBlock、model(700,120)→TextBlock、model(60,200)→Border …)
FAIL  **树里每一个该让路的滚动区都让了路**(走过 6 个,漏 2 个:

主机管理端 selftest: PASS=356 FAIL=2
```
装回去:`FAIL=0`。

★ 反向那条也钉了(`WheelInnerKeepsIt`):内层**自己还能滚**时,滚的是它、整页不动(实测内层 144 · 外层 0)。
没有它的话,「一律往上抛」那种实现也会全绿,而它让人在记忆库正文框里改不动字。

### 顺手写进 `WPF-PITFALLS.md`(只追加,49 行 0 删除)

新增第 15 条「页中页」。含:怎么确认是不是它(打网格)· 两个条件 · 三个锚点的实测对照表 ·

### ★★ 落法上收窄了一处 —— 不是无脑全勾

**只在中枢那份授权是空的时候**才默认全勾;中枢已经记着(哪怕一个)⇒ 以中枢为准。

没有这一条会长出一个**比原问题更坏**的缺陷:用户取消勾选 → 点确定 → 中枢记下少的那份 →
再打开这一页被**重新勾回全部** → 下次确定又悄悄授权回去 ⇒ **这一页永远撤不掉授权**,
而那正是 D90 裁定①要防的事的另一种形状。

★ 代价如实记账(写进决议包 §4):**「撤销全部」这一档下次打开会回到全勾** ——
中枢那边「从没授权过」与「授权后全撤了」在线上是同一个值(空数组),分不开。
分开它要在管理端存一份本地隐藏状态,而本条的用户意图是「默认」不是「锁死」⇒ 不加。

### 护栏

规则抽成静态纯函数 `ComponentPicker.InitialPermitted`(**生产走的就是它**),
`admin/SelftestOnDemand.cs` 把**两支都真的走一遍** —— 实机中枢上已经有 9 个授权,

另在 `SelftestLiveViews.LiveModels` 加了**接线**判据(真中枢下,面板里那份集合真的是它算出来的)。
