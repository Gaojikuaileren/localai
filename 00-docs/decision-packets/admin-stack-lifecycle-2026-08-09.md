## 0. 实况复核(协调层说的,与实测对照)

协调层给了四条实况并要求复核。**三条属实,一条比描述的更严重,还有一条说反了。**

| # | 协调层的说法 | 复核结果 |
|---|---|---|
| ① | `EnsureStackAsync` / `StackResult` 生产调用点 **0**,唯一引用者是 `admin/SelftestMoved.cs` | **属实**。全仓限定调用 `.EnsureStackAsync(` 只在自检里出现 |
| ② | `HostHubView` 有铸身份/防火墙/批准配对,**没有起栈动作、没有进度** | **说反了一半 —— 而反的方向让问题更难看见**。见 §0.1 |
| ③ | 「客户端与栈」页文案说进度在「主机中枢」页,而那页没有 ⇒ 两页互相担保 | **属实**(`AdminWindow.cs:149`) |
| ④ | 关栈「**这一半是接上的**」,只需核实确认之后是否真的停了 | **不属实。关栈根本没有「停」这个动作。** 见 §0.2 |

### 0.1 ② 的实情:不是「没有起栈动作」,而是**有第二套**

`HostHubView` 里有一条完整的起栈路径:`StartEdgeStepAsync` → `StartEdgeAsync`,
它自己 `Process.Start` 一个 `localai-lan-edge.exe`,有进度、有日志、有探活。

**而这恰恰是 `EnsureStackAsync` 零调用点却没人察觉的原因** ——
界面上确实有一条能起 Edge 的路,所以「起栈入口没接上」从表面上看不出来。

两套的差别是实打实的:

- 这一套**只起 Edge,从来不起网关** ⇒ 起完之后「模型」页仍然是空的;
- 它只在 `HostHubDown` 那一档才画出来。Edge 起着而网关没起时,页面走 `Host` 档,
  显示「这台电脑就是中枢主机」**一路绿灯,而且整档从不检查网关**;
- 两套同时跑会各起一个 Edge,第二个撞 `address already in use`(退出码 4)。

> ★ 写这段时本机的真实状态正是那个最坏中间态:**8442 通 / 8080 不通**。
> 也就是说,协调层说「那一页没有起栈动作」时,那一页其实正在对着一个半死的栈显示全绿。

### 0.2 ④ 的实情:关栈**没有停任何东西**

`App.xaml.cs` 托盘「关闭」实际走的是:

```
StackStop.QueryAsync()  →  弹确认框  →  请客户端优雅退出  →  管理端自己 Shutdown()
```

`StackStop` 全文件只有 `QueryAsync`(恒返回 `Known=false`)与 `ConfirmText` ——
**没有任何停止动作**。全仓 `.Kill(` / `taskkill` / `Stop-Process` 在客户端与管理端里
**零命中**(唯一一处是 `ClientLink.cs` 注释里写着"不许出现")。

⇒ 框弹了、人点了确定、客户端退了,而**网关与 lan-edge 原地继续跑**。
「关掉整套 AI 栈」这句话在实机上是假的。

**这是同一个形状的第五次**,而且比起栈那条更难发现:起栈至少还有第二套实现在跑,
关栈是**判据、文案、入口、自检全都有,而动手那一步压根不存在**。

## 1. 裁定

### D115① 管理端启动即起栈,入口只有一个

`App.OnStartup` 无条件调 `StackBoot.EnsureAsync()`。

- **两条启动路径结构性都盖到**:`OnStartup` 对「双击」与「`--tray`(客户端拉起)」
  是同一个方法,不靠任何 `if` 去分辨;
- **排在 `if (!_startHidden) ShowPanel()` 之前** —— 排在后面就只剩双击那一条路;
- **不 await**:起栈里有两个 20 秒探活窗口,await 会让双击后窗口最坏 40 秒才出现,
  而「窗口不出来」与「没起来」在用户眼里一模一样;
- **不提权**:本进程不提权(`Program.cs` D46 护栏),子进程继承 ⇒ 网关与 Edge 天然普通身份。
  这条**不需要新代码**,需要的是**不写**任何 `Verb = "runas"`。

**只起 gateway 与 lan-edge,不起 llama-server。** D87① 裁的「不做开机预热」说的是**模型**;
网关不是被预热的东西,它是**决定要不要预热的那个东西**(D83:Broker 住在网关里)。

### D115② 两套起栈实现合并成一条

删掉 `HostHubView.StartEdgeAsync`。界面那条路改调 `StackBoot`(单飞)。

- 单飞是**承重**的,不是优化:管理端启动调一次 + 用户打开那一页调一次 ⇒
  两边同时探到「没起」就各起一个;
- `StartEdgeAsync` 身上那几条硬救回来的约束**一条都没丢**,只是换了地方
  (无窗口 + 收 stdout/stderr + 重定向 stdin 不进 REPL + 探到才算起来 + 失败摆日志原文),
  自检跟着改钉 `HostProvision.EnsureEdgeAsync` 与界面那一格;
- **如实交代的行为变化**:`启动Edge.cmd` 那条退路**没有保留**。
  它把绑定地址写死成一台开发机的 `192.168.178.61`,换台机器就绑到一个不存在的地址上,
  **而且会显示成功**。现在拿不到网卡地址就如实停下来说选不出地址。

### D115③ 就绪判据探**网关 8080**,不是 8443

新增 `HostProvision.ProbeStackAsync()`,复用 `StackResult`(不另造模型)。

- 探 `http://127.0.0.1:8080/health` —— **模型清单读的就是这个口**;
- 8443 在 `run` 模式下本来就开着 ⇒ 探它等于「失败与成功长得一样」;
- 「AI 栈」那一格在 **`Host` 与 `HostHubDown` 两档里都画**。
  只在 HubDown 档显示,等于让最坏的中间态恰好落在看不见的地方。

**半起(`HalfUp`)单独成一档**,并说清缺的那一半会怎样:

- 缺网关 ⇒ 副机连得上,但**没有任何模型用得了**,「模型」页是空的;
- 缺 Edge ⇒ 模型用得了,但**副机连不上这台**。

失败一律说**哪一步 + 下一步能做什么**,并且**不许**退回一句「请自己跑 start-stack.ps1」。

### D115④ 关栈真的停,而且停完要验

新增 `StackStop.StopAsync()`。

**边界靠结构守,不靠 if**:网关用 `Kill(entireProcessTree: true)` ——
进程树只包含**它自己生出来的**后端,而 `adopt_running()` 认领的是别人起的,
**结构上不是网关的子孙**,这个调用够不着它们。

**顺序**:Edge(断对外入口)→ 网关(停了就不会再按需装载)→ 收尾漏网的后端。
反过来的话,刚杀完后端网关又给你装一个回来。

**`StackOwnership` 记账**:起栈**第一行**先拍一张 llama-server 快照 ——
那时在跑的就是 `adopt_running()` 会认领的那一批,关栈时一个都不动。
这一笔账只有在起栈那一刻记得下来:等到关栈再问,谁是谁已经分不出来了。

- 账里存的不只是 PID,连 `StartTime` 一起存(**PID 复用**是真的会发生的);
- **没拍过快照就一个都不动**(管理端重启过 / 栈是手工起的),并**如实说为什么**。
  猜「应该是这几个吧」然后杀掉,代价是杀掉用户正在用的进程。

**停完要验**(边界③):端口真的不通了、没有孤儿后端、显存回落(佐证,不是判据)。
「调了 terminate 就算」不算 —— 本项目已经栽过一次(`loader.shutdown()` 零调用点)。
**没停干净就不关管理端** —— 管理端一走,用户就失去了唯一能再试一次的入口。

### D115⑤ 护栏:凡被注释称为「唯一入口」的函数,必须有生产调用点

元断言在 `admin/SelftestMoved.cs`。

- **自检里的引用不算调用点** —— 这是整条判据的支点:
  一条只被自检引用的函数,在自检眼里和一条真在跑的函数长得一模一样;
- 只认**紧挨着方法声明**的 `///` 文档块(枚举成员/属性没有括号,它们是状态不是入口);
- 数**限定形式**(`Type.Method(`)的调用点,先剥注释再数 ——
  「注释里到处都是它、代码里一次都没有」正是要抓的病;
- 配**零命中判红**:扫到的声明数 < 2 判红,枚举到的生产 `.cs` < 20 判红。
  判据自己坏掉时的表现是**它会一直绿**。

**红测记录**(见 §3)。

## 2. 出包路径:`AdminAppPresent` 结构上恒为 false

`build-client.ps1` 把管理端发到 `<dist>\admin-pack`,
而客户端逐字探 `<自己所在目录>\..\admin\localai-admin.exe`(`AdminApp.AdminDirName = "admin"`)。

⇒ `HostSetup.RoleEvidence.AdminAppPresent` **结构上恒为 false**
⇒ 裁定第 1 条(主机客户端启动 ⇒ 拉起管理端 ⇒ 自动起栈)**在出包产物上根本走不到**,
而在开发树里它是好的 —— 典型的「只在发布形态下断掉」。

实测:`dist\admin` **不存在**,exe 躺在 `dist\admin-pack`,而且那儿**只有 exe 与 pdb**。

**改法**:默认值改为 `<Out 同级>\admin`,目录名与 `AdminApp.AdminDirName` **对拍**(算出来的,不是挑出来的)。
新增门禁 `[3b]`,问的是**客户端会去看的那个路径**:

- 先比**目录**(这一次发到的 == 客户端会去看的),再看文件在不在。
  顺序不能反:只看「那个路径上有没有 exe」会被**上一次构建的残留**变绿,
  于是把 `$AdminOut` 改错了也照样过 —— 那种判据在红测里会骗人。

管理端包补 `VERSION.txt` + `SHA256.txt`,并写明版本戳与客户端**是同一个**。

## 4. 顺带查实:管理端自检里有 **69 条断言从没跑过**

`SelftestMoved.cs` 的 `var dv4 = TryReadSource("Views/DevicesView.cs")` ——
而 V21 已把该文件改名为 `HostHubView.cs`,**管理端里没有 `DevicesView.cs`**。

⇒ `dv4` 恒为 null ⇒ 其下 `if (dv4 is not null)` 整片 **69 条断言一条都不执行**,
而且**不留任何痕迹**:不计 PASS、不计 FAIL、连一行 SKIP 都没有。
自检末尾那个 PASS 数看着照常涨。

**与本轮修的 `EnsureStackAsync` 是同一个病**,但躺下的是**断言**,后果更坏 ——
它让别的缺陷也跟着看不见(V21 那次搬迁就是在这片沉默里做的)。

**本轮不改那个文件名**:改完实测 **PASS 166→210 / FAIL 8→33**。
多出来的 25 条红,绝大多数钉的是 V21 **有意留在客户端**的成员
(`SelfPairAsync` / `ClientPairCard` / `KnockAsync` …)—— 要**逐条裁**
「该跟去客户端自检、还是本来就该撤」,不是改个文件名了事。
在一条车道里草草改名,只会把 25 条红塞给下一个人,而且那时它们看起来像是本轮引入的。

**本轮做了两件够得着且不留假象的事**:
① 本轮新写的断言已搬到那个 `if` **外面**(否则它们也是死的);
② 补一条 `Skip`,把「沉默」换成「看得见的空」。

⇒ **未了项**:那 69 条的逐条处置。已在 §6 登记。

## 5. 另一条查实:`FAIL=8` 是**红得理由是假的**

基线(main)管理端自检 `FAIL=8`,全部来自同一条:

> ★★ 反向:已解除的「SENIORBIRDS」**不出现**在已配对列表里

它按**显示名**找。而实机上 `SENIORBIRDS` 与 `HONGKONGPINGPON`
**各有在册的一条 + 已吊销的若干条,名字一模一样**。
于是这条断言在要求「把**在册**那条也从界面上抹掉」——
而那正是上一条断言(「在册设备真的出现在界面上」)要求的**反面**。
两条互相打架,按名字那条必然红,且**永远**红。

**产品行为是对的**:`LoadDevicesAsync` 里 `Where(d => d.Status != "revoked")` 过滤正常,
上一条断言绿着就是证据。

改钉 **`DeviceId`**(唯一,且 `DeviceRow` 真的印着它)。

> ★ 中间试过钉**指纹短码**,但已吊销的设备恰恰**没有活动证书** ⇒ `CertShort` 为 null
> ⇒ 8 条全落进「分不开、跳过」那一支,反向判据**整段空转**。
> 那个空转被同时补上的**零命中断言**当场抓出(FAIL=1),没有蒙混过去。
> —— 这一条值得记:**修断言的时候最容易把断言修成恒真**。
