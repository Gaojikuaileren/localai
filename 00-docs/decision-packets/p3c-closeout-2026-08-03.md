## D77 · P3c 收尾:i18n 移 P7、四条补齐、两条修订、四条明确不由 P3c 关

### 背景

P3c 的判据清单停在 2026-07-29,此后新增的四个场景(同传 / 文件翻译 / 多语言表 / 回信)一条都没写进去;
而清单上原有的几条一直是 `- [ ]`。08-03 的一轮系统摸底把实况对完之后,结论是:
**代码体量与质量远超判据(3.2 万行 / 1566 条断言全绿),但判据里最靠外的那几条 —— 打包、发现、退役、三语 ——
一条没做**,而它们恰好是「能不能交到第二台机器上」的那一层。

再拖下去的代价是具体的:i18n 每天都在变贵(界面还在长,现在是 101 个键 vs 2275 条硬编码正文),
而「P3c 进行中」这个状态本身已经挡住了对 P4 / 方向 B 的排期讨论。

### 选项

- A 不动判据,把八条全做完再签 —— 三语一条就够干很多天,且做完还会被后续界面推翻
- B 全部延后,直接开 P4 —— 欠账永久沉底(判据里没做的那几条以后没人会回头看)
- C **逐条裁定:能关的关、该移的移、打架的修订、关不了的明说谁来关**(采纳)

### 决定

**选 C。** 逐条如下。

#### 1)i18n 中日英 —— **整条移到 P7**(用户裁定)

- 移走的是**铺满正文**这件事(2275 条硬编码);
- **骨架留在 P3c 已完成项**:运行时切换 · 缺键刺眼(不静默回落)· Audit · 现有 101 个键;
- P3c 验收第四句「界面可切中/日/英三语」**随之移到 P7**。

理由:界面在 P3c 期一口气长了四个场景,现在铺一遍、P7 客户端 v2 还要再铺一遍。
**日语【内容】进记忆要补检索词表**那条 backlog 不受影响,仍挂在 i18n 名下一起走。

#### 2)本轮补齐(已落地)

| 判据项 | 落点 |
|---|---|
| 记忆面板的**编辑** | `MemoryCenter.EditText` —— 只改标题与正文,**打人工修改标记**;范围是权限动作、来源是溯源锚,都不许在编辑框里悄悄改 |
| 记忆面板的**溯源展开** | `StorageView.TraceBlock` —— 四种情形**分开说**:有原文可点回 / 原文已删 / 没记来源 / 会话已不在 |
| **协议版本协商** | `HubClient`:自报 `X-LocalAI-Protocol`,对不上单列 `ProtocolMismatch` 并说清该更新哪一端(D45 原话);**先过协议闸再判在线** |
| **Open WebUI 退役** | `start-stack.ps1` 不再打印它的入口,改指客户端 |
| **可分发产物** | `90-ops/build-client.ps1`:exe + SHA256 + 版本戳 + 一页说明;**自检不过不出包**;工作树不干净写进版本戳 |
| **改连接地址** | `HubClient.SetDial` + 已配对卡片入口(见下条修订) |

★ **协议协商只做了客户端这一半**:网关回这个响应头的那半行归网关线。
客户端在中枢没报版本时**如实显示「未声明协议版本 · 未协商」**,既不假装协商过、也不据此拒连
(没有证据说它不兼容,拒连会把今天能用的装置直接停掉)。

#### 3)判据修订两条

- **验收③**「换路由器后自动重新发现且无需重新配对」与 **D43**(DNS-SD 自动发现推迟 P3b.2,先静态配置对端)
  **直接打架** —— 本阶段结构上不可能达成。
  **修订为**:换网段后**能改连接地址且证书/配对不失效**。
  它保护的东西没变:重新配对会删掉本机私钥、把一个完全有效的身份亲手销毁。
  自动发现随 P3b.2 补上时,填的也是同一个字段。
- **验收④**「界面可切中/日/英三语」随 i18n 移 P7(见 1)。

#### 4)明确**不由 P3c 关**的四条(不是遗漏,是归属)

| 欠账 | 归谁 | 为什么不能在 P3c 关 |
|---|---|---|
| 记忆面板接 **P3a S5 后端** | P4 之后 | `panel.py` 是**库不是服务**,客户端没有可调的端点;要先把记忆服务化 |
| **D45 成员轴端到端** | P4 / 主机侧 | 客户端 `MemberContext` 仍是设备本地哨兵 ⇒ **「仅本人」目前挡不住同机另一成员**。这是安全属性没兑现,须单独排期,不许因为"界面看着有"就算过 |
| **主机自识别按 D36 原文** | P7 | 现为「拨号地址指向本机」的启发式,只做状态显示、不做权限判定 |
| **真正的安装器**(卸载项/自动升级/签名) | P7 / P11 | 没有升级策略之前先造安装器 = 先造一个升级问题 |

#### 5)桌面宠物归 **P8**

PLAN 写明 P8 前置 = P6 权限区域实装 + A7-pet 显存实测。其逻辑层(时钟 / 意图 / 清单 / 状态机)
在 P3c 期提前落地是好事,但**不计入 P3c 完成度**,也不因此把 P8 的前置放宽。
另:它**撞方向 B** —— 桌宠是第一个默认持续显示记忆内容的组件,唇形/语音输出任何记忆内容前须先补该闸。

### 理由

1. 判据是用来签字的,不是用来当愿望清单的:与既有决议打架的那条(③)如果不修订,P3c 永远签不了字;
2. 移 i18n 是**成本时机**问题而非放弃:界面还在长,现在铺会白铺一遍;
3. 关不了的四条**写清归谁**,比留在 P3c 清单里当"未勾选"更有用 —— 尤其 D45 成员轴,它是安全属性,不该混在界面欠账里被一起忽略。

### 代价与已知风险

- P3c 签字后,**三语与成员轴这两笔账要靠 P7 的排期兜住** —— 若 P7 迟迟不开,它们会沉底;
  缓解:本包把它们写进 PLAN 的 P7/P4 段落而不是只写在这里。
- 「可分发产物」不是安装器:用户拿到的是一个目录,删除 = 直接删目录。若之后要做升级替换,
  现在这份产物没有版本比对以外的任何机制。
- 协议协商目前**只有一边在说话**:在网关补上响应头之前,`ProtocolMismatch` 这条路径在生产里永远不会触发
  (自检里由构造覆盖)。这是已知的半成品状态,已在界面如实标注。

### 推翻条件

1. 若 P7 排期被证明遥遥无期 ⇒ 三语与 D45 成员轴须重新提回近端阶段(它们是可用性与安全属性,不是锦上添花);
2. 若 DNS-SD 在 P3b.2 之前就落地 ⇒ 验收③ 的修订自动作废,回到原文;
3. 若记忆服务化被裁定不做(记忆永远只在主机进程内)⇒ 「记忆面板接 S5 后端」这条判据须整条重写,而不是继续挂着。
