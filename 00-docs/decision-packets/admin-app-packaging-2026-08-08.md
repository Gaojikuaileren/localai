## 1. 输出目录:由代码里那条路径决定,不是由「dist/admin 还是 dist/host 好看」决定

### 1.1 代码里逐字探的是什么

`20-client-win/app/Services/HubAdmin.cs`:

```csharp
public const string AdminDirName = "admin";
public const string AdminExeName = "localai-admin.exe";

public static string? AdminAppPathNextTo(string? clientExeDir)
{
    if (string.IsNullOrWhiteSpace(clientExeDir)) return null;
    var exe = Path.GetFullPath(Path.Combine(clientExeDir, "..", AdminDirName, AdminExeName));
    return File.Exists(exe) ? exe : null;
}
```

⇒ 判据是 **`<客户端 exe 所在目录>\..\admin\localai-admin.exe`**。
`HostSetup.DetectRoleAsync` 用它填 `RoleEvidence.AdminAppPresent`(V14 裁定②:
角色判据的指向物从「旁边有没有 `..\host\localai-lan-edge.exe`」换成「装没装管理端」)。

⇒ **管理端 exe 落在哪里,直接决定「这台是不是主机」判得对不对。**
客户端出到 `<Out>`(默认 `dist\client-pack`,真正安装位置是 `dist\client`),
`..` 就是它的父目录 ⇒ 管理端必须出到 **`<Out 的同级>\admin\`**。

**代码那条路径与我要放的地方一致 ⇒ 两边都没有改。** 脚本里 `-AdminOut` 的默认值写成
`Join-Path (Split-Path -Parent $Out) 'admin'` —— 换 `-Out` 时它跟着走,两者永远并排。

### 1.2 为什么**不**并进 `dist\host\`

工单里提过这个选项(V10 的包 §8:管理端是网关的天然载体)。**没有选它,理由有两条,后一条是硬的:**

1. **软的**:并进 `dist\host` 就得改 `AdminAppPathNextTo` 那条路径(以及 `ClientLink`
   那条镜像路径)。改代码去迁就目录,而不是让目录服从代码 —— 而那条路径今天已经被
   V14 的一整段断言钉住了(`AdminDirName` / `AdminExeName` 两个常量 + 三向探针测试)。
2. **硬的**:`dist\host\` **今天无人产出**(审计 C-3:「它此刻正在服务,却没有任何脚本能重建它」)。
   里面的 `localai-lan-edge.exe` / `localai-identity.exe` 正在真机上跑。
   往那儿 `dotnet publish -o` 会用一次输出**覆盖**掉一份没有脚本能重建的东西。
   ⇒ **本车道一个字都没有往 `dist\host\` 里写。** C-3 仍然待裁,不在本包范围内。

## 2. ★ 审计 N2:一条**恒不成立**的肯定证据,而所有断言都是绿的

### 2.1 N2 原文与它的机制

> `AdminAppPresent` 今天**结构上恒为 false**,`DecideRole` 第②条肯定证据**恒不成立**。

机制:V14 把指向物换成了「装没装管理端」,而**没有任何脚本产出那个 exe** ——
`build-client.ps1` 只 publish 客户端,`run-tests.ps1` 只 `dotnet build`(不 publish)。
⇒ 真机上 `..\admin\localai-admin.exe` 永远不存在 ⇒ 主机认不出自己。

**而门禁全绿。** 因为 V14 那一整段断言喂的是**构造出来的** `RoleEvidence`
(`new RoleEvidence(true, true, null, null)`),它钉的是**判据表**,不是**谁来填这张表**。
所有「该判不是主机的都判了不是主机」的断言都成立 —— 只是那张表在真机上永远填不出 `true`。

### 2.2 这正是 ASSERTION-PITFALLS 第 12 条那句话的形状

> 对每一个「只有 X 能做」的动作,反问一句:**今天有没有设备真的是 X?**
> 判据形状:`assert 存在某个真实可达的身份能通过这道闸`(**存在性**,不只是"该拒的都拒了")。

⇒ 只把 publish 接上、不加这条**存在性**断言,同一个坑下次换个指向物还会再来一遍。

### 2.3 存在性判据的落点与形状(两半,缺一半就退化成假防护)

**第一半 —— 客户端自检里那两条**(`20-client-win/app/Selftest.cs`,V18 段):

```csharp
var realAdmin = Services.HubAdmin.AdminAppPath();          // 生产入口,不是自检自己拼路径
Assert(realAdmin is not null, "存在性:真实出包形态下确实找得到 ..\admin\localai-admin.exe");

var realEv = Task.Run(() => HostSetup.DetectRoleAsync(null)).GetAwaiter().GetResult().Evidence;
Assert(realEv.AdminAppPresent, "存在性(生产入口):AdminAppPresent 在真实产物上真的为 true");
```

两条**不可互相替代**:上面那条证明「文件在」,下面那条证明「**角色判据读到了它**」。

★ 它由环境变量 `LOCALAI_SELFTEST_EXPECT_ADMIN=1` 打开,**不是无条件跑**。
理由是 ASSERTION-PITFALLS 第 11 条那个坑:无条件 `Assert(AdminAppPath() is not null)`
等于在断言「自检此刻跑在哪个目录下」—— 它在 `dist\client` 绿、在开发树红,两边都不说明代码对不对。

**第二半 —— 门禁要求哨兵回带 `ADMINEXIST=1`**(`90-ops/build-client.ps1`):

自检把它写成**三态**:`1` = 跑了且过了 · `0` = 跑了且没过 · `-1` = **没要求跑**。
门禁在「真实安装形态」那一趟 `-RequireAdminExist`,并要求回执必须是 `1`。

> ★★ 两半缺一半都会退化成"看着有防护、实际没有":
> 只有断言 ⇒ 有人删掉门禁那行 `-RequireAdminExist`,断言**静默不跑**,而门禁照样绿;
> 只有门禁 ⇒ 没有东西真的去问那个问题。
> **「跳过了」与「通过了」必须在门禁上长得不一样。**

## 3. 出包自检覆盖管理端:三条**行为**判据,不是源码文本判据

### 3.1 用户点名的最低限度,逐条对应到断言

| 工单原话 | 断言编号 | 它到底看的是什么 |
|---|---|---|
| 能启动 | `4a-1` / `4a-2` | 真的 `new App` + `InitializeComponent` + `Application.Run()`;托盘图标**对象真的建出来且 `Visible == true`**;`--tray` 时 `Panel is null`(不弹窗) |
| 能缩托盘 | `4b-1`…`4b-6` | 真的打开窗口(`IsVisible` 为真)→ 真的 `Close()` → 窗口**真的隐藏**、对象没被销毁、应用**还活着**、图标**还在**、而且**还能再打开** |
| 托盘右键能真关闭 | `4c-1`…`4c-7` | 从 `NotifyIcon.ContextMenuStrip` 里按**名字**取出那一项 → `PerformClick()` → `Application.Run()` **真的返回**、`Exit` 事件真的发生、托盘图标真的收掉 |

★ 一条源码文本判据都没有。只验「源码里有 `ShowInTaskbar=false`」那种写法仍然是**编得过**,
不是**跑得起来** —— 那正是 ASSERTION-PITFALLS 第 12 条(4197 条全绿而真机开不起来)的形状。

### 3.2 为了让「托盘右键关闭」可测,生产代码里开了一条**诚实的测试缝**

`RealCloseAsync` 中间隔着一个**模态框** —— 自检进程里没有人去点它,进程会当场挂死。
⇒ 把「问人」和「告诉人」抽成两个可替换的一环(`ConfirmClose` / `ReportCloseBlocked`),
**默认实现就是原来那两个 `MessageBox`,生产路径一个字都没有改变**。
自检替换的只是"谁来回答那一句",不是被测的那条路本身。
(同款理由已写在 `HostSetup.ResolvesToThisMachine` 上方:「开成 public 是诚实的测试缝」。)

托盘菜单项另加了 `Name`(`TrayRealClose` / `TrayOpenPanel`)——
让自检**按身份**找它,而不是按显示文案猜;按文案找的断言会在改文案那天红,
而它本来要守的是"这条路通不通"。

### 3.3 ★ 没能真验到的,如实写在这里

1. **「请客户端优雅退出」那一支没有测。**
   `InstanceLock.SignalQuit` 打开的是**按会话**的命名事件 `Local\LocalAI.Client.Quit`,
   它只认应用键、**不认状态目录** —— 自检在这儿发一下,会把用户**真正在跑的那个客户端**关掉。
   ⇒ 那一支在自检进程里**结构上做不到**,如实留白,不拿一条源码文本判据冒充它。
   它的另一半(「等不到就如实说没退、绝不强杀」)由客户端自检那侧新加的
   「管理端源码里不许出现停进程 API」守着(`.Kill(` / `TerminateProcess` / `taskkill`)。
2. **托盘图标的「右键」这个动作本身没有模拟。**
   自检是从 `ContextMenuStrip` 里取出菜单项直接 `PerformClick()`,
   没有真的去点 Windows 通知区域那个图标 —— 那要驱动 shell,自检进程里做不到。
   ⇒ 被钉住的是「菜单挂上了 + 那一项在 + 点它真的关得掉」,
   **没被钉住的是「在通知区域上右键真的会弹出这个菜单」**。
3. **管理端自检没有跑在「无桌面」环境里过。**
   它对那种环境的处置是:整段记 `SKIP` 并写 `LIFE=0`,门禁据此判红并把异常原样打出来。
   这条**分支本身没有被红测过**(本机没有无桌面环境可用)。
4. ★★ **`DecideRole` 判出 `IsHost=true` 那一格,没有在真实产物上端到端跑过。**
   实测到的是**它的上游**:`DetectRoleAsync` 在真实产物形态下采集到的
   `AdminAppPresent` 确实为 `true`(而在此之前它**结构上恒为 false** —— 那正是 N2)。
   但 `DecideRole` 的第②条肯定证据要求**两个**都成立:`AdminAppPresent && IdentityExists`。
   而 `IdentityExists` 要求本机**真的铸过中枢身份** —— 自检**不许**去铸
   (铸身份不可回退,而且会碰真实状态,违反自检第一条纪律)。
   ⇒ 于是那一格今天仍然只由 V14 那些**构造出来的** `RoleEvidence` 断言覆盖。
   **如实说清缺口的形状**:N2 点的那半(证据填不出 true)已经修好并测到了;
   「填出 true 之后判据会不会把它读成主机」这半,靠的仍然是纯函数断言,
   不是真机端到端。要补它,得有一台**铸过身份**的机器上跑一次 —— 那是实机场次的事,不是自检的事。

## 3.5 ★★★ 路上撞到的一堵墙:出包门禁本来**根本出不了包**(与本工单无关的既有缺陷)

第一次跑 `build-client.ps1`,第二种目录形状 **4 条红、exit 1、一个包都没出**。
V0 同时在 `main` 上撞到了**一模一样**的四条 —— 说明它与本车道的改动无关。

**根因(实测坐实)**

门禁第二形状把 exe 拷到 `[IO.Path]::GetTempPath()` 底下,
而**本机 `%TEMP%` 根目录里躺着一份 757 KB 的 `Selftest.cs` 拷贝**
(`C:\Users\<用户>\AppData\Local\Temp\Selftest.cs`,2026-08-08 05:44 由别的会话留下)。

自检认「源码根」的锚点当时只有**一个**:往上翻到第一个含 `Selftest.cs` 的目录。
往上翻第 3 层正是 `%TEMP%` ⇒ **它把 `%TEMP%` 当成了客户端源码根**,于是
`TryReadAllSources` 把整个 `%TEMP%` 递归扫了一遍,扫进了各个会话 scratchpad 里的历史 `.cs` 快照。

四条红分别是:两条全仓文案断言(红在**别人的临时文件**上)、
一条「找得到管理端源码目录」元断言、
以及**铁证**那一条:`源码根=在 · 命中 0 次 · 落空 259 次`。

> ★ 判据在回答「我旁边有没有一个叫这个名字的文件」,而它自称在回答
> 「我是不是待在客户端源码树里」。**这两件事不是一回事** —— ASSERTION-PITFALLS
> 第 4 条(判据比想判的东西宽)+ 第 5 条(会随环境漂移的断言)。

**修法:收紧判据,不是去删别人的临时文件,更不是放宽那几条断言**

锚点改成**三点共证**,并把三处各自为政的锚点合并成一个 `ClientSourceRoot()`:

| 锚点 | 位置 |
|---|---|
| `Selftest.cs` | 源码根目录内 |
| `localai-client.csproj` | **同一个**目录内 |
| `..\admin\localai-admin.csproj` | 它的**兄弟**目录内 |

★ 顺带满足 V0 提的第 2 条:**「根在而一次都没命中」从结构上不可能了** ——
三点全中的目录里必然有一大批 `TryReadSource` 要的文件。
那条元断言因此加了半句 `_srcHit > 0`,作为**锚点被绕过**的守卫
(而不是继续把它误报成"有路径写错了" —— 给一个错的理由比不给更坏)。

★★ **没有删掉那份 `%TEMP%\Selftest.cs`**。它还在原处,正好当免费的对照组:
修完之后同一台机器、同一份污染,门禁不再被骗。
