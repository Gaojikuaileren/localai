|---|---|

## ② 所有模型默认「按需」勾上 —— ★ **撞上 D90 裁定①,等用户裁**

**用户原话**:
> 我需要所有模型一开始都是默认按需被勾上的。

### ★ 先说清「按需」那一列是什么

`20-client-win/admin/Views/ComponentPicker.cs:26-34` 逐字:

> ★★★ P4-S16b:本面板多了**第二列勾选** ——「允许按需装载」(D90 裁定①)。
> 两列的意思完全不同,界面必须让人一眼分得出来:
> · 第一列「常驻」 = 你要它**一直装着**。系统**一个字节都不会自动改它**;
> · 第二列「按需」 = 你**授权**系统在需要时自动装、空闲时自动卸。
>
> ★ 第二列存在的理由就是 D90 裁定①的代价段:
> 「用户要先授权一次,才有按需可言 —— 没有它,系统就是在你没同意的情况下自己动显存。」
> ⇒ 这一步**不能省**,也**不能默认全勾上:默认全勾 = 把那次同意伪造出来。**

两个集合分别在 `:208`(`_checked` = 常驻)与 `:219`(`_permitted` = 按需)。

### ⇒ 冲突说清楚

用户要的**逐字就是第二列默认全勾**,而代码里有一条明确裁定说不能。

★ 但那条纪律**保护的是用户本人** —— 而现在**用户就是那个要授权的主体,他亲口给出了这次同意**。
所以这不是"违规",是**同意的方式变了**:从「每个模型点一次」变成「一次性全给」。
⇒ 要的不是拒绝,是**留痕**:否则下一个人读 D90 会以为代码违规,而读代码的人会以为 D90 已废。

### 具体影响(用户判这条要看的)

默认全勾之后,**你不动手,系统会自己动显存**:你敲字时自动装模型(D87①意图即起)、
空闲到点自动卸(D87②)。★ 而 D87③「压力即让」已经落地(**用户自己补出了任务暂停 + 恢复路径**),
所以开游戏时它会让路 —— **写那句注释的时候 ③ 还没有,今天有了,代价比当时小。**

### 三条路(协调层建议第 2 条)

| | 做法 | 代价 |
|---|---|---|
| 1 | 直接默认全勾,注释与 D90 一起改 | 最省事。但 D90 那句「默认全勾 = 伪造同意」被**无声删掉**,下一个人不知道为什么 |
| **2 ★ 建议** | 默认全勾,**并在 D90 下补一条裁定**:「2026-08-09 用户一次性授权全部组件按需」,`ComponentPicker.cs:34` 那段改成引这条新裁定 | 同意留痕。**D90 的推理仍然成立,只是那次同意已经给过了** |
| 3 | 首次打开时**明确问一次**「要不要全部允许按需?」,答了就全勾 | 最忠于 D90 原意,但用户已经在对话里答过了 —— **再问一次是把已给的同意当没给** |

**⇒ 等用户裁。** 裁完连同 ① 一起发车道。

**用户原话**:

本仓今天已经数到第七次「一个修法漏改一处,缺陷就完整地留在那一处」——
按视图各写一遍的方案,是这个形状的完美温床。
⇒ 一个 `ModelReadiness`(或等价物),**所有入口订阅同一个源**;并配一条元断言:
**凡会发起模型调用的入口,都必须挂在这个闸上**(判据形状交给车道,但它要能红)。

## ⑥ 任务栏里「载入中的模型」要和真任务分开,**而且不要进度条**

**用户原话**:
> 底部的任务进行栏还会显示载入中的模型,这个功能很好,但是要和**正在计算中或者正在跑的任务**要区分开,
> 而且**启用的模型不需要进度条**,现在有个正在载入中的进度条,不对,修。

**锚点**:`app/Views/TaskDrawerView.cs:108-111`
```csharp
var bar = new ProgressBar { Height = 4, Minimum = 0, Maximum = 1, ... };
if (t.Progress < 0) bar.IsIndeterminate = true; else bar.Value = t.Progress;
```
⇒ **模型装载被当成一个普通 Task 塞进了同一条渲染路径**,于是自动拿到了进度条;
而它的 `Progress < 0`(没有真进度)⇒ 变成一条**来回跑的假进度条**。

★ 判词:**一个不知道自己进度的进度条,是在假装它知道。**
⇒ 模型装载改成另一种呈现(状态点 / 文字态),与「正在计算」的任务**在形上就分得开**,
不是靠颜色区分。★ 用户明说这个功能本身「很好」—— **不要顺手把它删掉**。
