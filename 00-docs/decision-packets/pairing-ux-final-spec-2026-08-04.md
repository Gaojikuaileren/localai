## 1. 规格(用户原话整理,逐条)

### 1.1 主机

| 状态 | 行为 |
|---|---|
| 开启客户端,判定为主机,**且没连接自己** | **自动连接自己**(自配对),标记为主机。不问、不给按钮 |
| 开启客户端,是主机,**已连接** | **什么都不做** |
| 打开设置 | **什么都不做** |

主机的设置栏上**只允许存在**:

- **已配对电脑列表**(列表里**能看到自己**,但**不能移除自己** —— 自己就是主机)
- **角色检测**按钮
- **网络选择**按钮 —— ★ **仅当有多个网络时才出现**;只有一个有线网络时自动选它、不显示按钮

其他按钮**一律不存在**。

### 1.2 副机

| 状态 | 行为 |
|---|---|
| 开启,判定不是主机 | 标记为副机 |
| 未配对,打开设置 | 出现**「开始寻找主机」**按钮 + 网络选择按钮(多网时) |
| 按下「开始寻找主机」 | 发出**敲门广播** |
| 已配对,打开设置 | **只显示当前主机信息 + 解除匹配**按钮 |

### 1.3 配对流程(主机驱动)

```
副机按「开始寻找主机」 → 发敲门广播
        ↓
主机的配对列表里出现那台电脑,条目后面有【接受】【拒绝】
        ↓
主机按【接受】 → 开窗 → 匹配 → 关窗,一气呵成
        ↓
主机的已配对列表出现副机;副机的设置栏出现「当前主机 + 解除匹配」
```

**拒绝**:副机显示「被 xxx 主机拒绝」,**但可以再按一次按钮再次广播**。

★ 广播是**按需的**(按一次按钮发一次),不是每 5 秒一次的周期广播。

## 2. ★ 唯一需要补一笔的地方:主机按「接受」时,凭什么认得出那是你的电脑

主机列表里的敲门条目,内容全部是**对方自报的**:名字 + 来源 IP。
局域网上任何人都能敲门,名字随便写。两条都写「Zori 的笔记本」时,操作者**分不出哪条是自己的**。
按下【接受】= 给那台机器发证书。

**解法:不加任何点击。** 让敲门包带上 **CSR 公钥指纹**,于是六个词在**敲门那一刻**就能两边各自算出来:

- 主机的列表条目上**直接显示那六个词** —— ★ **位置:显示在设备名称的下面**(用户裁定);
- 副机屏幕上(「正在等待主机接受…」那一屏)在自己的设备名下面显示**同样的六个词**;
- 操作者瞄一眼两块屏幕,一致就按【接受】。

★ 用户原话:「当然防止重名的设备我们还需要校验词,直接用那六个词」「校验词显示在设备名称下面」。
  ⇒ 六个词在这里的职责被明确成**分辨重名设备**,而不是一道额外的关卡 ——
  它就长在名字底下,和名字一起被读,不打断流程。

⇒ **仍然是一次点击、一气呵成**,而「这条是我那台」有了凭据。
按钮文字本身承担断言(如「六个词一样 —— 接受」),不提供跳过。

★ 这不是把旧的六词比对塞回来:旧流程里词要等 enroll 之后才出现,所以必须**两次点击**
(先开窗、再批准)。把 CSR 指纹放进敲门包,词就前移到了敲门那一刻,一次点击就够。

## 3. 状态与判据(不许再出现"两份账")

- **角色**:`Host / HostHubDown / Client / Unknown` 四态照旧,判据仍是回环管理面的**肯定证据**;
- **配对窗口**:客户端**不再持有任何本地状态** —— 开窗/关窗都发生在【接受】那一次动作里,
  由中枢自己记账。本包**取消**「展开即开窗 + 三道闸」的整套设计;
- **敲门列表**:完全由中枢维护并自报,客户端只渲染。

## 4. 界面元素清单(这是"只允许存在"的清单,多一个都算 bug)

★★ **角色检测按钮只在【还没配好】时出现**(用户补充)。配好了就不该再问"我是谁" ——
那时角色已经由一次成功的连接证明过了,再摆一个检测按钮只是噪音。

**主机 · 已连接(常态)**
1. 已配对电脑列表(含自己;自己那条**没有**移除按钮)
2. 敲门列表(有人敲门时才出现,每条带六个词 + 接受 / 拒绝)
3. 网络选择(仅多网)
★ **没有角色检测**

**主机 · 未连接 / 中枢没起来(异常态)**
1. 正在做什么的实况(自动:身份 → 防火墙 → 起中枢)
2. 失败时:中枢自己打印的原文 + 打开完整日志 + 重试
3. 角色检测

**副机 · 未配对**
1. 开始寻找主机
2. 网络选择(仅多网)
3. 角色检测
4. (广播后)等待中 + 本机六个词;被拒绝时显示「被 xxx 主机拒绝」并可再按一次

**副机 · 已配对**
1. 当前主机信息
2. 解除匹配
★ **没有角色检测**

★ 现有界面里**要删掉**的:「＋ 添加一台新电脑」展开块、「一次装好这台主机」、
「启动中枢(Edge)」、主机卡上的「完成本机配对」按钮、手填地址框(降级为"找不到时才出现")。

## 5. 请 **core 车道**做的(本包的落地前提)

### 5.1 敲门协议(替换掉旧包里的周期敲门)

- **`UDP :8446` 广播监听**(端口待定)。副机按下按钮时向广播地址发一个包:
  `{ knockId, displayName, clientVersion, protocolVersion, csrSpkiSha256 }`
  ★ `csrSpkiSha256` 是本包的关键:有它,六个词才能在敲门那一刻算出来(§2)。
- 中枢收到后记一条 `Knock`,**TTL 60 秒**(按需广播,不再是 5 秒一次),并**当场算出六个词**。
- `GET /admin/pairing/knocks`(回环)—— 列出敲门者 + 每条的六个词。
- `POST /admin/pairing/accept { knockId }` —— 开窗(**只对这个来源 + 这个 CSR 指纹**)、
  等它 enroll、发证、关窗。**一次调用走完**。
- `POST /admin/pairing/reject { knockId }` —— 记一条拒绝结果,副机下次查询时拿到。
- 副机怎么知道结果:敲门后轮询业务口的一个匿名端点(如 `GET /pair/knock-status?knockId=…`),
  返回 `waiting | accepted | rejected`,以及被谁拒绝(主机名)。

### 5.2 安全边界(从旧包继承,**仍然有效**)

- 敲门内容**全部是自报的**:只作显示,永不进 prompt,永不作判据;
- **必须限流封顶**(匿名写入面):按来源限流 + 全局硬顶,满了丢新的并如实显示;
- **敲门永远不弹窗**,只进列表 —— 否则局域网上任何人都能让主机屏幕跳东西;
- `displayName` 服务端截断 64 字 + 剔控制字符;
- UDP 广播需要**额外的入站防火墙规则**;
- AP isolation / 访客网络下广播被静默丢弃 —— 文案要能区分「敲了没人应」与「我根本发不出去」。

### 5.3 仍然要做的(与本包无冲突,见 `pairing-audit-core-items-2026-08-04.md`)

回环 8442 的 admin token、匿名 enroll 限流、`displayName` 截断、provisioning 清理。
