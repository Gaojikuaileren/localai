## 1. ★★★★ 最硬的一条:`HostSetup` 整块搬会**静默**退回 08-07 那个实机缺陷

链条(逐个实测过):

```
DecideRole → DetectRoleAsync → DetectBootAsync
  → App.xaml.cs:416  Hub.NoteRole(decision.Role.IsHost, …)
  → HubClient.IsHostMachine(:272) → BusinessRoute(:332-333) → DecideBusinessTarget(:240)
```

这是**全客户端唯一**能回答「我该拨回环网关还是拨 LAN Edge」的判据。
搬走 ⇒ `IsHostMachine` 恒为 false(fail-closed)⇒ **主机上的客户端**走 LAN Edge、
拿 `lan-device` 档 ⇒ 组件面板点「确定」又吃「这台设备不能做这个操作」。

★★ **而且不会有任何断言变红**:V13 那 18 条拨号断言里的 `isHost` 是**自检自己喂的**
(`Selftest.cs:7993 v13Hub.NoteRole(true, …)`)。这正是 ASSERTION-PITFALLS **第 13 条**
(「我喂给它的输入,在真机上是谁喂的?」)的原样复发。

> ★ V10 §3 说 `DecideRole`「解的是一个不该存在的问题」—— 那句话写于 **08-07**,
> 而这个消费者是 **08-08(V13)** 才出生的。§3 对「用它分流**起栈**」成立,
> 对「用它定**拨号落点**」**不成立**。两个用途要分开裁,别一起搬走。

⇒ **拆法**:起栈/铸身份/防火墙/探管理面那一半搬;
   角色判据(`RoleVerdict` / `RoleEvidence` / `DecideRole` / `DetectRoleAsync` /
   `ResolvesToThisMachine` / `DecideBoot` / `DetectBootAsync`)+ `GatewayPort` / `GatewayUpAsync` /
   `LocalNics` / `IdentityExistsAsync` **留客户端**,管理端用 `<Compile Link>` 编同一份。

### 1.1 ★★★★ 迁移**本身**会亲手制造一条恒真断言

`Selftest.cs:8172-8176` 写的是:

iRole < (bootCode.IndexOf("MayStartStack") is var iSt && iSt >= 0 ? iSt : int.MaxValue)

## 3. ✅ 已裁(用户 2026-08-08)—— 数据权威:`memory.json` **搬干净**

> **迁到 `%LOCALAPPDATA%\LocalAI\admin\memory.json`,不留在 `client\` 下。**
> 理由(用户原话):**搬就搬干净,不留一个名字骗人的路径。**

★ 这条里**唯一会丢数据的动作就是迁移**,所以三条纪律:

1. **先复制、验完再删原件** —— 不许 move-then-pray。
   验的是**内容**(条目数 + 内容哈希),**不是**「文件存在」;

3. **迁移失败要看得见** —— 失败时管理端**不许静默用空库启动**(那会让用户以为记忆没了)。
   照 D50「坏档留证」的既有形状办。

★ 客户端那边:`MemoryPath` 连同读写点**全部删掉**,一个都不留。
  留一个「只读」也不行 —— 那还是两个进程碰同一个文件,而下一个人会顺手把它改成可写。
