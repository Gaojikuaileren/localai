## 1. 为什么 B1 与 B3 必须同一提交(实测,不是推断)

改动前的实况:

| 面 | `holder` / `device` 从哪儿来 |
|---|---|
| GPU 面 | `body["holder"]` —— 客户端填 `Environment.MachineName` |
| 同步面 | 证书指纹 → 成员表 → `device_id`(2026-08-05 审计 C1 已修) |

**两边各自自洽,所以谁也不炸。** 而 `/v1/session/end` 恰好横跨两者:
它拿一个**自报的** `device` 去逐条比 GPU 面的 `holder`。
⇒ 只改一边,这条路径当场失配,**退出不再释放任何租约**;
而客户端那半边(`HubClient` 那条老路径的继承者)对它的失败是吞掉的 —— **看不出来**。

★ 按目录切做不到"同一提交"(服务端在 `10-core/gateway`、客户端在 `20-client-win/app`),
这正是 D92 把车道改成垂直切片的那条理由在本车道上的具体形态。

## 2. B1–B6 的处置(实测前后见交回正文,这里只记**决定**)

| # | 决定 | 依据 |
|---|---|---|
| B1 | GPU 面三处 `holder` 全部改为**服务端解析**;body 里的 `holder` **无声忽略**,不报 400 | 报 400 会让版本略旧的客户端**一份租约都持不住**,而那正好把「全网有没有人在用」变回恒真式 —— 病比药重。诚实那一半由响应给出:`lease.holder` 回带的是服务端认定的名字 |
| B2 | `/v1/session/end` **只释放服务端认定的这台设备自己持有的**租约;自报值不参与匹配,但**如实回带** `ignored_device` | 静默丢弃会让旧客户端拿着一个 200 以为租约放掉了。★ 身份解析不出(`unknown`)时**一条都不放**并回 403:`unknown` 不是一个身份 |
| B3 | 唯一解析口 `principal_device()`;`_sync_device` **只剩一行转发** | 合一的做法不是"把同步面那套抄一份到 GPU 面"(那是**两份**会漂的实现),而是把它提上去。★ 同步面行为**一个字节都没变** |
| B4 | 额度桶按**动作类别**拆(`QUOTA_BUCKETS`),`Caps` 增 `leases_per_min` | 见 §2.1 |
| B5 | `lease_count` 与 `leases` 读**同一份**已过滤列表 | 见 §2.2 |
| B6 | 写 `permitted_on_demand` 是**另一个动作** `permit_on_demand`,只有 `trusted-local` 有 | 见 §2.3 |

### 2.1 B4:那条断言的形状(ASSERTION-PITFALLS 第 9 条,又一次)

原断言:

```python
_ren = assert_helpers.code_only(gateway.gpu_lease_renew)
check("★★★ 续租归 lease 档(不吃变更配额)",
      '"lease"' in _ren and "change_resident" not in _ren)
```

它问的是**「源码里有没有那个词」**,而它想守的是**「续租做不做得到不吃变更配额」**。
归档确实归对了,但 `lease` 与 `change_resident` **共用同一个令牌桶、同一个上限** ——
所以这条断言**当时是绿的、而它守的那句话是假的**。

⇒ 新判据是**行为**:把续租桶打满,再点一次确定,它必须还能过。
★ 归档那条**留着**但降级为辅助(它仍拦得住"手滑改了档位"),不再单独承担这句话的真伪。

### 2.2 B5:方向是 fail-open,所以它更危险

`lease_count = len(self._leases)` 不过滤过期,而 `leases` 那一行早就写着 `expires_at > now`。
`idle_is_meaningful = lease_count > 0` —— **这个字段就是「idle 可不可信」的开关**,
而它坏在「永远说可信」那一边。复现只要三步(发 ttl=0.05s 的租约 → 等 0.2 秒 → 取快照)。

### 2.3 B6:一道写在文档里、代码里不存在的闸

「`permitted_on_demand` 只有主机变更面能写」写在方案书 §8.1.7、写在 Broker 的四集合注释里、
写在端点注释里 —— **代码里一道闸都没有**。实测:副机带上这个数组 POST 一次,
中枢的授权集合当场被它写成了它想要的样子。

★ 而这份授权正是 D90 裁定①的**代价段**所说的那一步:
「没有它,系统就是在你没同意的情况下自己动显存。」
⇒ 副机能自己签这个字,等于那条代价段被绕过,而绕过它的人不是机主。

★ 它必须是**另一个动作**而不是 `change_resident` 的一个字段:
带不带这个数组的两次 POST 在 HTTP 上长得一模一样 —— §6.2「参数决定它是安全还是灾难」。

## 3. ★★ D90 未决项 ② 的处置:**新开 transient 平面 + 收窄 I2 的作用域**

> D90 原文:「自动装载走 `committed` 还是新开 transient 平面?直接决定 I2/I3 怎么求值。
> 新开 transient ⇒ I2 的 `actual == committed` 会因为多出来的按需组件而**永久违反**,
> 除非把 transient 从 I2 的作用域里排除 —— **那是对不变式的修改,要一起裁。**」

**本车道的处置:新开 transient 平面,并把 I2 的作用域显式收窄为**

```
state == READY  ⟹  actual − transient == committed
```

**理由(三条,缺一不可)**

1. 走 `committed` 是**不可选**的:D90 裁定①白纸黑字「仍然禁止:自动改动 `committed` ——
   一个字节都不许」,而 D90 裁定③还要求自动路径**结构上够不着**它。
2. 不收窄 I2 会造出一个**永久违反、消解不掉**的不变式 —— 而那种状态会反过来逼系统
   去自动改写锚点,正是 D10 存活那半条禁止的事(D90 自己在裁定①里点过这条推理)。
3. 收窄的是**作用域**,不是把检测器关小:减法**只减 transient 平面登记过的成员**。
   一个既不在 `committed` 也不在 `transient` 的野组件**减不掉**,I2 照样红 ——
   这一条有正反两面的断言钉着(`test_gpu_broker.py`「I2 作用域收窄」那一组)。

**代价,如实记账**

- 「驻留」从此有两层含义。⇒ 按 D90 裁定③,按需那半**一律 `transient_` 前缀**,
  快照里是**新键** `sets.transient_resident`,既有键的含义一个字都没改;
  界面上是**两列**(常驻 / 按需),并各有 tooltip 说清区别。
- `finish_startup` 的放行条件同步收窄,保持「放行条件就是 I2 的后件」这句话继续成立
  (开机时 transient 必为空,今天减的是个空集)。
- ★ **中枢重启后**:transient 平面与租约一样**不挺过重启**(D83①),
  于是 `adopt_running()` 会把按需起来的后端认领进 `committed`。
  这不是自动路径在改 `committed`(那条路径结构上够不着它),而是**重启后账本追现实**
  的既有语义;重启后 `committed`/`intended` 本来也都是空的,所以它没有放大任何"用户的勾选"。
  **写出来是因为它是本次改动带进来的一个新交互面**,不是因为它今天有害。

**若被推翻**:改回走 `committed` 就等于推翻 D90 裁定①;
改成"不收窄 I2"就等于接受一个永久违反的不变式。两者都要另立决议。

## 4. ★★ D90 未决项 ④ 的处置:**`AutoStartPreset` 作废并撤掉**

> D90 原文:「`AutoStartPreset`(连上中枢就自动装预设)与 D87 裁定①「不做开机预热」
> 正面矛盾,两者留哪个?★ 这两个开关今天是死的(审计 B1,已置灰),裁完才谈得上让它们生效。」

**处置:撤掉 `AutoStartPreset`。留 `AutoUnloadIdle`(仍置灰),理由不同。**

**为什么是撤掉,不是继续置灰**

- 它与 D87 裁定①**正面矛盾**,而 D90 放行按需装载的全部依据就是 D87。
  一边引用新裁定放行按需装载、一边把与它相反的开关留在原地,是拿新裁定当挡箭牌。
- 按 D90 裁定①,「连上就自动装」属于**自动改 `committed`** 那一类 ——
  它连一条合法车道都没有(合法的那条只到 `permitted_on_demand` 为止)。
- 置灰的含义是「这件事有人管、在等某一步」。**它等不到那一步了。**
- 取代它的是「启用的模型」里新增的那一列**「允许按需装载」** ——
  那才是 D87①「意图即起」在界面上的落点,而且它同时是 D90 裁定①要求的那次授权。

**为什么 `AutoUnloadIdle` 留着**

「空闲即卸」(D87②)**已经落地**,但它是**中枢**的策略:计时器是主机与副机
**共享的一个**(D87⑧)。把它做成每台客户端各自的开关,正是那条裁定点名要防的事。
⇒ 它要么成为主机上的一个中枢设置、要么撤掉;在那件事被裁之前保持**拨不动 + 文案说清真实行为**。
★ 今天的真实行为不再是"什么都没发生":按需授权过的成员**确实**会空闲自动卸。

**连带记账**:`Views/ModelCatalog.cs` 的 `Presets` 表**从此没有读取方**。
不删它的理由是具体的:D87 裁定⑤「可自定义,但必须有一个预设」仍然有效,
它的落点是「模型选择策略」那片占位框,而那件事还没做。已在该文件里写明,
免得它变成又一份「随包发布的死代码」(D92 点名的 A5 形状)。

## 5. S16-b 接动作:三条硬条件与**两个不同的钟**

**放行条件(缺一不可,全部落在 `Broker.sweep_idle_transient`)**

1. **这个组件**的按需空闲 ≥ 阈值(默认 600 s) ← D87②
2. `blocking_leases()` 为空 ← D90 裁定②「正在跑的不动」,**硬条件**,不是"提醒后仍卸"
3. 目标在 **transient 平面**里 ← D90 裁定①「禁令只管 committed」

**★★ 一处必须写下来的更正:`idle_seconds` 不能当放行条件。**

D90 包 §4.4 建议的条件①是「`idle ≥ N`」,而 `idle_seconds` 被**客户端心跳**刷新
(`LeaseKeeper` 每 TTL/3 ≈ 30 秒续一次租)。⇒ 只要有任何一台客户端活着,
它**永远到不了 10 分钟**:拿它当条件是把一个**恒真式**换成一个**恒假式**,两者都不是检测器。

⇒ 改看 `transient_idle_s`:**逐组件**的「多久没被意图点名过」,
中枢上的一份,任何一台机器的意图都刷新它 —— D87⑧「共享的一个」在这里的落点是
**共享在中枢上**,而不是"一个全局标量必须同时管所有组件"。
`idle_seconds` 保留为**纯观测量**(界面用它说"全网有没有人在"),并有断言钉住没有动作读它。

**收割搭在采样循环里,不另起 task** —— 模块头「不设收割线程 = 第二个写者」,
且有断言数源码里后台任务只许起一处。

**★★ 本次不实现 D87③「显存压力即让」。**
D90 明写它「若指让给别的程序,仍需单独裁」,而 D90 的未决项由用户保留、
不许在实现里被默认值悄悄裁掉。⇒ `admission_guard()` 照旧**只报告降幅,不触发任何卸载**,
并有一条断言钉住这一点。**这是有意留空,不是没做完。**
