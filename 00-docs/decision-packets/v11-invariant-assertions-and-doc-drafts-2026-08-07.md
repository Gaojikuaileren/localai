### 1.1 【方向一 · 结构性】客户端源码里不得出现任何停进程/停服务 API

**放**:`20-client-win/app/Selftest.cs`
**判词**:
> ★★★ 客户端全部源码里不得出现任何停进程/停服务的 API ——
> 「主机关掉客户端,副机还要能继续用」靠的就是**这个工程根本没有这个能力**

**判据**(要点):
```csharp
var all = TryReadAllSources();                    // 既有工具,Selftest.cs:8268
if (all.Count == 0) { /* 跳过:发布产物原位跑,没有源码 —— 不是缺陷 */ }
else {
  Assert(all.Count >= 20, $"★★ 元断言:源码枚举没写坏(只读到 {all.Count} 个 ⇒ 下面这条在空转)");
  // ★ 禁用符号表【拼出来】,免得这条断言自己的源码撞在自己的判据上
  string[] banned = { ".Kill" + "(", "GetProcessesByName", "CloseMainWindow", "task" + "kill",
                      "Stop-" + "Process", "GenerateConsoleCtrlEvent", "CreateJobObject",
                      "AssignProcessToJobObject", "TerminateProcess", "Environment.Exit" };
  // 逐文件扫 CodeOnly 之后的代码;Selftest.cs 自己不参与被扫
  // 命中即红,并打印 文件:行号 → 命中的符号
}
```

**为什么不是恒真式**:它扫的是 `CodeOnly` 之后的**代码**,而表里全是 **API 符号** ——
这类符号**只可能出现在代码里**。前两轮那个坑(`CodeOnly` 把字符串清空后再去 `Contains` 一句**界面文案**,
于是判据永远为真)**在这里结构上不可能重演**,因为要找的东西恰好是 `CodeOnly` **保留**的那部分。
今天命中数是 0,而这个 0 是**扫出来的**不是**扫不到** —— 两条元断言把这件事分开
(`all.Count == 0` 走跳过分支;`all.Count >= 20` 保证枚举没写坏)。

**红测**:在 `RegisterCleanupSteps()` 末尾临时加
`Lifecycle.Register("stop-stack", () => Process.GetProcessesByName("localai-lan-edge").First().Kill());`
⇒ **必须红**,且打印两条命中(`GetProcessesByName` 与 `.Kill(`)。删掉 ⇒ 必须绿。
第二个红测:把 `banned` 里的 `.Kill(` 换成一个绝不会出现的乱码 ⇒ 该项永不命中,用来验证扫描确实在跑。

> ★ 复核员独立验过三件事:`TryReadAllSources()` 以「哪个目录里有 `Selftest.cs`」为锚,
> 枚举 `20-client-win/app/**` 的 `*.cs`(去 bin/obj),实数 **116 个** ⇒ `>= 20` 那条元断言今天为真;
> 且今天确实 0 命中。
> ★★ **但它挡不住这一类**:「加一步 POST 一个新的 `/admin/stack/stop` 端点」——
> 那里一个停进程 API 都没有,**这条全表扫描完全看不见**。挡它的是 §1.2。
