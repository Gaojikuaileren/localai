## 3. 落地了什么

### 3.1 D36 主机自识别 —— 不依赖配对信息,fail-closed

`HostSetup.DecideRole(RoleEvidence)` 是**纯函数**(IO 在 `DetectRoleAsync` 里做完再喂进来),
所以"主机上判成主机 / 副机上判成不是主机"两个方向能各测一次 —— **只测一个方向等于没测**。

三条互相独立的证据,按 D36 原文:

| 证据 | D36 出处 |
|---|---|
| 配置的中枢地址解析到本机 | 「该地址解析到本机回环 → 这台就是主机」 |
| 铸过中枢身份 + 带主机工具目录 | 「主机 = 持有 CA 私钥与成员表的那一台」「它是一个**安装事实**」 |

**判定顺序是承重的**:

1. **地址明确指向别人 ⇒ 立刻判不是主机**,哪怕旁边摆着一整份主机工具目录。
   ★ 一台副机上如果有人整包拷来了 host 目录,**这条是唯一挡住它去起栈的东西**;
2. 地址解析到本机 ⇒ 是主机;
3. 地址无从解析时,才轮到「安装事实」——**而且要两条都有**:
   光有工具不算(可能是拷来的),必须**真的铸过身份**;
4. 其余一律**不是主机**,并说清是**哪一种**拿不准。

★ fail-closed 的方向是有意选的,理由写在代码里:
**副机误判成主机会去起一套不该起的栈**(两台抢 8443、两个 Broker 各写各的账本);
**主机误判成副机只是退回今天的手动状态**。两个方向代价不对称 ⇒ 默认落"不是"。

★ `ResolvesToThisMachine` 返回 **`bool?`**:`null`(拿不准)与 `false`(明确不是本机)
**必须分开** —— 合成一个的话,一次 DNS 抖动会让主机在下次启动时被判成副机。

### 3.2 开机分流(六条路,每条都有界面落点)

`HostSetup.DecideBoot(role, isPaired, hubReachable, identityExists)` —— 也是纯函数。

| 路 | 界面落点 |
|---|---|
| 主机 · 没身份 | 「还没有铸身份 —— 先铸一次,副机才配得上来」 |
| 主机 · 有身份 · 栈没起 | 「正在自动启动网关与 LAN Edge…」→ **起栈** |
| 主机 · 就绪 | 空(没有坏消息就不该占那一行) |
| 副机 · 没配对 | 「还没配过对」+ **为什么判成不是主机** |
| 副机 · 连不上 | 「多半是主机没开机」(V1 那五种归因已经在 HubClient 里,不重复实现) |
| 副机 · 就绪 | 空 |

★★★ **副机绝不起栈**是**结构性**的:起栈的唯一入口被 `BootDecision.MayStartStack` 挡着,
而它只在 `HostStartStack` 那一条为真。副机的四条路径**拿不到它**。
自检里逐条钉了这件事(4 条副机路径 + 3 条主机路径)。

### 3.3 EnsureStackAsync

- 起 **gateway**(`python -m uvicorn gateway:app --host 127.0.0.1 --port 8080`,
  **与 `start-stack.ps1` 逐字一致** —— 两处不一样的话,"手动起得来、自动起不来"会变成查不出根因的问题)
  与 **lan-edge**(`localai-lan-edge.exe run`);
- ★ **不提权**(边界②)。客户端自己是普通启动的,由它拉起两者天然同级;
- ★ Edge 用 `run`(只绑回环)**不用 `run-lan`** —— 对外监听要配合防火墙那一步,
  是**另一次有意的动作**,不能顺手在自动起栈里替用户开对外的门;
- ★★★ **边界③:不看退出码,去探**。网关探 `/health`,Edge 探 8443 能不能连上;
  探不到就如实说是哪一步、为什么(端口被占?venv 缺依赖?证书没铸?),
  **不退回那句「请自己去跑 start-stack.ps1」**;
- ★ **「起了一半」单独成一个状态**(`StackResult.HalfUp`)—— 它和"全没起来"的下一步不同;
- ★ 幂等:已经在跑的记 `Skipped`(算**成**,不算失败),可重试。

## 5. ★ 自动关栈(2026-08-07 追加要求)—— **本次只完成勘察,没有实现**

用户:「我要等自动起栈功能完成,还要验证自动关栈。」

### 5.1 复核:坑 3 **完全属实**

```
model_loader.py:272  async def shutdown()   「中枢退出时收掉自己起的那些。★ 认领的不动」
    → 全仓调用方:0 处
gateway.py           → 只有 @app.on_event("startup")(:770),**没有 shutdown 钩子**
```

⇒ **今天关网关,按需起的 `llama-server` 不会被收,显存继续被占。**

★ 一处协调层担心的边界**其实已经写对了**:`ModelLoader` 内部 `_procs`(自己起的)
与 `_adopted`(认领的)本来就是两个集合,`shutdown()` 只遍历 `_procs`。
⇒ 「认领的不动」**不需要新加防护**,只需要**别在接线时把两者合并**。

### 5.2 坑 1 / 坑 2 的判据我同意,并且它们指向同一个地方

关栈的四条硬条件(任何一条拿不准 ⇒ **不关**):
① `blocking_leases()` 为空 · ② 全网空闲 ≥ 阈值(中枢侧那份)· ③ 没有副机在线 · ④ 四条全满足。

★ 方向不对称,和起栈那边正好相反:**误关的代价是切断别人**(D83:租约不挺过重启),
**误不关只是多占一会儿显存**。⇒ fail-closed 落在「不关」。

### 5.3 ★ 为什么本次没有实现 —— 两条硬约束

1. **判据全在中枢侧,而那几个文件是本车道的禁区**:
   `blocking_leases()` / 共享空闲标量在 `gpu_broker.py`(**明写禁区**);
   收孤儿要调 `model_loader.shutdown()`,而 `model_loader.py` 是 **V7 语音车道的禁区**。
   ★ 可行的接法是**只动 `gateway.py`**:加一个 `@app.on_event("shutdown")` 调已有的
   `shutdown()`,再加一个只读的「现在可以关栈吗」判据 —— 两者都不用碰那两个禁区文件。
   但按本车道规矩,**动 `gateway.py` 要先在决议包里点名**,这一节就是点名。
2. **新增跨进程消息要成对 + 登记(D95),而欠债收工时必须仍是 1。**
   客户端要知道"现在可以关了",就多一条契约 ⇒ 要同时补两侧断言并登记进
   `check_contract_pairs.py`。这是一整轮的活,不该塞进本轮末尾**赶完但没验**。
