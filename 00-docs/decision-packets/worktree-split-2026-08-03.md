## 2. 决定:按 **git worktree** 分车道,一条车道一个目录一个分支

```
E:\.meine\.Proj_Soft\.Proj\.localAI          main(只接受合并,不在上面直接干活)
E:\.meine\.Proj_Soft\.Proj\.localAI-core     wt/core    分支 core/*
E:\.meine\.Proj_Soft\.Proj\.localAI-client   wt/client  分支 client/*
E:\.meine\.Proj_Soft\.Proj\.localAI-pet      wt/pet     分支 pet/*
E:\.meine\.Proj_Soft\.Proj\.localAI-ops      wt/ops     分支 ops/*
```

建法(一次性):

```
git worktree add ../.localAI-core   -b core/egress-gate
git worktree add ../.localAI-client -b client/p3c-tail
git worktree add ../.localAI-pet    -b pet/frames
git worktree add ../.localAI-ops    -b ops/acl
```

**worktree 直接消掉三件事**:① 每条车道有自己的 checkout ⇒ 别人的半成品**编不进你的构建**;
② 你的工作树里只有你自己的改动 ⇒ `git add -A` 重新变得安全;③ 冲突从"随时随地"
收敛到"合并那一刻",而且那一刻是**你选的**。

### 2.1 目录归属(谁改哪儿)

| 车道 | 拥有 | 只读 |
|---|---|---|
| **core** | `10-core/gateway/**` · `10-core/memory/**` · `10-core/identity/**` | 其余全部 |
| **client** | `20-client-win/**` **除** `app/Services/Pet/**` 与 `app/Assets/pet/**` | 其余全部 |
| **pet** | `20-client-win/app/Services/Pet/**` · `20-client-win/app/Assets/pet/**` | 其余全部 |
| **ops** | `90-ops/**` · `config/**` | 其余全部 |
| **(所有人)** | `00-docs/decision-packets/<自己的新文件>.md` | `00-docs/` 其余一律只读 |

**越界的唯一合法方式:在自己的决议包里写清"要动别人哪一行、为什么",由那条车道去改。**
(今天已有先例并且奏效:两层 MCP 决议包 §4.6 指名要 Hermes 那一路去改 DD-1,对方照办了。)

### 2.2 三个共享文件的协议

| 文件 | 谁能改 | 协议 |
|---|---|---|
| `20-client-win/app/Selftest.cs` | client · pet | **只追加,不重排**;各自把断言写进**自己那一段**并加分隔注释;合并时用 `git merge` 而不是复制粘贴 |
| `20-client-win/app/localai-client.csproj` | client | pet 要加文件**不必改它**(glob 自动收);要改编译项先在决议包里提 |
| `00-docs/{DECISIONS,PROJECT_PLAN_v3.0,STATE}.md` | **合并时由人串行并入** | 车道里**只写 decision-packets 新文件**;主干上逐处 Edit、禁止整文件覆盖;并入前重读文件尾 |

### 2.3 D 号协议(今天撞了两次,写死)

1. 草案期一律写 **`D?`**,不提前占号;
2. **并入 `DECISIONS.md` 的那一刻**才取号:`grep '^## .* · D' DECISIONS.md | tail -3` 看当前最大号 +1;
3. 取号后**立刻提交**,不要写完全文再提交 —— 号是靠"已进 git 历史"确定的;
4. 代码注释/报错文案引用 D 号的,改号时必须一起改(`grep -rn 'D6[0-9]\|D7[0-9]' 10-core/ 20-client-win/`)。

### 2.4 合并节奏

- 车道分支**只向 main 合并**,不互相合并;
- 合并前:`git fetch && git rebase main`,在**自己的工作树里**解冲突、跑自检,绿了再合;
- main 上不直接改代码,只做合并与文档串行并入;
- **每条车道收工即合**,不攒。今天的三次事故全部发生在"攒了半天没合"的窗口里。

## 4. 代价与已知风险

- **worktree 会多占磁盘**:每条车道一份完整 checkout(本仓 ~几百 MB,可接受);
  `bin/obj` 各自独立反而是好事 —— 今天正是因为共用 `bin` 才会编到别人的半成品。
- **合并冲突从"随时"变成"合并时"**,总量不会变少,但**变得可预期**,而且撞的时候你手上有完整上下文。
- **文档仍是唯一的真串行点**:三份中央文档没法分车道。缓解办法只有"车道里只写决议包 + 主干串行并入",
  这条今天已经验证有效(两层 MCP 决议包就是这么活下来的)。
- **纪律靠自觉**:worktree 拦得住构建污染,拦不住有人手贱去改别人的目录。
  这条只能靠上面的归属表 + 每次提交前 `git status` 自查。

## 5. 推翻条件

1. 若并行车道降到两条以内 ⇒ worktree 的收益不抵管理成本,退回单工作树 + `git commit -- <路径>`;
2. 若磁盘吃紧 ⇒ 改用 `git worktree add --detach` + 稀疏检出,只拉自己那几个目录;
3. 若某条车道频繁需要改别人的目录 ⇒ 说明归属划错了,重划而不是破例。
