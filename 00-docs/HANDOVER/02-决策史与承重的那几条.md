## 0. 先说这一节怎么用

这个项目所有**技术裁定**都记在一份文件里:`00-docs/DECISIONS.md`。它很长,你读不完,也不需要读完。
但其中十来条属于「**违反了不会报错**」那一类 —— 代码能编过、能跑、门禁能绿,后果落在别人的机器上或几个月后。
这一节要做的事就三件:告诉你这套编号系统的**真实形状**(它和你想的不一样)、
告诉你**哪几条是承重的**、告诉你**哪几句话今天已经是假的**。

### 三条阅读纪律(这一节自己也守)

1. **每一个数字都在过期。** 下面所有数都是 2026-09-02 在 `HEAD = 46d76ee`(分支 `main`,工作树干净)上量的。
   **每个数旁边都配了一条你能自己跑的命令** —— 数字与命令不一致时,以你跑出来的为准,不要相信这份文档。
   先确认你和我站在不站同一个地方:

   ```bash
   git rev-parse --short HEAD        # 我量的时候是 46d76ee
   git log --oneline | wc -l         # 755
   git ls-files | wc -l              # 610
   wc -l 00-docs/DECISIONS.md        # 7155
   ls 00-docs/decision-packets/*.md | wc -l   # 73
   ```

2. **本节不写「此刻什么在跑」。** 那种话第二天就是假的。要判断某件事在不在生效,下面给的是**命令**,不是结论。

3. **本节尽量不给行号,给的是函数名 / 变量名 / 抬头原文。** 这不是风格洁癖 ——
   这一节的上一稿有至少两处行号偏了(`D82` 的「D 号协议」那句、`D108` 的 N2 那句);
   而**指出它偏了的那个人自己也偏了三处**(钩子里那段拒绝文案、`D124` 的删除线范围、
   「第一条带回溯链的决议是哪条」)。⇒ 在这个仓库里,**行号是最不可靠的一种引用**。
   本节凡是给了行号的地方,都写着「量于 2026-09-02」;凡是能用符号名的地方,都用符号名。

## 1. 一条决议是怎么从「草案」变成「有号」的

### 1.1 号长什么样

编号写成 `D<数字>`,是 Markdown 二级标题。**两种形状都合法,写判据时两种都要认**:

```
## 2026-08-08 · D111 · D82 与 D92 各更正一处 …     ← 号后面还有标题
## 2026-08-08 · D114                                ← 号独占行尾,后面什么都没有
```

> ★ 这两种形状的**比例本身就是个会过期的数**。`check_decision_numbers.py` 的注释里写着
> 「号独占行尾,**9 条**;号后面还有标题,**104 条**」—— 那是**写那行注释当天**的数。
> 今天实测第一种是 **29** 条。**注释是留痕,不是现状**,这一点在本仓适用于每一句注释。
>
> ```bash
> python -c "import re,io;t=io.open('00-docs/DECISIONS.md',encoding='utf-8').read();print('号独占行尾',len(re.findall(r'^##[^\n]*?·\s*D\d+\s*$',t,re.M)),'| 全部带号抬头',len(re.findall(r'^##[^\n]*?·\s*D\d+\b',t,re.M)))"
> ```

### 1.2 三步流程,一步都不能跳

1. **干活的人先写「决议包」**,放在 `00-docs/decision-packets/<自己起的名字>-<日期>.md`。
   自由格式的长文:量到了什么、裁了什么、为什么、代价、红测怎么做的。
2. **草案期,包的抬头必须写 `D?`,不许提前占号。**
   这条规矩在 `DECISIONS.md` 里,标题逐字是 **「D 号协议(已撞两次,写死)」**,在 D82 那一条正文里
   (`grep -n "D 号协议" 00-docs/DECISIONS.md`,量于 2026-09-02 在 `:3606`)。
   原文:草案期一律写 `D?` 不提前占号 · **并入那一刻**才取号 · 取号后**立刻提交**
   (号靠"已进 git 历史"确定)· 改号时代码注释与报错文案里的引用必须一起改。
3. **合并进 `main` 的那一刻**,由在 `main` 上做合并的那个人(项目里叫「**第 0 条车道**」)
   把包里的结论**手工逐段 Edit** 进 `DECISIONS.md`,**当场取号,取完立刻提交**。

### 1.3 包和中央文档是两种东西

| | 决议包 `decision-packets/*.md` | 中央文档 `DECISIONS.md` |
|---|---|---|
| 它是什么 | **冻结的历史记录**,写完就不动 | **现行结论** |
| 里面的行号/数字 | 描述的是**写那天**的代码 ⇒ **一定过期** | 也会过期,但有人维护 |
| 审计怎么对待它 | **不计入** | 计入 |

> 「不计入」这条口径有出处,`grep -rn "冻结的历史记录" 00-docs/` 会在两份审计报告里各命中一次。
> ⇒ **不要拿决议包里的行号去找代码。**

## 2. ★★★ 「这个项目有多少条决议?」—— 这个问题没有单一答案

这是新人最容易搭错的一根线:他默认「D 号 = 决议条数 = 阅读顺序」。**三个都不成立。**

至少有**五种数法**,今天它们互不相等:

| 数法 | 今天 | 它为什么会骗你 |
|---|---|---|
| `DECISIONS.md` 里全部 `## ` 抬头 | **147** | 你以为它们都是决议 —— 其中 16 条根本没有 D 号 |
| 闸认得的「带号抬头」 | **131** | 差出来的那 16 条里,**有 2 条其实是有号的(`D14a`)**,只是闸读不出字母后缀 |
| **不同的** D 号 | **108** | 131 − 108 = 23 条抬头是**复用旧号的补记** |
| 最大 D 号 | **D137** | 不是条数。取下一个号时用的是这个数 +1 |
| 闸自己打印出来的那个数 | **108** | 它印的是「不同号」,不是「条数」—— 别拿它当条数 |

**一次量完(★ 每个数写下来那一刻就开始过期):**

```bash
python -c "import re,io;t=io.open('00-docs/DECISIONS.md',encoding='utf-8').read();n=[int(x) for x in re.findall(r'^##[^\n]*?·\s*D(\d+)\b',t,re.M)];print('全部抬头',len(re.findall(r'^## ',t,re.M)),'| 带号抬头',len(n),'| 不同号',len(set(n)),'| 最大 D',max(n))"
python 90-ops/gate/check_decision_numbers.py | head -2      # 闸自己印的那个数
```

用的正则就是闸自己的判据(`check_decision_numbers.py` 里的 `_HEADING`),不是我另写的。

### 2.1 ★ `D14a` —— 一个对判据隐形的号

`DECISIONS.md` 里有两条抬头带字母后缀(量于 2026-09-02 在 `:303`「D14a 命名:沿用当前机器名,RP ID 取 tailnet 级」
与 `:753`「D14a 完成 · tailnet 名定死为 `tail71cfd7.ts.net`」)。

**闸看不见它们**,因为 `_HEADING` 的 `\b` 在 `D14a` 的 `4` 和 `a` 之间不成立:

```bash
python -c "import re;H=re.compile(r'^##[^\n]*?·\s*D(\d+)\b',re.M);print('D14a ->',H.findall('## 2026-07-26 · D14a 命名'),'| D14 ->',H.findall('## 2026-07-26 · D14 设备身份'))"
# → D14a -> []   D14 -> ['14']
```

**这不是排版细节。** D14a 在方案书 §16 里的推翻条件栏逐字写着 **「不可推翻。改 tailnet 名 = 改 RP ID =
所有已注册设备的 credential 全部作废」** —— 一条自称不可推翻的裁定,对守 D 号的那道闸是隐形的。

同一个洞的另一半更坑:**你在决议包里写 `D14a`,闸会把它读成 `D14`**,而 `14` 冻在闸的已知欠债表里
⇒ **静默吞掉,一个字都不说**。验:

```bash
python -c "import re;print(re.compile(r'\bD(\d+)(?!\[)').findall('见 D14a'))"   # → ['14']
```

### 2.2 一个号可能有好几条抬头 —— 只读第一条 = 读了一半

「补 / 再补 / 三补 / 终版」是后写的,**和正条同等有效,而且经常推翻正条里的某一句**。

今天存在多条抬头的号:`D30 D38 D40 D41 D50 D52 D65` 各 2 条 · `D58` 4 条 · **`D59` 7 条** · `D60` 4 条 · `D61` 5 条。

> ★ 别按序数词数。`D60` 的抬头里出现过「补」「三补」「**八补**」—— 而它一共只有 **4** 条。
> **序数词是写的人当时的记法,不是计数。**

```bash
python -c "import re,io;from collections import Counter;t=io.open('00-docs/DECISIONS.md',encoding='utf-8').read();c=Counter(int(x) for x in re.findall(r'^##[^\n]*?·\s*D(\d+)\b',t,re.M));print(sorted((k,v) for k,v in c.items() if v>1))"
grep -nE "^##.*· D59\b" 00-docs/DECISIONS.md      # 看那 7 条各是什么
```

python -c "import re,io;t=io.open('00-docs/DECISIONS.md',encoding='utf-8').read();n=[int(x) for x in re.findall(r'^##[^\n]*?·\s*D(\d+)\b',t,re.M)];print('相邻逆序',sum(1 for i in range(1,len(n)) if n[i]<n[i-1]),'处')"

### 2.4 两个「以为每条都有」的字段,其实都不是每条都有

方案书 `§12.1 记录协议` 规定条目格式是「背景 / 选项 / 决定 / 理由 / 代价与已知风险 / **推翻条件**」,
并且逐字写着 **「『推翻条件』是本格式里最重要的字段。半年后你需要知道的不是当时决定了什么,
而是这个决定现在还成不成立。」**(`grep -n "推翻条件" 00-docs/PROJECT_PLAN_v3.0.md | head`)

**而实测只有约一半的条目真的有这个字段:**

| 字段 | 今天 | 怎么读 |
|---|---|---|
| 有「推翻条件」 | **71 / 131** | 没有的 60 条**不是漏写**,是早期还没形成这个格式。其中 22 条本身就是「补记 / 更正」型抬头,天然不带 |
| 有 `> 出处:` 回溯链 | **55 / 131** | 有一条很干净的分界线 —— 见下 |

```bash
python -c "import re,io;t=io.open('00-docs/DECISIONS.md',encoding='utf-8').read();q=[s for s in re.split(r'(?m)^(?=## )',t) if re.match(r'^##[^\n]*?·\s*D\d+\b',s)];print('带号条目',len(q),'| 有推翻条件',sum('推翻条件' in s for s in q),'| 有出处行',sum(bool(re.search(r'^>\s*出处',s,re.M)) for s in q))"
```

**回溯链那条分界线值得单记:第一条带 `> 出处:` 的决议是 `D77`(2026-08-03)。**
在它之前的 **72** 条,**一条都没有**;从它开始的 59 条里,只有 4 条没有。

⇒ **读 D77 之前的决议,想找它的决议包只能自己 `git log -S` 去挖。**
⇒ 另外:回溯链**会叫别的名字** —— 有几条写的是 `> 来源:` 或 `> 依据:`(而它们所在的条目同时也有 `> 出处:`,
所以两种数法今天都是 55)。**你写扫描器时要想到这一点**,这是本仓「零命中不是不存在」纪律的现场。

## 3. ★★★ 「有一批号在 `DECISIONS.md` 里 grep 不到」—— 两种完全不同的原因,别混

今天 `1..137` 里有 **29** 个号在 `DECISIONS.md` 里没有抬头。**它们不是同一回事**,
处置方式相反 —— 把两者混成一句「有 29 条欠债」是最坏的读法。

```bash
# 分类命令:每个缺号的去向,一次问清
python -c "
import re,io
doc=io.open('00-docs/DECISIONS.md',encoding='utf-8').read()
num={int(x) for x in re.findall(r'^##[^\n]*?·\s*D(\d+)\b',doc,re.M)}
plan=io.open('00-docs/PROJECT_PLAN_v3.0.md',encoding='utf-8').read()
s16=plan.split('## 16. 决议记录')[1].split('## 17.')[0]
in16={int(x) for x in re.findall(r'\bD(\d+)\b',s16)}
pk=io.open('00-docs/decision-packets/two-layer-mcp-decisions-2026-08-03.md',encoding='utf-8').read()
inpk={int(x) for x in re.findall(r'^##[^\n]*?·\s*D(\d+)\b',pk,re.M)}
miss=[i for i in range(1,max(num)+1) if i not in num]
print('缺抬头',len(miss))
print('  ① 在方案书 §16 里 :',[i for i in miss if i in in16])
print('  ② 在封存包里有抬头:',[i for i in miss if i in inpk])
print('  ③ 两边都找不到    :',[i for i in miss if i not in in16 and i not in inpk])
"
```

今天的答案:**① 19 个 · ② 10 个 · ③ 0 个。**

### ① 故意的 —— 早期决议在方案书 §16(19 个:D1–D16、D18–D20)

`DECISIONS.md` 第 4 行逐字写着:

> 范围: **v2.1 定稿后、执行期产生的决定。** v2.1 定稿时已有的决议(含 Q1–Q5)见方案书 §16,不在此重复。

**注意这一行没有出现「D1–D20」这几个字。** 真正的范围要去 `00-docs/PROJECT_PLAN_v3.0.md` 的
`## 16. 决议记录` 那两张表里看,而那里比你以为的多:

- 「随 v2.1 及之前」表:`D1–D7` + `Q1–Q5`;
- 「v2.2 新增」表:`D8 D9 D10 D11 D12 D13 D14 **D14a** D15 D16 D17 D18 D19 D20 D21 D22 D23 D24 D25 D26`。

⇒ ★ **`D17` 和 `D21–D26` 两处都写着** —— §16 里有,`DECISIONS.md` 里也有抬头。
读到两处口径打架时,**`DECISIONS.md` 是现行结论**。

⇒ 你在代码里看到 `D8` / `D10` / `D14` 而 grep 不到,**先去方案书 §16 找**,那不是错误。

### ② 取了号,而从来没落进中央文档(10 个:D66–D75)

`00-docs/decision-packets/two-layer-mcp-decisions-2026-08-03.md` 里有十条编号裁定 `D66–D75`
(两层 MCP:工具池、外部控制面、Vigil/宠物始终本地、出境、审计链、层间隔离……)。
那份包的抬头逐字写着:

> ## ⛔ 状态:**封存 · 等 P6**(用户裁定,2026-08-03)
> …… **⇒ 用户裁定:本包封存,不并入中央文档,等 P6 开工时再取用。**

**这十个号在 `DECISIONS.md` 里没有抬头,而且从来没有过。** 这句话是「考据式否定」,读当前文件证不出来,
必须用 git 自证 —— 而**上一稿给的自证命令是坏的**,先说这个:

```bash
# ✗ 坏的版本(尾随空格):它对每一个「号独占行尾」的抬头都返回 0
git log --oneline -S"· D114 " -- 00-docs/DECISIONS.md | wc -l    # → 0,而 D114 明明有抬头

# ✓ 能用的版本 —— 先拿一个【已知落了地】的号标定判据本身
git log --oneline -S"· D114" -- 00-docs/DECISIONS.md | wc -l     # 必须 ≥1,否则判据坏了
for n in 66 67 68 69 70 71 72 73 74 75; do \
  printf "D$n: "; git log --oneline -S"· D$n" -- 00-docs/DECISIONS.md | wc -l; done
# 我用这个版本重跑过:D66–D75 全部 0(755 个提交)
```

> ★★ 这一格值得单记:**判据给对了答案,不等于判据是对的。**
> 那条坏命令对 D66–D75 恰好给出了正确答案 —— 而下一个人拿它去核别的号,会得到一串
> 看起来很硬、实际是假阴性的零。**你的靶子先得是真的靶子。**

**它是「欠债」还是「设计」?—— 仓库自己给了两个不一致的答案,你要知道两个。**

- 守 D 号那道闸把这 10 个号冻在一张叫 `_KNOWN_MISSING` 的表里,那张表的抬头注释写着
  「**存量欠债表 —— 只许变短**」,并且明写「豁免写在包里,欠债写在这里,**两者语义不同,不许互相顶替**」;
- **而同一个文件下面几行的注释推翻了这一半**:「★★★ 而 D66–D75 那整段**不是"该落而没落"** ……
  **它们是【设计】,不是账。上一版这段注释把两者混成一句『该落而没落』,那句话是错的。**」

⇒ 今天的实况:**它们在一张名为「欠债」的表里,而那张表自己的注释说它们不是欠债。**
同一段注释还写清了为什么清不掉:「这 14 个在今天的判据下**结构上清不动**」——
① 真并进去(而用户明裁封存,不许并);② 改闸的语义,把「封存号」与「欠账号」分成两栏(那是一次要单独裁的判据改动)。

### ③ ★ 还有第三种「欠」,别和上面两种混:**该取号而没取**

上面两种说的是「号在包里、抬头没有」。还有一批是**连号都没取**:
一份决议包已经并进 `main` 了,抬头还挂着 `D?`。**这才是今天让闸变红的那一半。**

```bash
python 90-ops/gate/check_decision_numbers.py ; echo "退出码 $?"
```

**我跑的时候它是红的**(`5 PASS · 2 FAIL`,退出码 1)。两条红都出在这第三类:

```
★ 存量欠债(包里引用、中央文档里没有抬头):**14 / 14**      ← 这一半今天是绿的
★ 该取号而没取(已并入 main、抬头仍挂着草案标记):**10 / 8** ← 红
  X 已并入 main 的决议包,抬头里不许还挂着草案标记(存量除外)
       v41-egress-direction-b-2026-08-22.md
       v42-p5-second-batch-2026-08-22.md
  X 该取号而没取的存量只许变短    实测 10 份 > 期望 8 份
```

那 10 份 = 2026-08-03/04 起就冻在表里的 8 份 + `V41` `V42` 这两份新的。
两份包的**主标题那一行**里确实各挂着 `D?`(`head -3 00-docs/decision-packets/v41-egress-direction-b-2026-08-22.md`),
而 `git cat-file -e main:00-docs/decision-packets/v41-egress-direction-b-2026-08-22.md` 证明它们已经在 `main` 的树里。

> **⇒ 这对你意味着一件很具体的事:你新建自己的第一份决议包、第一次 `git commit` 时,

## 4. 这个项目的两个成文习惯 —— 不知道会当成垃圾清掉

### 4.1 更正时**原文划掉不删 · 带时态留痕**

判词在 `DECISIONS.md` 里出现过两次(`grep -n "带时态的留痕" 00-docs/DECISIONS.md`):

> **带时态的留痕不会骗人,不带时态的会。** 原文划掉不删。

**三种形状,你都会遇到:**

**形状一 · 删除线 + 带日期的更正块**(取自 D124 的出处栏,量于 2026-09-02 在 `:6568`):

```markdown
> ~~★ 「V33」没有对象:全仓 git log --all | grep -i V33 零行……故未取号。~~
>
> > ### ★★★ 2026-08-11 更正:上面那句是假的,而它是中央文档里的一句假话
> > 此处原写「V33 没有对象」——那是 grep【标签】而不是找【工作】得出的结论。
> > 那条工作存在、已并入 main、而且今天真的在生效……⇒ 见 D126。
> > ★★ 错在哪:**零命中不是不存在。**
```

**形状二 · 整条决议顶部的留痕块,下文一字不改**(D46 顶部):

```markdown
> ## ★★★ 2026-08-06 · 留痕更正:本条的根因叙述在本机不可能成立(裁定本身保留)
>
> **不改写下文一个字** —— 它是 07-29 当时的真实判断,历史记录不重写。
> 但引用本条之前必须先读这一段。
```

**形状三 · 开一条新 D,不就地改旧条。** 这是这个仓库处理「一条决议要变」的**默认手法**,理由写在方案书 §12.1:

> **★ 不得把新决定伪装成旧决定的延续** —— 那恰好绕过了这个字段(指「推翻条件」)。

D24 和 D25 都在正文里专门引用了这一条,原文:「**这是一条新决定,不是 D8 的延续** …… 故新开本条
并给出自己的推翻条件,而不是就地改写 §16 D8 那一格。」

⇒ **你要改一条既有决议时,不要去编辑那一条。**

**你照着做的三件事:** ① 划掉不删(`~~…~~`),不要 `git rm` 那一段;② 每一句更正带日期,
不要写「现在改成……」;③ 写清「**为什么会错**」,而不只是「现在是什么」。

#### ★ 陷阱 A:划掉的段落会骗过你的 grep

因为原文不删,`grep 未取号` 这类扫描**会命中已经了结的旧待办**。
D 号闸为此专门加了一个 `_STRIKE` 正则,扫之前先把删除线段剥掉;它的注释里给了实例
(一份 08-04 的签字包里那条「仍待取号并入」当天就了结了,不剥掉就会误报)。

⇒ **你写任何扫描 `00-docs/` 的判据时,第一件事是决定「划掉的段算不算」,并把这个决定写进注释。**

#### ★★ 陷阱 B:一条决议「看起来被维护过」,而被维护的是另一句

D124 里**有**一个删除线 + 留痕块(上面形状一那段)。所以它读起来像是被人照看着的。
**而同一条决议里那句今天已经不成立的话(「`build-client.ps1` 没有并发闸」)旁边一个记号都没有。**
详见 §6 第 ① 条。⇒ **「这一条有人维护过」推不出「这一条每一句都是新的」。**

#### 划痕在哪儿最密(用来判断该不该小心)

```bash
for f in 00-docs/DECISIONS.md 00-docs/STATE.md 00-docs/PROJECT_PLAN_v3.0.md; do \
  printf "$f: "; grep -o '~~' $f | wc -l; done
git grep -l '~~' -- 00-docs/decision-packets | wc -l
grep -c "留痕" 00-docs/DECISIONS.md
```

我量到:`DECISIONS.md` **4** 个 `~~` 记号(= **2** 段删除线)· `STATE.md` **36** · `PROJECT_PLAN_v3.0.md` **80** ·
决议包 **14** 份有划痕 · `DECISIONS.md` 里「留痕」出现 **21** 行。

> `DECISIONS.md` 里划掉的只有 2 段 —— 这份文件更常用的是**形状二**(顶部留痕块 + 下文一字不改)。

### 4.2 决议包 ↔ 中央文档,以及守它的那道闸

#### 闸在哪、怎么确认它活着

`.githooks/pre-commit` 一共**六段**闸(绝对路径 / 自检 / 行尾 churn / 中央三文档串行 / 控制字符 / **D 号落地**)。
第 ⑥ 段就是守 D 号的,它调用 `90-ops/gate/check_decision_numbers.py`;脚本非零退出即 `exit 1`。

**先做一件事,否则六道闸一道都不跑:**

```bash
git config core.hooksPath        # 有回显才算装上了
```

★ 我这台机器上它回显的是**绝对路径** `E:\.meine\.Proj_Soft\.Proj\.localAI\.githooks`(写在 `--local` 配置里),
不是 `.githooks`。两件事跟着来:**① 新克隆一份什么都没有,必须自己再设一次;
② 仓库换了目录,这个绝对路径会静默失效,而钩子不跑和钩子跑过了长得一模一样。**
`.git/hooks/` 里今天只剩 `*.sample`,所以没有备份的那一套。

#### 它守什么(两个半边,是分两次长出来的)

- **半边一 · 「取了号但没落地」**:扫决议包里出现的 `D<数字>`,和 `DECISIONS.md` 里**编号抬头**解出的集合比,
  包里有、抬头里没有 ⇒ 判红。
  > ★ 它**只认抬头,不 grep 全文**。脚本注释给的理由:正文里会引用别的号(「见 D82」),
  > 拿「整份文件出现过这个字符串」当判据,**一条被随口提过的号就能骗过它**。
- **半边二 · 「该取号而没取」**:一份包只要**已经在 `main` 的树里**,就不许再自陈草案。

#### ★★ 半边二的放行条件比你以为的窄 —— 这一格必须读准

判据是 `_self_declares_draft()`,它的第一行是 `if _QMARK in txt: return True` ——
**全文任何一处**出现 `D` + 问号都算,**不只是抬头**。放行只有三条:

1. **主标题**(`# ` 那一行,**不看 `## `**)里指得出一个**真** D 号(`_h1_names_real_number`);
2. 文件里有一行 **`DRAFT-D:`** 的看得见的豁免;
3. 文件还不在 `main` 的树里(还在你的车道里)。

⇒ **把 `D?` 从标题挪到正文里躲不开。** 脚本自己的注释记着这条判据被扩宽过三次,
每一次都是因为「零命中与全清白长得一模一样」。

#### 它**不**守什么

- **只扫 `00-docs/decision-packets/*.md`,非递归。** 生产代码、`STATE.md`、`COORDINATOR-HANDOFF.md`、`90-ops/`
  里写的「见 D69」,它**一个都看不见**(§3④ 给了自证命令)。
- 只在你**这次提交碰到了** `DECISIONS.md` 或 `decision-packets/` 时才跑。**改代码不触发。**
- 找不到 `python` 时它 `exit 1`,不放行 —— 原文:「**这【不算通过】:跑不了和跑过了必须长得不一样。**」

#### ★★★ 三个新人第一天就会撞上的坑

**坑一 · 决议包里写一个大写十六进制色值,这道闸会当场判红,并报一个不存在的 D 号。**

提取引用用的是 `_REF = re.compile(r"\bD(\d+)(?!\[)")`。实测:

```bash
python -c "import re;R=re.compile(r'\bD(\d+)(?!\[)');print(R.findall('color: #D93025;'), R.findall('#d93025'))"
# → ['93025'] []      ⇒ 闸会说「你引用了 D93025,而 DECISIONS.md 里没有它」
```

⇒ **决议包里的色值一律写小写**(`#d93025`)。这不是洁癖,是唯一的绕法 —— 闸不认识颜色。
(同一条正则的另一半就是 §2.1 那个 `D14a → D14` 的静默吞。)

**坑二 · 「把结论并进 `DECISIONS.md` 并取号」这条出路,在你的车道里做不到。**

`.githooks/pre-commit` 第 ④ 段(中央三文档串行闸)的判据是**当前分支名**:只要本次提交动了
`00-docs/DECISIONS.md` / `00-docs/PROJECT_PLAN_v3.0.md` / `00-docs/STATE.md` 三者之一,
而 `git symbolic-ref --quiet --short HEAD` **不是 `main`**(detached HEAD 也算,拿不到分支名就判红),
就直接 `exit 1`。

⇒ **取号只有在主工作树、在 `main` 上才走得通。** 在车道里你只有「写 `DRAFT-D:` 豁免」这一条,
或者去找第 0 条车道。

配套的另一条:**这道 D 号闸只读你自己工作树里的那份 `DECISIONS.md`。**
你引用了别人刚在 `main` 上取的号,在你的车道里它还不存在 ⇒ 判红。
**正确处置是先 `git rebase` 到最新 `main`,不是给自己写一行 `DRAFT-D` 豁免** ——
豁免是给「这号故意还没落」用的,拿它遮一个「我的树太旧」会把假绿留在包里。

**坑三 · ★★ 这道闸今天给你的拒绝理由是错的。**

`.githooks/pre-commit` 第 ⑥ 段里那段固定文案(量于 2026-09-02 在 `:432-444`)逐字写着:

```
提交被拒绝 — **决议包里写了 D 号,而 DECISIONS.md 里没有对应的编号标题**。
```

**而今天判红的不是那一半。** 实跑脚本,红的两条是**第二半**(见 §3③);第一半今天是绿的(14/14,没有新增)。
⇒ **你会照着那段文案去找「我引用了哪个不存在的号」,而根本没有这回事。**
真正要读的是脚本自己打印的那两行 `X`(它们出现在这段文案**上面**)。

这正撞上本仓自己那句判词:**「给错原因的提示比不给提示更坏。」**

#### ★ 顺带:钩子自己的自述也是留痕,别当现状

### 抬头怎么写

```markdown
## 2026-09-02 · D138 · 一句话说清裁了什么

> 车道:Vxx(`decision-packets/xxx.md`)。前置:D101 · D83。

### 裁定① …

```

**四个字段不要省**:前置 · 裁定(编号分条)· **推翻条件** · 出处 + 「并入时当前最大 D<n>」
(最后那半是给 D 号撞车留的自证)。
★ 实测只有约一半的既有条目做到了(§2.4)—— **那是历史,不是许可。**

### 三条最容易犯的错

1. **提前占号。** 草案期一律 `D?`。号以「已进 git 历史」为准。
2. **就地改写别人那条决议。** 开新条,在新条里写清推翻了旧条的哪一句(§4.1 形状三)。
3. **把两件推翻条件不相干的事合成一条 D。** D117 的出处栏专门讲了为什么不与 D116 合并:
   「合成一条之后,任何一侧被推翻都会把另一侧一起拖下水,而**一条决议应当能被单独推翻**。」

### 闸红了,先别找放行口

每道闸的放行口都是**窄的**,会在终端上留一行明说的环境变量
(`LOCALAI_ALLOW_EOL_CHANGE=1` / `LOCALAI_ALLOW_CENTRAL_DOCS=1`)。
**不要用 `--no-verify`** —— 它会把整个 pre-commit(今天是六段)一起关掉。

而 D111 的推翻条件里写着这个项目对误报的态度,直接照办:

> 若这道闸开始出现误报 ⇒ **先查是不是规矩又太宽了**,而不是先加放行口。
> **误报的根因通常在规矩,不在闸。**
