## 0. 先立三条读法,否则下面每一段都会误导你

**① 本文里每一个具体数字,写下它的那一刻就开始过期。**
所以每个数字后面都跟着一条你能自己跑的命令。**以命令的输出为准,不以本文为准。**
这不是客套 —— 这个项目自己的 `00-docs/COORDINATOR-HANDOFF.md` 开头就逐字写着同一句话:
不要引用文件里的任何数字,它们写下的那一刻就开始过期。

**② 本文不告诉你「现在什么在跑」。**
那种话第二天就是假的。要判断某个东西在不在跑,用命令问,不要读文档。

**③ 引用位置一律给 `文件 + 符号名`,不给行号。**
这个仓库的行号漂得很快。反例就在代码里躺着:`20-client-win/admin/Services/StackStop.cs`
的文件头注释指着 `10-core/gateway/gateway.py:849` 说那里有 `safe_to_stop_stack()` ——
**今天那个函数在 `gateway.py:1096`**(`git grep -n 'def safe_to_stop_stack' -- 10-core` 自己看)。
注释没错,它记的是**被换掉的那一版**。⇒ 本仓的注释经常是历史留痕,不是现状;
**引注释之前先去那个位置看一眼。**

还有两条这个项目自己的判据纪律,你会用得上:

- **零命中不是「不存在」。** 先问它会不会叫别的名字。
- **非零命中也不是「存在」。** 判据问的是字符串在不在,你要回答的是**代码/东西**在不在。

## 2. 你会撞上的第一堵墙:`.githooks/pre-commit` 有**六道**闸

### 2.1 ★★★ 先做一件事:钩子在新克隆里是**不装的**

```bash
git config core.hooksPath        # 空 = 钩子没装,你的提交什么都不会被检查
```

`core.hooksPath` 只存在本机的 `.git/config` 里,**clone 不会带走**。
而且本机这份存的是**绝对路径**(`E:\…\.githooks`)—— 意味着**把仓库文件夹搬个位置,钩子就静默失效**。
钩子文件自己第 8 行写了装法:

```bash
git config core.hooksPath .githooks     # 相对路径,搬家也不怕
```

同一处还设了 `core.autocrlf = false`(`git config core.autocrlf`)。这个仓库的行尾**逐文件混合**,
autocrlf 打开会让第 ③ 道闸(行尾护栏)对你狂叫。**别改它。**

### 2.2 六道闸各是什么

```bash
wc -c .githooks/pre-commit                       # 2026-09-02:26549 字节
grep -nE '^#  [①②③④⑤⑥]' .githooks/pre-commit    # 六段的抬头
```

它们**按顺序跑,前一道拒了就 `exit 1`,后面几道根本不会执行**。
⇒ 所以「被拒了」第一步是看**是哪一道**,别默认是路径那道。

| # | 闸 | 什么时候咬你 |
|---|---|---|
| ① | 绝对路径 | 暂存区里任何**非豁免**文件出现 `X:\` 或 `X:/`(**任意盘符**,连注释里的也算)。豁免只有 `config/paths.toml` · `00-docs/*` · `*.md` · `.githooks/*` · `.gitignore` · `90-ops/localai-model-replacement-eval/*`。它刻意放过 `http://`,但会抓 `file:///E:/` 里嵌的那个 `E:/` |
| ② | 自检门禁 | 本次提交碰了 `10-core/gateway/`、`10-core/gpu-broker/` 或 `10-core/memory/` ⇒ **当场跑 `90-ops/run-tests.ps1` 快层**。★ 这一条要跑几分钟;**用带默认超时的工具提交会把它掐死**,给足超时,并把提交信息先写文件再 `git commit -F <文件>` |
| ③ | 行尾 churn 护栏 | 改已有文件时顺手改了行尾。**大改动它会误报** —— 先自己数两边的 CR 数自证(`tr -cd '\r' < 文件 \| wc -c`),再 `git -c diff.algorithm=histogram commit`;**别顺手用它推荐的 `LOCALAI_ALLOW_EOL_CHANGE=1`** |
| ④ | 中央三文档串行闸 | 碰 `00-docs/DECISIONS.md`、`00-docs/PROJECT_PLAN_v3.0.md`、`00-docs/STATE.md`。判据是**分支名**:`git symbolic-ref --short HEAD` 不等于 `main` 就拒(detached HEAD 也拒)。★ **只有这三份**在范围内 —— `00-docs/ASSERTION-PITFALLS.md`、`00-docs/worklog/`、以及**你自己新建的决议包**都可以直接改。★ 它自己的注释明说它**只回答「在哪儿改」,回答不了「谁在改」** |
| ⑤ | 控制字符护栏 | 文件里有 `\a \b \f \v` 之类不可见字节。★ 它会对你**只是碰过**的文件报**既有**缺陷 —— 用 `git show HEAD:<文件>` 自证是不是你带进来的;是既有的就按字节修掉,别绕过。**这道闸没有放行口,是有意的** |
| ⑥ | D 号落地闸 | 碰 `00-docs/DECISIONS.md` 或 `00-docs/decision-packets/` ⇒ 跑 `python 90-ops/gate/check_decision_numbers.py`。★ 它**只看你这个工作树里的 `DECISIONS.md`**,引用别人刚取的号会被拒 ⇒ 先 rebase |

★★ `--no-verify` 会把**六道一起**关掉。钩子里第 ③④ 段各自给了**窄的**放行环境变量,
理由逐字写在注释里:没有窄口子,人就会去用 `--no-verify`。

## 5. 死的 · 第一类:出生即空(空壳目录)

### 5.1 ★★ 网上流传的那条 awk 判据会骗你 —— 先看清它到底回答什么

很多人(包括本文的上一稿)用这条命令找空目录:

```bash
git -c core.quotePath=false ls-files | awk -F/ '{d=$0; sub(/\/[^\/]*$/,"",d); print d"\t"$NF}' \
 | awk -F'\t' '{c[$1]++; if($2 ~ /^\.git/) k[$1]++} END{for(d in c) if(c[d]==k[d]) print d}' | sort
```

2026-09-02 它输出 **14 行**,其中**两行是假的**:

- `.gitignore` —— 那是根文件,没有 `/`,被 awk 当成了目录名;
- **`20-client-win` —— 而它有 297 个文件。** 因为 awk 只看**直接父目录**,
  而 `20-client-win/.gitkeep` 和 `20-client-win/.gitignore` 恰好直接躺在它下面,再没别的。

⇒ **这条判据只回答「某目录*直接*装着的文件是不是全是 `.git*`」,不回答「这棵子树是不是空的」。**

### 5.2 ★ 用这条,它回答的才是「子树空不空」

```bash
for f in $(git ls-files | grep '\.gitkeep$'); do
  d=$(dirname "$f")
  printf '%-40s %s\n' "$d" "$(git -c core.quotePath=false ls-files "$d" | grep -vc '\.gitkeep$')"
done | sort -k2 -n
```

2026-09-02 输出(左边目录,右边「除 `.gitkeep` 外还有几个跟踪文件」):

**真空壳(= 0)共 12 个:**
```
00-docs/snapshots            10-core/mcp-tools/http       40-integrations/cloud-image
10-core/job-service          10-core/mcp-tools/stdio      40-integrations/comfyui
10-core/orchestrator         10-core/trade-stub           40-integrations/model-curator
10-core/session-service      90-ops/storage-audit         40-integrations/prompt-translator
```

**不是空壳,只是也放了 `.gitkeep`(= 最活的几个目录):**
`10-core/gpu-broker` 2 · `00-docs/audit` 9 · `10-core/memory` 31 · `10-core/gateway` 38 · `20-client-win` 296。

### 5.3 ★★ 「`.gitkeep` 来自首日且没动过」**证明不了**目录是死的

上一稿用过这条判据,它是错的。实测:

```bash
for f in $(git ls-files | grep '\.gitkeep$'); do
  printf '%-46s %s\n' "$f" "$(git log --oneline -- $f | wc -l)"
done
```

今天全仓 **17 个 `.gitkeep`,每一个都只有 1 条历史,全部来自首个提交 `4f849b9`(2026-07-26)**。
而这 17 个里有 5 个躺在最活的目录下(`10-core/gateway/` · `10-core/memory/` ·
`10-core/gpu-broker/` · `00-docs/audit/` · `20-client-win/`)。
⇒ **这条性质对活目录同样成立,它不是判据。** 真正的判据只有 §5.2 那一条。

## 9. 48 条本地分支怎么读,以及**哪两条永远不许合**

`git branch` 会吐出一堆分支,新人第一反应是「这里有几十条未完成的工作」。**不是。**

```bash
git for-each-ref --format='%(refname:short)' refs/heads/ | wc -l          # 2026-09-02:48
git for-each-ref --format='%(refname:short)' refs/heads/ | sed 's#/.*##' | sort | uniq -c
```

**分成四族:**
- `claude/<主题>-<6位后缀>` —— 一次 AI 车道(lane)的工作分支。**后缀是会话 id,不是版本号**,别去比大小;
- `vN/<主题>` —— 早期的车道命名法(`git for-each-ref --format='%(refname:short)' refs/heads/ | grep -v '^claude/'` 自己列);
- `parked/selfpair` —— **存放点,不是功能分支**;
- `worktree-agent-<长十六进制>` —— 工作树代理留下的存档。

### 9.1 ★★★ 一条命令就能把它们分成「可以删」和「不能碰」

```bash
for b in $(git for-each-ref --format='%(refname:short)' refs/heads/); do
  a=$(git rev-list --count main..$b)
  [ "$a" -gt 0 ] && echo "$b  ahead=$a  behind=$(git rev-list --count $b..main)"
done
```

**2026-09-02:48 条里 `ahead>0` 的恰好只有两条。** 其余全部 `ahead=0` ——

## 10. `config/` 五个文件各控制什么 · 换机器必须改哪几个

```bash
git ls-files config
wc -l config/*.toml
```

pre-commit 第 ① 道闸禁止代码里出现绝对路径,**就是为了让「换盘只改这里」成立**。

| 文件 | 控制什么 | 换机器要不要改 |
|---|---|---|
| `paths.toml` | **五个逻辑根**:`code` / `models` / `assets` / `state` / `cache`,以及 `[cache]` `[assets]` `[state]` `[memory]` `[external]` `[backup]` `[gc]` 等派生路径。今天 `code` 指着仓库所在盘,其余四个根都在另一个盘 | **✅ 必改** |
| `vram-budget.toml` | 显存预算与**组件表**(每个组件的 peak / port / 启动参数),以及 `[calibration]` **硬件指纹** | **✅ 必改** —— 见 §10.2 |
| `caller-accounts.toml` | **allowlist**:哪些 Windows 账户配得上最高档 `trusted-local`。★ 文件开头逐字写着:**缺文件 / 缺字段 / 空表 ⇒ 拒绝启动**,它是 allowlist 不是 denylist | **✅ 必改**(账户名跟着机器走) |
| `retrieval-lexicon.toml` | 记忆检索选路用的**闭合词表**(中/德/英)。只决定走哪条轨,不用于回答问题 | ❌ 与机器无关 |
| `eval-thresholds.toml` | 记忆系统评测门槛(三条硬线) | ❌ 与机器无关 |

### 10.1 ★★★ 坑一:`config/paths.local.toml` 是个**幻影**

`.gitignore` 里忽略了它,你会自然以为这是「本机覆盖文件」。**它不是。**

```bash
git grep -ni 'paths\.local\|paths_local\|PATHS_LOCAL' -- .
```
2026-09-02:**命中数 1,就是 `.gitignore` 那一行本身。没有任何代码读它。**
⇒ **建一个 `config/paths.local.toml` 不会有任何效果,而且一声不吭。**
真正要改的是 `config/paths.toml` 本身(它在 pre-commit 第 ① 道闸的豁免名单里,允许含盘符)。

### 10.2 ★★ 坑二:`desktop_floor` 的决定因素是**显示配置**,不是显卡

`config/vram-budget.toml` 的 `[calibration]` 里有**两组**指纹,驱动**不同的重测项**:
- GPU 指纹(`gpu_name` / `gpu_total_vram` / `gpu_uuid` / `vbios`)不符 ⇒ 重测与硬件相关的组件 peak;
- **显示指纹不符 ⇒ 重测 `desktop_floor`**(桌面工作集由分辨率与显示器数量决定)。

⇒ **换显示器但没换卡,也必须重测。**
★ 而且这一段里有一条诚实的留痕值得读:显示指纹**至今未标定、且被明确判为「不可回填」**,
理由是当年那轮没有记录分辨率与显示器数量 —— 「把今天的值追认为当时的测量条件,是一次伪装成『补录』的捏造」。

### 10.3 ★★★ 坑三:改 `paths.toml` 时**沿用文件里现有的单引号**

上一稿说「读 `paths.toml` 的有四个地方」,**这个数错得离谱**。自己量:

```bash
git grep -l 'paths\.toml' -- 10-core 20-client-win 90-ops | grep -v '\.md$'
```
2026-09-02:**42 个跟踪文件**提到它,横跨 **Python / C# / PowerShell 三种语言**,
而且**几乎每一处都自己手写了一个极简解析器** —— 没有共用库。

**这就是那个坑:各家解析器认的引号不一样。**
- `90-ops/ai-op-account/ai-op-paths.ps1` 里 `Read-PathsToml` 的注释白纸黑字写着:
  「只认 `key = 'value'`(**单引号**)」;
- `90-ops/backup/backup.ps1` 的解析器里记着一次审计:「**三种取值都要认**(2026-07-31 审计):
  此前只认单引号,于是 `[backup]` 段一个都读不到 —— `require_encryption` 这个安全开关
  **设成 true 也不生效**(死代码)」;
- `90-ops/start-stack.ps1` 用的是一条 `Select-String` 正则,**同样只认单引号**;
- `10-core/identity/Paths.cs` 与 `10-core/gateway/{gateway,model_loader,backend_key,membership}.py`
  各有各的写法。

⇒ **改 `paths.toml` 时沿用现有的单引号写法。** 换成双引号会让一部分脚本读出 0 个键。
(好在它们大多 **fail-closed**:`ai-op-paths.ps1` 直接 `throw "paths.toml 解析出 0 个键 —— 拒绝继续"`,
Python 侧也是抛异常而不是猜一个路径。)

### 10.4 ★ 另外三处「跟着机器走」但**不在 `config/` 里**

- `10-core/speech/launch.toml` 的 `[venv].rel` 指向语音后端自己的 venv,`[verified]` 段是**本机实测读数**;
- `.git/config` 里的 `core.hooksPath`(绝对路径)与 `core.autocrlf=false` —— 见 §2.1;
- 门禁脚本用的是 **PATH 上的裸 `python`**(`grep -n 'Get-Command python' 90-ops/run-tests.ps1`),
  而记忆套件用的是另一个 venv。**拿错解释器会得到假 FAIL。**
