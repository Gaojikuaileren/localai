## 2. 第 0 步:先证明闸真的在跑

六道提交闸**全部**装在 `.githooks/pre-commit` 一个文件里(我今天量:455 行)。
git 只在 `core.hooksPath` 指对时才会跑它,而**指错了不会报错,只是什么都不跑**。

### 2.1 两条命令

```bash
git config --get core.hooksPath     # 必须指向本仓的 .githooks
git hook run pre-commit; echo $?    # 成功 = 完全静默 + 退出码 0
```

**成功长什么样**,这一条必须写下来,因为本节的主题正是「什么都不跑和跑过了长得一样」:

| 情形 | 表现 |
|---|---|
| 钩子找得到 | **一个字都不打印**,退出码 **0** |
| 钩子找不到 | `error: cannot find a hook named pre-commit`,退出码 **1** |

我今天两边都试过(第二种用 `git -c core.hooksPath=/nonexistent-dir hook run pre-commit` 造出来,
主仓一个字节没动)。

★ **一句警告**:如果索引里已经暂存了 `10-core/gateway|gpu-broker|memory/` 下的改动,
`git hook run pre-commit` 会**真的**把第 ② 段的快层门禁跑起来(数分钟),不是一次空转。
想只验「钩子在不在」,先确认 `git status --porcelain` 里没有这三个目录下的暂存改动。

★ 钩子写的日志路径是 `/tmp/localai-precommit.log`,那是 **Git Bash 的 `/tmp`**。
本机 `cygpath -w /tmp` 解出来是 `C:\Users\<你>\AppData\Local\Temp` —— 在资源管理器里
按字面找一个 `/tmp` 目录是找不到的。

### 2.2 ★★★ 装钩子:worktree 是**几份独立配置**,不是一份

这是最容易踩、而且踩了**不会报错**的一处。

本仓 `git config --get extensions.worktreeConfig` 返回 **`true`** ⇒ worktree 级配置优先级最高。
而每一条车道工作树的 `.git/worktrees/<名>/config.worktree` 里,**各写了一份自己的 `hooksPath`**。
我今天逐个 `cat` 过:三条车道**三份拷贝,三份都是同一个绝对路径**。
它们读出来的值一样,**不是因为共享,是因为三份拷贝碰巧写着同一个字符串**。

⇒ 在主树跑 `git config core.hooksPath .githooks` **只改 `.git/config`**,车道照旧指向绝对路径。
搬盘、改盘符、改目录名之后:**主树的闸活着,车道的六道闸一声不响全关掉。**

**我自己红测过这条优先级**(在临时目录里另建了一个一次性仓库,主仓一个字节没动):

| 做的事 | 主树解析出 | 车道解析出 |
|---|---|---|
| 初始:两处都写绝对路径 | `C:/ABS/PATH/.githooks` | `C:/ABS/PATH/.githooks` |
| 只在主树 `git config core.hooksPath .githooks` | `.githooks` ✔ | `C:/ABS/PATH/.githooks` ✘ **没跟着变** |
| 再在车道 `git config --unset --worktree core.hooksPath` | `.githooks` | `.githooks` ✔ |

**正确装法 —— 逐个工作树都要动:**

```bash
git config core.hooksPath .githooks                       # 主树
# 每一个 worktree 里二选一:
git config --worktree core.hooksPath .githooks            # 各自也写相对路径
git config --unset --worktree core.hooksPath              # 或者删掉,让它回落到主配置
# 装完逐个复读:
git worktree list
for d in $(git worktree list --porcelain | awk '/^worktree /{print $2}'); do
  printf '%-60s %s\n' "$d" "$(git -C "$d" config --get core.hooksPath)"
done
```

★ **钩子源码自己的安装说明写的是相对路径**(`git config core.hooksPath .githooks`),
而本机实际值是绝对路径。配置不进版本库,所以这不算「代码错」;但它意味着
**换盘/改名之后六道闸会静默全关**,而第 ① 段闸存在的全部理由恰恰就是「换 SSD 时只改一个文件」。

### 2.3 ★ 车道数量与状态是会变的,别背下来

`git worktree list` 我今天(2026-09-02)打印 **4 行**:主树 + 3 条车道,其中一条是 **detached HEAD**。

**为什么这一格要提**:第 ④ 段「中央三文档串行闸」拿**分支名**当判据,而 detached HEAD
**拿不到分支名** ⇒ 它按 fail-closed 判红(钩子里那两行:`git symbolic-ref --quiet --short HEAD`
取不到时把分支名写成 `(detached HEAD —— 拿不到分支名)`,随后与 `main` 比较必然不等)。
⇒ **在 detached 的车道上碰 `DECISIONS.md` / `PROJECT_PLAN_v3.0.md` / `STATE.md`,会被拒,
理由行里写的是「拿不到分支名」。** 钩子注释自己写着「新状态默认落在『拦住』那边」。

自证:`git worktree list`(自己看今天有几条、哪条是 detached)。

### 2.4 为什么这一步排在最前面

只验「装上了以后能过」是不够的。**一道从此什么都不拦的闸,和一道判据正确的闸,长得一模一样。**
上一位审计者在一次性仓库里做过双向红测,结论逐字:

| 做的事 | 结果 |
|---|---|
| `core.hooksPath` 指向不存在的目录,提交一个含 `"E:\some\where"` 的文件 | **exit 0,提交产生了** —— 绝对路径闸一声不响 |
| 同样内容,`core.hooksPath` 指向真钩子 | 打印「✗ 绝对路径: code2.py」,**拒绝,提交数没变** |

★ 第二行是必须验的那一行。这句话是这个仓库的方法论核心,你会在钩子源码的注释里反复看到。

## 3. 闸的清单:四层,什么时候跑 · 守什么 · 红了是什么意思

**每一层的触发条件都不一样。别把「我提交过了」读成「都验过了」。**

### 一、`.githooks/pre-commit` —— 六段,每次 `git commit` 走一遍(前提:钩子装对了)

| # | 段名 | 什么时候真的跑 | 守什么 | 红了是什么意思 |
|---|---|---|---|---|
| ① | 绝对路径 | **每次提交**,对每个新增/改动的文本文件 | 代码里不许出现 `X:\` / `X:/` 形式的盘符路径;路径一律从 `config/paths.toml` 读 | 你把一个换盘就会失效的路径写进了代码 |
| ② | 自检门禁 | **只在本次提交动了 `10-core/gateway/`、`gpu-broker/`、`memory/` 时** | 跑 `90-ops/run-tests.ps1` 的**快层**(不带 `-Full`) | 有断言红了,或有套件「没跑起来」。完整输出在 `/tmp/localai-precommit.log` |
| ③ | 行尾 churn | 每次提交,对**已存在且被修改**的文件 | 「你改到了没打算改的部分:行尾」 | 有 N 行**只有行尾变了** |
| ④ | 中央三文档串行闸 | 只在动了 `00-docs/DECISIONS.md`、`PROJECT_PLAN_v3.0.md`、`STATE.md` 时 | 这三份**只许在 `main` 分支上改** | 你在车道分支(或 detached)上改了中央三文档 |
| ⑤ | 控制字符 | 每次提交,所有文本文件 | 不许出现 `\t \n \r` 之外的 C0 控制字符 | 你的脚本把 `dist\admin` 写成了 `dist<BEL>dmin`(Python 里 `\a` 被当转义) |
| ⑥ | D 号落地闸 | 只在动了 `DECISIONS.md` 或 `decision-packets/` 时 | **两条**判据,见下面 §3.1 | 见 §3.1 —— ★ **它今天很可能是红的,而债不是你的** |

**① 的豁免名单是六条**(我今天逐条对着钩子源码数的,不是背的):


### 二、`90-ops/run-tests.ps1` —— 一键跑全仓自检,并**如实报出没跑的部分**

★★ **脚本用法块里写的是 `pwsh`,而本机没有 `pwsh`。**
`which pwsh` 空;只有 `C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe`(5.1)。
照抄会得到「命令不存在」,很容易读成「门禁坏了」。**用 `powershell`。**
(同一段里「约 20 秒」那句已经被作者自己更正为「实测约 3 分钟」,并写明了更正理由:
*「一个说自己 20 秒、实际跑 3 分钟的门禁,会被人当成卡住了而中途掐掉。」* —— `pwsh` 那处是同一个病没修完。)

```powershell
powershell -File 90-ops\run-tests.ps1              # 快层。作者标注「实测约 3 分钟」
powershell -File 90-ops\run-tests.ps1 -Full        # 连 dotnet + 客户端 + 管理端自检(数分钟)
powershell -File 90-ops\run-tests.ps1 -ListOnly    # 只列清单与分类,不跑任何东西

```

**退出码才是判定。** 0 = 全绿且无未分类文件;1 = 有 FAIL **或有「没跑起来」的套件**。

★★★ **`FAIL=0` 不等于门禁过了。** 2026-08-11 真的出现过 `FAIL=0` 而退出码 1
(判定是「FAIL=0,没跑起来 2 个」)。**看退出码,别看那行绿字。**

★★ **这一节最贵的一句话是门禁自己印出来的。** 我 2026-09-02 跑了一趟,输出里逐字有:

> `client --selftest` —— 理由:慢(数分钟)。加 `-Full` 一起跑。**★ 本次【没有跑过任何一条客户端断言】。**
>
> `admin --selftest` —— 理由:慢(数分钟)。加 `-Full` 一起跑。**★★ 本次【没有跑过任何一条管理端断言】——
> 而 `.githooks\pre-commit` 走的正是这一条路,也就是说【每一次提交】管理端都没被验过。**

⇒ **「我提交过了」在这个仓库里明确不包含客户端和管理端的任何一条断言。**
要验那两边,只能 `-Full`,或者直接跑对应的 exe(见 §4)。

**同一份输出里还有几样东西不判红,但第一次看到会以为门禁坏了**,先打个招呼:

- 一批 `manual` 档套件的「没跑」栏,每条都写了理由。

**它的承重性质是「诚实」,不是「覆盖率」**,具体落成**四张反向全表**(新加一个东西却不登记 ⇒ 当场判红):

★ 还有第五张,**盖住覆盖账本身**:`-Full` 才跑的每一个套件,非 `-Full` 时**必须**出现在「没跑」栏里。

这个仓库有**至少六个** `PASS=` 数字。它们在不同**形态**下量的,**不许相加,也不许相减**。

### 4.1 ★★★ 前置条件:后四行那些 exe **都不在 git 里**

一份**新克隆的仓库里,它们一个都不存在**。这不是环境坏了。我今天量的:

```bash
git ls-files dist | wc -l                        # ⇒ 0
git check-ignore -v dist/client/VERSION.txt      # ⇒ .gitignore:39:dist/
git check-ignore -v 20-client-win/app/bin/Release # ⇒ 20-client-win/.gitignore:2:**/bin/
```

**先造出来:**

- **仓库形态**(③④)⇒ 在 `20-client-win/app` 与 `20-client-win/admin` 各跑一次 `dotnet build -c Release`;
- **出包形态**(⑤⑥)⇒ `powershell -File 90-ops/build-client.ps1`,**一次约 15 分钟**(单文件 + 压缩)。
  ★★ **脚本没有并发闸** —— 开工前先确认没有别的会话正在出包;中途停会留 `VBCSCompiler` 锁住 `obj\Release`;
  **改完源码再开构建,别边跑边改**(版本戳会说谎)。

### 4.2 六个形态

| # | 形态 | 我 2026-09-02 量到 | 怎么自己量 |

于是去找一个不存在的回归。**⑥ 与 ①–⑤ 同样不可互比,同样写下来就开始过期。**

### 4.3 ★★ 怎么把 `SRCHIT` / `SRCMISS` 量出来 —— 两个 exe 的路子**不一样**

这一格上一版写错过,写文档的人和你都会栽在这儿:

| | 怎么拿到口径 |
|---|---|
| **客户端** | **控制台不一定打**。那一段被 `if (_srcMiss > 0)` 包着 ⇒ **仓库形态(`SRCMISS=0`)一个字都不印**。必须先设哨兵:PowerShell 里 `$env:LOCALAI_SELFTEST_SENTINEL="<某个路径>"`,跑完 `Get-Content <那个路径>`,得到一行 `PASS= FAIL= SRCHIT= SRCMISS= SKIP= OWED=` |
| **管理端** | 直接跑 `--selftest` 就行,它**无条件**在控制台打「口径:源码锚点命中 N 处 · 落空 M 处」 |

★ **不设 `LOCALAI_SELFTEST_SENTINEL` 时,客户端有意什么都不落盘。** 这不是 bug。

Git Bash 里的等价写法:

```bash
S="$TEMP/localai-sentinel.txt"    # $TEMP 在 Git Bash 里是个 Windows 路径,exe 认得
LOCALAI_SELFTEST_SENTINEL="$S" ./dist/client/localai-client.exe --selftest > /dev/null; cat "$S"
```

★ 控制台是 **cp936**。用 `python -c "...encoding='gbk'..."` 之类的办法读重定向下来的输出,
直接按 UTF-8 读会是一屏乱码 —— 别把乱码读成「自检坏了」。

### 4.4 为什么不能比:③ 与 ⑤ 差的那一千多条**不是「变少了」,是【测不了】**

发布产物旁边没有源码 ⇒ 自检里所有 `TryReadSource(...)` 落空 ⇒ 调用方一律写成
`if (src is not null) { Assert… }` ⇒ **整段跳过:不计 PASS、不计 FAIL、也不计 SKIP。**

这就是 `SRCHIT` / `SRCMISS` 两个字段存在的理由 —— 它们**明说**这一趟摸到了几处源码锚点。
我今天量到:仓库形态 `278 / 0`,出包形态 `0 / 256`。

★ **注意 278 ≠ 256**:锚点总数**本身**也随形态变(源码根没找到时,一批更深的读取压根不会发生)
⇒ **不能拿 `SRCMISS` 反推「少跑了多少条」。**

### 4.5 ★★★ 稳定的是 `PASS + SKIP`,不是 `PASS`

这是本节**最实用**的一条,而且是三轮**互相独立**的测量共同指向的:

| 谁 · 什么时候 | 出包形态(`dist/client`) | `PASS + SKIP` |
|---|---|---|
| 上一轮审计 · 2026-09-02(原位 + 仓库外) | `PASS=1059 SKIP=10` | **1069** |
| 复核者 · 2026-09-02(仓库外,首趟 / 其后 5 趟) | `PASS=1060 SKIP=9` / `PASS=1059 SKIP=10` | **1069** |
| 我 · 2026-09-02(原位 6 趟 + 仓库外 1 趟) | `PASS=1060 SKIP=9`(七趟逐字相同) | **1069** |

仓库形态同理:上一轮报 `PASS=2214 SKIP=1`,我今天 2 趟都是 `PASS=2215 SKIP=0` ——
**两边 `PASS+SKIP` 都是 2215。**

漂的那一条我们都抓到过原文,来自客户端 `SelftestModelGate` 里那条剪贴板断言:
`SKIP 剪贴板在这个进程里打不开(COMException: OpenClipboard 失败 0x800401D0 (CLIPBRD_E_CANT_OPEN))`。
剪贴板打得开 ⇒ 它 PASS;打不开 ⇒ 它 SKIP。**一条 PASS↔SKIP 互换,与 exe 待在哪儿无关。**

> **写进你的工作习惯:`PASS` 数是一次「这台机器此刻的观测」,不是产物的属性。**
> 看到别人报的数与你的不一致,**先问是不是同一形态、同一趟、`PASS+SKIP` 对不对得上**,再去找回归。

## 5. 已知的失效模式:一条断言可以既不 PASS、也不 FAIL、也不 SKIP

**它们的共同点是:输出看起来完全正常。** 下面每一条我都在今天的 main 上量过或读过源码核过。

### ① 出包形态旁边没有源码 ⇒ 一整批判据整段消失(最大的一个)

**这是设计如此**:读不到源码就跳过、不判红 —— 否则一条本意是护栏的断言会把出包挡住。
代价是这些条目**不进任何计数**。
**怎么看出来**:看哨兵里的 `SRCHIT` / `SRCMISS`(§4.3)。

### ② ★★★ 真正决定「摸不摸得到源码」的不是「在不在仓库里」

`TryReadSource` 今天**只**走 `ClientSourceRoot()`,而后者要求
**`Selftest.cs` 与 `localai-client.csproj` 同时出现在同一级目录**(从 exe 所在目录往上最多 8 层)。

⇒ 把 exe 放进仓库里**任何一个不是客户端源码根的目录**,`SRCHIT` **恒为 0**。

**我今天两个方向都钉过**(全在仓库外的临时目录里,仓库一个字节没动):

| 做的事 | 哨兵 |
|---|---|
| 只把 `localai-client.exe` 拷到临时目录 | `PASS=1060 FAIL=0 SRCHIT=0 SRCMISS=256 SKIP=9 OWED=0` |
| 再把 `Selftest.cs` + `localai-client.csproj` 两个锚点拷到 exe 旁边 | `PASS=1078 FAIL=15 SRCHIT=1 SRCMISS=255 SKIP=4 OWED=1` ← **红了,而且冒出一条 OWED** |

⇒ 源码根一「找到」,一批判据立刻活过来(并且因为那里只有一个真文件而按设计红了)。
**这条机制是可以证死的,不需要推断。**

自证(引函数名,不引行号):

```bash
# 注意:C# 的 `string?` 里那个 ? 在 sed 里要用 . 代掉,别照写问号
sed -n '/static string. ClientSourceRoot/,/^    }/p'  20-client-win/app/Selftest.cs
sed -n '/static string. TryReadSource/,/return null/p' 20-client-win/app/Selftest.cs
```

### ③ ★ 活的漏:一条 `SKIP` 打印了,但**不进计数**

我今天出包形态跑一趟,**输出里 `SKIP` 开头的行有 10 行,而哨兵写的是 `SKIP=9`。**

差的那一条:`20-client-win/app/Selftest.cs` 里唯一一处**裸** `Console.WriteLine("  SKIP …")`
(判词是「副机侧配对入口那 13 条(V39 归属搬迁)」),它**没有走 `Selftest.Skip(...)`**,
而计数器就在同一个文件里。

自证 —— **这条命令今天应当只有一处命中,而且不在 `Skip()` 函数体内**:

```bash
grep -rn 'Console.WriteLine("  SKIP' 20-client-win --include=*.cs
```

**它旁边的注释今天是假的**,逐字写着:

> ★★ 这里**没有**用 `Skip(...)`:这份自检今天还没有那个函数(它是 V36 正在加的东西)……
> ⇒ V36 并入后这一处该跟着换成 `Skip(...)`,好让它进 SKIP 计数。

**而 `Skip()` 就在同一个文件里。** git 自证(考据式否定必须用 `git log -S`,读 HEAD 证不出来):

```bash
git log -S 'internal static void Skip(string what, string why)' --oneline -- 20-client-win/app/Selftest.cs
git log -S '副机侧配对入口那 13 条'                              --oneline -- 20-client-win/app/Selftest.cs
git merge-base --is-ancestor <前者> <后者> && echo 是祖先 || echo 不是祖先
```

我今天跑出来:`Skip()` 来自 V36 那次提交(2026-08-15),这一行来自 V39 那次(**同一天**),
`--is-ancestor` 返回**否** —— **两条车道同日并行**。
⇒ **那句注释在它写下的那一刻是真的**(V39 那棵树里确实还没有 `Skip()`);
两条都并进 main 之后,**没有人做那个跟进动作**。

★★ **这是一条留痕注释的活标本。** 引注释时必须问一句:它描述的是哪一棵树?

★★★ 而且这笔债是**登记过**的 —— `00-docs/decision-packets/v39-assertion-ownership-2026-08-15.md` 里
有一行逐字写着「**V36 并入后,本轮那一处该跟着换成 `Skip(...)`**」;
`ASSERTION-PITFALLS.md` 第 26 条的处置也写着「所有裸 `Console.WriteLine("  SKIP …")` 全改成 `Skip(…)`」。
**两处都写了,而事情没做完。**

⇒ 更要紧的是:**全仓没有任何一条元断言钉住「不许再出现裸 SKIP 打印」。**
我按「零命中不是不存在」的规矩,换了几个名字搜过(`裸 SKIP` / `裸 Console` / `进 SKIP 计数` /
`不许再出现`),命中的**全是文档和注释,没有一条是可执行的判据**。
这正是 `ASSERTION-PITFALLS.md` 第 25 条说的**「只装了半个护栏」**:手工普查一遍、改完就完。

**这是一件新人可以立刻上手的活**:把那一处改成 `Skip(...)`,**并且**补一条元断言钉住它。

### ④ 车道 worktree 里,客户端/管理端自检**可能整段不跑** —— 而这是**逐条车道不同**的

`bin/` 不进 git ⇒ **一份新开的 worktree 里本来就不会有构建产物**。
`run-tests.ps1` 对这种情形**不判红**(判红会训练人用 `--no-verify`),而是记进覆盖账的「没跑」栏。
判据是 `.git` 是不是一个**文件**(worktree 的 `.git` 是指向主库的文件,不是目录)。

★★ **但它只在「exe 不存在」时才走这条分支。** 我今天逐条车道量过,**三条车道三种状态**:
一条有编好的 Release exe(那里的自检**会真跑**)、一条有 `bin/` 但没有那个 exe、一条连 `bin/` 都没有。

⇒ **别背状态,量一遍**:

```bash
git worktree list
for d in $(git worktree list --porcelain | awk '/^worktree /{print $2}'); do
  printf '%-60s %s\n' "$d" \
    "$([ -f "$d/20-client-win/app/bin/Release/net9.0-windows10.0.19041.0/win-x64/localai-client.exe" ] \
       && echo '有产物 ⇒ 自检会跑' || echo '没产物 ⇒ 记进「没跑」栏')"
done
```

★★★ **推论,请记牢:全仓扫描的门禁在车道工作树里容易恒绿。要算数,得回主工作树跑一次。**
★★ 也**别为了消这条「没跑」去出包**;但更别把它读成「客户端没问题」——那一趟一条客户端断言都没跑。

### ⑤ 产物比源码旧 ⇒ 跑它等于测上一版

真事:改了 `Selftest.cs`、加了 3 条断言,门禁照报 `client --selftest PASS=… FAIL=0` ——
**与改动前一模一样**,因为跑的是上一次出包的产物。

现在 `run-tests.ps1` **比时间戳**:产物比源码旧就当「没跑起来」报出来,**并且不跑**
(注释逐字:*「跑出来的绿数字比不跑更有害」*)。扫描根是一张登记表,不是写死的 `20-client-win\app`。

★ 同族陷阱:用 `Copy-Item 备份 → 源文件` 还原红测时,**时间戳会一起被拷回去**,
MSBuild 判 up-to-date、一行都不重编 —— 还原后先 `(Get-Item $f).LastWriteTime = Get-Date`。

### ⑥ 判据在**另一种输出布局**下整段不跑

一条判据写死了从 `AppContext.BaseDirectory` 往上的**层数**(`..\..\..\Views`),
只在 `bin\Debug\<tfm>\`(三层)解得对;而门禁跑的是 `bin\Release\<tfm>\win-x64\`(**四层**)
⇒ 解出一个不存在的目录 ⇒ 整块 `if (Directory.Exists(...))` 静默跳过,
**连 `SRCMISS` 都不进**(它不走 `TryReadSource`)。

**规矩**:自检里不许再出现第二处「从 `AppContext.BaseDirectory` 往上找」,
一律走共用的 `Selftest.ClientSourceRoot()` / `AdminSourceRoot()`(**锚点判据,不数层**)。
★ 这条护栏今天是活的 —— 你会在自检输出里看到它逐字报「只许有一处」。
(★ 它本身也有形态依赖:出包形态下它会 `SKIP`,理由逐字是「发布产物旁边没有源码,扫不了编译集」。)

### ⑦ 元断言的**下限**被一批不可能失败的条目撑着

`Assert(hits.Count >= 2, "零命中要判红")` 形状是对的,但 `hits` 里混着几条**结构上不可能失败**的条目
⇒ 把**真正承重的那一条**抽掉,下限仍然满足,整段全绿。

> **一句话判据:一个下限只能证明「表不空」,证明不了【那一条】还在表里。**

(这条在 `ASSERTION-PITFALLS.md` 里有独立编号,已装护栏。)

### ⑧ 判据只认**限定形式**的调用点

同一件事换个写法(换个重载、加个命名参数、拆成两行),扫源码的判据就认不出来了 ——
它会**静默地少数一处**,而少数一处正好等于「那处不存在」。

## 6. `SKIP` / `OWED` / `LIFE`:三个词的分工

**这张表是 D117 裁的,记住它。**

| 字段 | 含义 | 门禁怎么看 |
|---|---|---|
| `SKIP` | **这个形态下本来就测不了**(旁边没源码 / 这台机器上起不了替身进程 / 端口上坐着真东西) | 黄字打印,**不判红** |
| `OWED` | **本该跑得了却没跑成**(判据指错文件 / 子进程挂死 / 那一段一条结果都没写出来) | **判红** |
| `LIFE` | 「托盘右键关闭 → 管理端退出 → 栈真的没了」验没验到(**管理端专有**) | `0` **判红** |

哨兵格式:`PASS=n FAIL=n SRCHIT=n SRCMISS=n SKIP=n OWED=n [LIFE=n]`。
★ **头一段 `PASS=n FAIL=n` 逐字不动** —— `run-tests.ps1` 与 `build-client.ps1` **共用那条正则**;
新字段一律追加在后面。
★ 字段**缺失**(exe 比脚本旧)**不判红**,只说「口径不明」—— 不拿一个不存在的数去否定一次运行。
★★ `OWED=` 是**无条件打印**的(哪怕是 0)。源码注释里逐字解释了为什么:

> `run-tests.ps1` 读的是**控制台汇总行**,而「只在 >0 时才印」会让它读不到字段 ⇒
> 打出「口径不明:这份 exe 比本脚本旧」。**那句话在正常的一趟里是假的**,
> 而**一条天天说假话的提示会被人学会无视**。
> ⇒ 字段恒在:`OWED=0` 与「没有 OWED 字段」必须是两件看得出区别的事。

### ★★ 我今天把 `SKIP` 与 `OWED` 的分岔**跑出来给自己看了一次**

同一条断言(「每个 json 只能有一个写者」),两种处境,**输出完全不同**:

| 处境 | 它打印的 |
|---|---|
| exe 单独放在临时目录(源码根**不在**) | `SKIP  每个 json 只能有一个写者 —— 发布产物旁边没有源码` |
| 把两个锚点文件拷到 exe 旁边(源码根**在**,但读不到那些文件) | `OWED  每个 json 只能有一个写者 —— 客户端源码根在(<那个临时目录>)` ⇒ **判红** |

⇒ 这就是这套口径**存在的全部意义**:
**「这个形态下测不了」和「判据自己坏了」在没有这个分岔的世界里输出一模一样。**

### 7.1 ★★★ `dist/client/VERSION.txt` 里那句「两个数为什么不一样」的解释,今天不成立

那份文件逐字写着:

**三重证据它今天是假的:**

1. **它自己就把自己驳倒了。** 同一份 `VERSION.txt` 上面几行的口径逐字是:

2. **机制上不可能。** 见 §5②:`TryReadSource` 只认 `ClientSourceRoot()`,
   要求两个锚点文件同时在同一级。`dist/client/` 往上翻永远配不上这个条件。

**那 `1060 / 1059` 那一条差到底是什么?** 是 §4.5 那条 PASS↔SKIP 互换(剪贴板),
**与 exe 待在哪儿无关** —— 三轮独立测量里,同一个路径上两种值都出现过。

**★★ 而这句话最要紧的地方不是 `VERSION.txt`。** `dist/` 是**未跟踪目录**,新人克隆下来根本没有它。
这句话真正会撞上新人的地方是**跟踪着的源码**:它就印在客户端 `Selftest.cs` 的口径块里

## 8. 五个好的断言例子 —— 盯住同一件事:**它是怎么保证自己能红的**

### 例 1 —— 尺子自己的定标(客户端 `Selftest.cs`,`NoComments` / `CodeOnly` 那一组)

背景:`NoComments`(去注释器)/ `CodeOnly`(去注释 + 去字符串)是本仓**所有**源码判据的那把尺。
**一把量错了的尺,会让每一条靠它的判据变成一句没人验过的话,而且不出声。**

它喂进去的是**合成源码**(下面是节选,判词有删节):

```csharp
const string _u = "https:" + "//example";
var _src = "class X {\n"
  + "    string A() => $\"" + _u + "/a\"; void MarkerSameLine() { }\n"
  + "    void MarkerAfterUrl() { }\n"
  + "    char Q() => '\"';\n"
  + "    void MarkerAfterCharQuote() { }\n"
  + "    // MarkerInComment\n"
  + "    string B() => \"MarkerInString\";\n"
  + "}\n";
```

然后是 7 条定标(①、①b、②、③、④、⑤、⑥)。自证:`grep -n "定标" 20-client-win/app/Selftest.cs`。

**好在哪(四条,逐条学)**

1. **喂的是合成源码,不依赖本仓任何内容** —— 它测的是**尺**,不是被量的东西。
   仓库怎么改都不会让它假绿或假红。
2. **两个方向都钉**:①③ 钉「该留的留下了」(不把字符串里的 `//` 当注释起点、保留字符串),
   ② 钉「该剥的剥掉了」(**剥不掉就是个恒等函数**)。
   **只钉一个方向的定标,会被「恒真」和「恒假」两种坏实现分别骗过。**
3. **有一条合体断言(定标⑥)**,专门挡「把某一条定标改到刚好通过」那种修法。
4. ★★★ **它红过,而且是当场把作者自己的判断证伪的。** 源码注释里留了一句认错,逐字:

   > 写这段注释时我以为「客户端这两份今天是对的」—— **那句话被这组定标当场证伪了**:
   > 客户端这两份认字符串、却**不认字符字面量**……实测:补字符字面量分支**之前**,定标 ②④⑤⑥ 四条红。

   同一段还写着两句值得抄走的话:
   *「两边各坏各的……两个方向都得钉,少钉一个就会留下另一半。」*
   *「『今天是对的』与『有人在守着它对』本来就是两回事。」*

### 例 2 —— 元断言:先钉住「我切得到」,再钉内容(客户端 `Selftest.cs`,`ClientPairCard` 那一组)

```csharp
var cpc = Slice(dv, "UIElement ClientPairCard", "string? _pickedNic");
Assert(cpc is not null,
       "★ 元断言:切得到副机的配对入口 `ClientPairCard` —— 切不到的话下面两条会**静默变成零断言**");
Assert(cpc is not null && cpc.Contains("开始寻找主机"),
       "★ 副机未配对时的唯一主按钮是「开始寻找主机」");
Assert(cpc is not null && cpc.Contains("nics.Count > 1") && cpc.Contains("nics.Count == 1"),
       "★★ 网络选择【仅多网时出现】;只有一张就自动用它、不显示按钮(用户裁定)……");
```

(判词有删节;自证 `grep -n "ClientPairCard" 20-client-win/app/Selftest.cs`。)

**好在哪**

- **零命中不是通过。** 任何「在某段文本里找 X」的判据,前面都要有一条「我真的切到了那段文本」。
  函数改名、文件搬家之后,没有元断言的那几条会**静默变成零断言** ——
  而输出里少了三行 PASS 是没人会注意的。
- **最后一条示范了「判据不能比想判的东西宽」**:两个分支都钉,否则「永远显示选择框」也是绿的。

**同族写法你会反复看到,下面两条是我今天从仓库里挑出来的真例子:**

```csharp
// 20-client-win/admin/SelftestMoved.cs —— 遍历源是【登记表本身】,不是手写名单
var adminCids = LocalAI.Identity.WireContracts.All
    .Where(c => c.Cid.StartsWith("CONTRACT:cert.admin.", StringComparison.Ordinal))
    .Select(c => c.Cid).ToArray();
Assert(pinnedV4.Count == adminCids.Length && adminCids.Length > 0,
       $"★★ 元断言两个方向:钉了 {pinnedV4.Count} 条 / 登记 {adminCids.Length} 条(零命中也判红)");
```

★ 三处一起看:**遍历源是登记表**(新增一条契约而这儿没补断言 ⇒ 当场红)、
**两个方向都钉**(既不许多也不许少)、**`> 0` 把零命中也判红**、
而且**把两个数打印出来** —— 红的时候你一眼看得出是哪边错。

```csharp
// 20-client-win/admin/SelftestLiveViews.cs —— 反向判据自己钉住「我不是在空转」
Assert(revokedChecked > 0 || !devices.Any(x => x.Status == "revoked"),
    "★ 元断言:反向判据至少查了一条已吊销设备 —— 0 条的话这一段是空转,而空转看着像通过");
```

★★ 它旁边的注释记着这条元断言**真的抓到过一次**:
*「第一版改成钉指纹,结果 8 条全落进『分不开、跳过』那一支,反向判据整段空转 ——
而那个空转是被下面那条零命中断言当场抓出来的(`FAIL=1`),不是蒙混过去的。」*
**这就是「它红过一次给自己看」长什么样。**

★ 还有一条**元断言钉替身自己**(`20-client-win/admin/SelftestStackStop.cs`):
`Assert(py.ProcessName.Contains("python", …), "★ 元断言:替身的进程名真的含 python —— 不含的话它躲开了被测判据,这条测了个寂寞")`。
**替身也要被验过。**

### 例 3 —— 护栏自己会喊「我在空跑」(客户端 `Selftest.cs`,`RunCommentFedGuard`)

```csharp
var selftests = TryReadAllSources()
    .Where(x => Path.GetFileName(x.Path).StartsWith("Selftest", StringComparison.Ordinal))
    .ToList();
if (selftests.Count == 0)
{
    if (SourceRootPresent())
        Owed("「正向断言被注释喂绿」护栏",
             "源码根就在旁边,而一个 Selftest*.cs 都没枚举到 —— 护栏本身在空跑");   // ⇒ 门禁判红
    else
        Skip("「正向断言被注释喂绿」护栏", "发布产物旁边没有源码,读不到自检源码");     // ⇒ 黄字,不判红
    return;
}
```

**好在哪 —— 这是本仓最该学的一段**

- 它把**两种「什么都没扫到」分开**了:
  *源码根不在* = 这个形态下测不了(`Skip`);
  *源码根在、却一个文件都没枚举到* = **判据自己坏了**(`Owed` ⇒ 判红)。
- ★ 没有这个分叉,一条扫描型护栏在「提取器写错了」和「确实干净」两种情况下**输出一模一样**。
- ★★ 我在 §6 里把这个分叉**跑出来给自己看了一次**(同一条断言,一次 `SKIP` 一次 `OWED`)——
  **你也应该这样验一条护栏:造出它该红的处境,看它红。**

### 例 4(附赠)—— 一条断言怎么救了一整套判据:D 号闸的元断言

`90-ops/gate/check_decision_numbers.py` 的注释里记着一次事故,值得单独读:

> 第一版的正则写成 `\bD(\d+)\s*$`,只认得抬头两种形状里的一种 ⇒ 匹配到 **11 条**,
> **而元断言(≥20)当场把它拦住了。**
> ★ 记一笔:**那条元断言不是装饰** —— 没有它,这个正则会让 100 多个已落号被判成「缺失」,
> **而报出来的每一行都读起来像真的。**

**这就是「下限型元断言」用对的样子**(对照 §5⑦ 用错的样子:下限被一批不可能失败的条目撑着)。

### 例 5(附赠)—— 「把开关关掉再打一次」:`test_gpu_policy.py` 第 9 节的第 ⑤ 组

第 9 节一共 **六组**(①–⑥),不是「一正一反两条」。其中第 ⑤ 组是全节最承重的一条:

```python
gateway.TRUSTED_LOCAL_ACCOUNTS = frozenset({"nobody-by-this-name"})
_s9f, _c9f = _probe_real(_owner)
check("★★★★ 把机主从 allowlist 里拿掉 ⇒ 同一个账户、同一条回环连接立刻改不动 —— "
      "这条路的开关确实是 config/caller-accounts.toml,不是「走回环就是机主」",
      _c9f.status_code == 403, …)
```

它旁边的注释解释了为什么必须有它:

> 没有这一条,上面 ① 的 `_owner` **取自被测的那张表本身**,「这条路的开关是 allowlist」
> 这句话在这里**不可能为假**。

★ 而第 ① 组的注释还示范了**怎么正确地不写一条断言**:

> 这里**不写**「allowlist 非空」那种前提 —— 它恒真(`load_caller_accounts` 对空表直接 raise,
> `import gateway` 那一刻就炸了,断言根本跑不到)。要证明「判据真的是那张表」,
> 得**把机主从表里拿掉再打一次,见下面 ⑤**。

★★ **引这句话时必须带上「见下面 ⑤」那半句** —— 掐掉它,读起来像一条没做的待办,
而 ⑤ 就在下面十几行,**已经写好了**。
(上一版这份文档就是掐掉了后半句。这本身是一个「引用截断」的活例子,归 §7 那一族。)

★ 还有三组新人一定要知道的,别以为只有一正一反:
③ 回环但账户不在 allowlist ⇒ 403;⑤ 见上;⑥ 主机上**非机主** Windows 账户拿到的档位
比 `lan-device` 还少一个 lease。

## 9. 提交前的自问清单(照抄这五问)

1. **它有没有可能是恒真的?** 我能不能构造一个坏实现让它照样绿?
2. **我让它红过一次吗?** 改坏被测对象 → 看到它红 → 还原 → 复绿。**四个字:两个方向。**
3. **零命中会怎样?** 切片切不到、grep 命中 0 —— 会判红,还是会静默通过?
4. **在「旁边没有源码」那一趟里会怎样?** 答案必须是**跳过**(`Skip`),不是红。
   要它在那一趟也有效,就换成**运行时问得出来**的判据(`Enum.GetNames`、`Strings.Get`、直接调那个属性)——
   那类判据比查源码文本更强:**测的是行为,不是那串字写在哪个文件里。**
5. **我说「某处没有 X」时**,判据会不会被截断、被 markdown 排版骗、命中同名的别的东西?
   **它会不会叫别的名字?**(零命中不是不存在。)

★ 还有三条硬性习惯:

- 判据里机器要读的锚点**必须是 ASCII**(中文和标点在 cp936 控制台里会乱码 —— 这条踩过 4 次);
- **引一句注释时要注明它描述的是哪一版**(§5③ 与 §7.1 是两个活例子);
- 「从来没有 / 别处没有 / 被裁过两次」这类**考据式否定**,读 HEAD 证不出来,
  必须 `git log -S '<原文>'` 与 `git grep <commit>` 自证。
