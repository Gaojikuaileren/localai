# 00 · 这是什么,以及怎么把它跑起来

> 读者假设:你**从没见过这个项目**,不认识任何缩写,不知道任何历史,而你要接手继续开发。

## 0 · 先说三条读法,不然你会被这份文档(和其它每一份文档)骗到

**① 凡是数字,都在写下来那一刻开始过期。**
门禁的 PASS 数、决议编号、版本戳、耗时、行号、欠债条数 —— 一个都不例外。
所以本文里**每出现一个数,旁边就有一条你能自己跑的命令**。以你跑出来的为准,不是以这里写的为准。
看到别处哪份文档给了数却没给命令,那个数就当没看见。

**② 注释常常是「留痕」,记的是被换掉的那一版。**
这个仓库的习惯是:删掉一段代码之后,把原文和「为什么删」留在注释里。
所以你读到一段注释描述某个行为时,**先确认它描述的是哪一版**。
本文第 7 节列了今天仍然在骗人的几处 —— 那一节是本文最值钱的部分。

**③ 零命中不是不存在。**
`grep` 找不到某个东西,先问它会不会叫别的名字、会不会在另一份文件里。
例子(下面第 7 节还会展开):`grep D7 00-docs/DECISIONS.md` 是零命中,
但 D7 **确实存在** —— 早期决议在方案书 `§16` 里,`DECISIONS.md` 抬头逐字写着「不在此重复」。

> 我会写「未验」而不是写成事实。

## 1 · 五分钟版:这是什么

**一台自己的电脑上跑的私人助理,不是一个联网服务。** 它整个存在的理由写在方案书里:

> **一个真正的私人助理。** 记忆是它的核心,不是附加功能。

这句话在 `00-docs/PROJECT_PLAN_v3.0.md` 的 **§1 定位与范围**里(量于 2026-09-02 是第 96 行,别记行号):

```powershell
Select-String -Path 00-docs\PROJECT_PLAN_v3.0.md -Pattern '记忆是它的核心'
```

★ 顺带一句:那份方案书**开头几十行本身就是一条最值钱的留痕** ——
2026-08-08 有人逐条查实,把一个阶段从「已验收」改回「部分」,并写明**不补签字**的理由
(「缺的是那三格里真要有人去做的事,不是缺一行字」)。新人第一天该读的是那一段。

### 把它想成三件东西套在一起

1. **一台主机。** 模型权重、向量库、关系库、你跟它说过的话,全在这台机器的硬盘上。
2. **一个 Windows 桌面程序**(客户端),你双击它跟助理说话。它是**唯一入口**
   —— 早期用过的 Open WebUI 已经退役,任何文档再把它当日常用法推荐都是过期的。
3. **家里第二台电脑**装同一个客户端,通过局域网连上主机。它连的不是「一个账号」,
   是**这一台机器**:两边用应用自签的 CA 走双向 TLS,第一次连接要在两块屏幕上
   **逐字核对六个英文单词**,再由主机上的人按批准。
   主机的 CA 私钥在 TPM 里、不可导出、**故意不进备份** —— 换主机 = 所有客户端重新配对。
   这是有意的安全性质,不是遗漏。

### ★ 左下角那条显存条显示的是【主机】那张卡,不是你这台

这一条单独拎出来,因为它是本仓**专门裁掉过一次的事故形状**,而且直觉是反的。
去读 `20-client-win/app/Services/VramMonitor.cs` 的文件头,它逐字记着 2026-08-05 的裁定:

> 「本机那张卡**一个字都不显示**了:它不是"差一点的同类数据",它是另一台机器。」

在这之前,副机上显示的是**副机自己**那张卡,而标签只写「显存」——
两台机器的数字长得一模一样,**没有任何地方能看出来看错了**。
今天只剩三种口径(`VramSource` 枚举里逐条写着):

| 口径 | 标题 | 下一步该查什么 |
|---|---|---|
| `Hub` | 「主机显存」 | 正常,唯一会显示数字的来源 |
| `HostUnreachable` | 「主机未连接」 | 查网络 / 查 lan-edge 起没起 |
| `HostNoReading` | 「主机显存读不到」 | **连着**,坏的是主机上的采样器 —— 查显卡那头 |

★ 后两种**不能混为一谈**:说成「未连接」会把人支去查网络,而问题在显卡那头。

### 它今天真的能做什么

我读的是代码路径,不是抄清单:

- **能对话** —— 走本机的 8B 模型,逐字流式;
- **能按需装模型** —— 你在输入框敲第一个字,客户端就 `POST /v1/gpu/intent`,
  中枢把模型装进显存;闲下来再卸掉。**不需要你手动起后端**;
- **能在两台机器间同步**待办与「提升为共享」的会话;
- **能在你输入里出现疑似密码 / 密钥 / 银行卡号时,在送进模型之前拦下来**
  (`10-core/gateway/gateway.py` 的 `/v1/chat/completions` 里,E1 扫描排在组装和转发之前)。

## 2 · 三个目录、四个 exe(上一版文档说成「两个程序」,而漏掉的那个正是副机连不上的原因)

```
dist\
 ├─ client\   localai-client.exe        WPF 窗口程序 · 通用客户端 · 每台机器都装
 ├─ admin\    localai-admin.exe         WPF 窗口程序 · 主机管理端 · ★ 只装主机
 └─ host\     localai-lan-edge.exe      控制台程序(内嵌 Kestrel)· mTLS 边界 · ★ 只装主机
              localai-identity.exe      控制台程序 · 铸身份 / 列成员 / 吊销 · ★ 只装主机
```

自证这四个的项目类型与目标框架(**下一节会告诉你为什么必须自己读一遍**):

```powershell
Select-String -Path 20-client-win\app\localai-client.csproj,
                    20-client-win\admin\localai-admin.csproj,
                    10-core\lan-edge\localai-lan-edge.csproj,
                    10-core\identity\localai-identity.csproj `
              -Pattern 'TargetFramework|OutputType|Sdk='
```

**★ 三个目录必须并排。** 客户端**逐字**去探 `..\admin\` 与 `..\host\`。
单独拷走任何一个,都会让「主机自动起栈」或角色判定走不到。
`dist\README.txt` 是每次出包**自动生成**的,它自己也写着这句,并且记着一件事:
`host\` 曾经**从来没被任何脚本发布过**,落后一百多个提交而无人发现。

**主机那台**(铸过身份、持有 CA 私钥的那一台)装全部三个目录。
**副机**(家里第二台电脑)**只拷 `client\` 这一个目录**。

> ★★ 「副机不起栈」不是靠判断挡住的,是**结构性的**:副机上根本没有 `localai-admin.exe`。
> 这是本仓一条反复出现的手法 —— **用「够不着」代替「判断」**。
> 一条靠判断挡住的路,判断写错就通了;一条结构上不存在的路,写错也通不了。

### 角色判定今天是怎么判的(★ 我把上一版和反驳者都推翻了一次)

我 grep 过:`HostRole` 枚举、`ProbeRoleAsync`、`HostHubDown` 这几个名字
**今天在客户端代码里一个都不存在**,只剩在 `00-docs/` 的历史记录里。
`20-client-win/app/Views/DevicesView.cs` 的文件头逐字解释了为什么:

> 「此前『副机不显示主机卡』靠的是**运行期**探测(探不到 8442 就藏起来),现在是**代码不在**。」

所以「客户端开机去探 8442 端口来判自己是不是主机」这句话**今天是错的**。
今天的判据是 `20-client-win/app/Services/HostSetup.cs` 里的 `DecideRole` ——
一个**纯函数**,不碰 IO,吃三条互相独立的证据:

| 证据 | 问的是什么 |
|---|---|
| `AdminAppPresent` | 客户端旁边**装没装**管理端(`..\admin\localai-admin.exe`)。★ 只问「装没装」,不问「跑没跑」—— 后者会死锁,主机第一次启动时管理端当然还没跑 |
| `IdentityExists` | 本机有没有铸好的中枢身份 |
| `ConfiguredHubResolvesLocal` | 已知的中枢地址解析到本机了吗。★ `null`(解析不了)与 `false`(解析到别人)**必须分开** —— 合成一个的话,一次 DNS 抖动就会把主机判成副机 |

判法(照代码里的顺序):

1. 地址明确指向**别人** ⇒ 无论旁边放着什么,**都不是主机**。
   这一条排最前面是承重的:有人把整包拷到另一台机器时,管理端也跟着拷过去了,
   只有这条否定证据能拦住它;
2. 地址解析到本机 ⇒ 是主机;
3. 装着管理端 **且** 铸过身份 ⇒ 是主机(没有配置地址时走这条);
4. 其余一律「不是主机」,并**说清是哪一种拿不准**。

> ★ 代价不对称:副机误判成主机会去起一套不该起的栈(两台机器抢同一个端口、两个仲裁器各写各的账),
> 主机误判成副机只是退回手动。⇒ **拿不准一律答「不是」。**

### ★ 客户端源码里没有任何「单侧权威动作」,而这条是被断言钉住的

`20-client-win/app/Selftest.cs` 里有一条**元断言**,枚举整个 `app/` 树,
确认客户端里**不存在**起栈入口、铸身份、起 LAN Edge、回环管理面路由这些动作 ——
它们全部归管理端。而且它自带一条「元断言的元断言」:必须真的读到了 ≥20 个源文件,
否则「一个都没匹配到」会静默变成「全清白」。

```bash

```

### 还有第五个可编译产物,别被它误导

`20-client-win/transport/localai-client-transport.csproj` —— 早期的**无 UI 命令行客户端**,

## 3 · 跑起来之后有哪些进程,各听什么口,谁起谁,缺了会怎样

下表的端口我是**逐个读源码里的绑定语句**得出来的,不是抄文档。

| 进程 | 干什么 | 听哪个口 | 谁把它起起来 | 它不在的时候会怎样 |
|---|---|---|---|---|
| **pg-mem**(PostgreSQL) | 记忆库的关系面 | `127.0.0.1:5432` | Windows 服务,开机自启,跑在 `.\ai-mem` 账户下 | 记忆套件连不上。**今天的聊天不受影响**(网关根本不连它) |

| **Embedding** | 嵌入 + 重排,**跑 CPU、0 显存** | `127.0.0.1:18084` | Windows 服务 `Embedding`,NSSM 包 `D:\AI\venvs\embedding` | 嵌入/重排别名返回 503 |

### ★★★ `90-ops\start-stack.ps1` **不是**「也可手动」的等价路径

不带参数跑它,它除了起网关,还会**静态起一个 llama-server**(18081,`-ngl 99`,带鉴权密钥文件)。
而 **D101 裁定②** 原文要求自动起栈:

> 「只起 **gateway 与 lan-edge**,**绝不起 llama-server**:按需装载已经落地,静态起会和 transient 平面打架。」

`20-client-win/app/Services/ChatClient.cs` 的 `backend_unavailable` 分支上方有一整段留痕就是为这件事写的,
逐字:「照着这句话做,等于亲手制造一个与 transient 平面打架的后端。」

**「打架」具体是怎么发生的**(我读了 `10-core/gateway/model_loader.py` 才敢这么写):

1. 网关的 `adopt()` 会**认领**端口上已经在服务的后端 —— 你手起的那个会被认下来;
2. 但同一个端口被多个组件共用(8B 的三个上下文档都是 18081),
   **光看端口分不出是哪一档**,它按登记顺序取第一个匹配的,并如实标记这是**推断**;
3. `unload()` 对认领来的孤儿**只是从账上划掉,不杀** —— 边界是「不是我们起的,不该由我们杀」。
   ⇒ 结果是:一个网关**管不着、也杀不掉**的进程继续占着显存,而显存仲裁看到的是一个它没登记的占用者。

⇒ **正确用法**:

- 想要一个能聊天的栈 ⇒ **打开管理端**,模型交给按需装载;
- 只想手动验网关起不起得来 ⇒ `start-stack.ps1 -NoBackend`;
- 确实想要一个静态后端(比如脱开客户端压测网关)⇒ 跑不带参数的那条,
  **用完记得把那个 llama-server 停掉**。

自证:

```powershell
Select-String -Path 90-ops\start-stack.ps1 -Pattern 'NoBackend|Start-Process -FilePath \$Llama|Model8B'
Select-String -Path 00-docs\DECISIONS.md   -Pattern 'D101' -Context 0,30
```

### ★★ 怎么看它此刻在不在跑(不要相信任何一份写着「现在什么在跑」的文档,包括这一份)

栈是管理端拉起来的、随时在变。所以进文档的是**命令**,不是一张表:

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -in 5432,6333,6334,6335,6336,8080,8442,8443,18081,18082,18083,18084,18085 } |
  ForEach-Object {
    $p = Get-CimInstance Win32_Process -Filter "ProcessId=$($_.OwningProcess)" -EA 0
```

而你不会收到任何提示。
★ 顺带一提:这个仓库当前存的是一条**绝对路径**,所以你在别处克隆之后必须自己再设一次。

#### 步骤 2 —— 跑一次门禁,拿到**你自己的**基线

```powershell
# ★★ 先看有没有别人在跑它 —— 这个脚本【没有并发闸】,它不会告诉你有人正在跑
#   ★ `-ne $PID` 不能省:这条命令自己的命令行里就带着 'run-tests' 这几个字,
#     不排掉自己,它会稳定地把【你自己】报成「有人在跑」(我实测撞过)。
Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" |
  Where-Object { $_.ProcessId -ne $PID -and $_.CommandLine -match 'run-tests\.ps1' } |
  Select-Object ProcessId, CreationDate      # 空 = 没有别人在跑

# 然后自己计时,别抄任何人的秒数
$sw=[Diagnostics.Stopwatch]::StartNew()
powershell -ExecutionPolicy Bypass -File 90-ops\run-tests.ps1
$sw.Stop(); "$([int]$sw.Elapsed.TotalSeconds) 秒 / 退出码 $LASTEXITCODE"
```

- ★★ **必须用 PATH 上的裸 `python`**(脚本自己就是这么调的)。拿某个虚拟环境的 python 去跑,
  会因为缺包报**假 FAIL**;
- ★ 这个仓库是**多车道并行改**的(见第 6 节)。两边同时跑会互相拖慢近一倍 ——
  它们会同时停在同一个测试文件上好几分钟,那不是卡死;
- ★ 耗时:脚本文件头自己记着一个实测值,而我今天量到的和它不一样,和上一轮量的也不一样。
  **这个数随机器负载浮动近一倍,不要记它**,记「别以为它卡住了」就行;
- ★ 它会打印一张**覆盖账**,把「没跑的部分」逐条列出来并写明理由。
  **那张账比 PASS 数值钱得多** —— 它甚至会告诉你出厂产物落后 HEAD 多少个提交。

只想看清单不想跑(十秒出结果):

**坑长这样**(我 2026-09-02 在这台机器上实测过两遍):

四个项目**目标框架不一样**。客户端和管理端是 `net9.0-windows10.0.19041.0`
(为了用一个需要 Windows SDK 的 API 而改的),而 lan-edge 和 identity 是 `net9.0-windows`。
⇒ 客户端的正确路径是:

```powershell

```

而**旧目标框架的输出目录至今还留在这台机器的盘上**,里面躺着一份一个月前的同名 exe
(`bin\Debug\net9.0-windows\` 和 `bin\Release\net9.0-windows\` 两处都有,**大小还一样**)。
你照着一份旧文档写的路径跑,它**不会报「找不到文件」**,它会跑起来给你一个答案:

| 跑哪一个(量于 2026-09-02,这两个数明天就会变) | 结果 |
|---|---|
| `bin\Debug\net9.0-windows10.0.19041.0\`(**对的**) | `PASS=2190 FAIL=0`,退出码 0 |
| `bin\Debug\net9.0-windows\`(**旧的**,exe 是 2026-08-03 的) | `PASS=1451 FAIL=11`,退出码 1 |

★ 注意失败的**形状**:不是「跑不起来」,也不是一个假的绿,而是**十一条假的红**。
原因是这些断言会去读磁盘上**今天的源码**,而那份一个月前的 exe 里钉的是一个月前的锚点。
你会看到「模型是系统组导航项 FAIL」「有一键清空附件 FAIL」这类**在今天的代码里根本不成立的失败**,
然后花一天去修一个不存在的回归。

★ 认出它的两个特征:**PASS 数少了几百条** + **退出码非 0**。
★ 顺手把旧目录删掉,它对谁都没用,只会继续骗下一个人:

```powershell
Remove-Item -Recurse -Force 20-client-win\app\bin\Debug\net9.0-windows
Remove-Item -Recurse -Force 20-client-win\app\bin\Release\net9.0-windows
```

★★ 还有一条纪律:**开发树 / 出厂包原位 / 出厂包换个位置,三种形态的 PASS 数不可互比。**
`dist\client\VERSION.txt` 里自己就写着这件事,并给出了它那一版的两个数,还专门写:
「少的不是覆盖变差了,是那批断言在这个形态下**测不了**。」
你要比,只能拿**同一形态**的两次结果比。

## 6 · 这台开发机哪里特殊 —— 换台机器你会得到不同的结果

★ 下面每一条我今天都亲手量过。每条都配了命令,因为**换机器之后它们全都会变**。

### ① ★★★ UAC 是彻底关掉的 —— 这台机器上不存在「普通用户 / Medium」上下文

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' |
  Format-List EnableLUA, ConsentPromptBehaviorAdmin, PromptOnSecureDesktop
whoami /groups | Select-String 'Mandatory Label|Administrators'
```

我量到 `EnableLUA = 0`,而机主账户在 Administrators 组 ⇒ **该账户没有分裂令牌**。
桌面 explorer 自己就跑在 High,所以**它启动的每一个进程都是 High** ——
双击 `.cmd`、Explorer 拉起、计划任务、`runas /trustlevel`,全都一样。

**换到一台 UAC 正常的机器上会怎样(逐条):**

- 双击得到 **Medium** 进程,提权得到 **High**;
- ⇒ **铸身份的等级和用身份的等级会真的分家。**
  在这台机器上「用哪种方式铸」无所谓,在别的机器上**必须一致**(见第 4 节步骤 8);
- ⇒ 客户端与管理端那条「发现自己被提权就自动降权重开」的护栏,
  在这台机器上**永远不会触发**(降下来还是 High),在别的机器上会真的走。
  ★ 顺带看一眼 `20-client-win/app/Program.cs` 里那段:护栏问的**不是**「我是不是管理员」,
  而是「**设备密钥打不打得开**」—— 打得开就放行,什么等级都行。
  它是被改过的:原来问的是「是不是管理员」,而在 UAC 关闭的机器上那个判据**恒为真**,
  会把一台完全健康的机器判成不能用,**并且给出的理由是假的**;
  ★ 而且它**只许试一次重开** —— 曾经炸过:降权重开出来的进程仍然是 High,于是它又去重开自己,
  用户屏幕上窗口不停地闪;
- ⇒ 密钥目录的 ACL 只给 SYSTEM / Administrators / 服务账户,而在 UAC 的过滤令牌里
  Administrators 是 **deny-only 组** ⇒ **中等完整性的进程读不到它**。
  网关在正常机器上正是中等完整性的进程 —— 这就是后端鉴权密钥另开一个目录的原因。

> ★ **一句咬过两次的错话,别再传:** 曾经有文档写「任何靠降权来保证安全的设计在本机一律失效」。
> **那句话是假的**,真相窄得多:关在沙箱里的程序**自己拆不开**那道墙(实测「拒绝访问」),
> 子孙进程也一起被关住;**能拆的只有机主本人**。
> 两者的差别决定了一整条隔离路线可不可用 —— 前一句会把它整个否掉。

## 9 · 第一天会撞上的六道提交闸

`.githooks/pre-commit` 串了六道。★ 前提:你跑过 `git config core.hooksPath .githooks`,否则**一道都不响**。

| # | 闸 | 什么时候响 | 撞上了怎么办 |
|---|---|---|---|
| ① | **绝对路径** | 暂存的文件里出现盘符路径 | 路径从 `config/paths.toml` 读。**连注释里的绝对路径也禁**(它会随换盘变成一句错话) |
| ② | **自检门禁** | 本次提交动了网关 / 仲裁器 / 记忆相关代码 | 让它跑完。★ **会跑整套自检,数分钟** —— 用超时短的工具提交会把它掐死;提交信息先写文件再 `-F` |
| ③ | **行尾 / churn** | 一次改动里回车符数量大幅变化 | ★ **大改动会误报**。先自己数两边的 `\r` 自证,再用 `git -c diff.algorithm=histogram commit`。**不要**用它推荐的那个环境变量 |
| ④ | **中央三文档串行** | 在非 main 分支上改 `DECISIONS.md` / `PROJECT_PLAN_v3.0.md` / `STATE.md` | 这是有意的串行点(它们各有唯一的「当前状态」与编号计数器,两处同时写必打架)。★ **只有这三份**;`ASSERTION-PITFALLS.md`、`worklog/`、你自己新建的决议包**不在范围内**,可以直接改 |
| ⑤ | **控制字符** | 暂存的文本里有制表/换行之外的控制字符 | ★ **没有放行口,而且这是有意的**。成因几乎总是用 Python 写文件时反斜杠被当成转义。**按字节修** —— 眼睛看到的和磁盘上的字节不是一回事 |
| ⑥ | **决议编号落地** | 动了 `DECISIONS.md` 或 `decision-packets/` | 包里写了编号、中央文档里没有 ⇒ 红。真是草案就在**包里**写一行看得见的豁免锚点 |

**★★ 一条比上面任何一道闸都重要的纪律:不要用 `--no-verify`。**
那会把六道闸**一起**关掉。每一道闸在拦你的时候都会告诉你**它自己那一道**的正确绕法 ——
用那个,别用大锤。

### ★ 那道最出名的「绝对路径闸」,范围比它听起来小得多

```bash
sed -n '1,45p' .githooks/pre-commit      # 自己读一遍豁免表和扫描范围
```

- 它只扫 `git diff --cached --name-only --diff-filter=ACM` ——
  **未跟踪的文件永远进不了它的视野**(整个 `dist/` 就是这么逃掉的);
- 它有一张豁免表,里面包含 `config/paths.toml` · `00-docs/*` · `.githooks/*` · `.gitignore` ·
  **所有 `*.md`**,以及一个第三方语料目录。

⇒ 也就是说:**文档里写满绝对路径是被允许的**(本项目也确实到处写),
被挡住的只是「已跟踪的**非文档**文件」。
**别把「代码里没有绝对路径」理解成被机械保证了。**

### 三个已知的假红,认得出来就不会被吓到

1. 决议包里写十六进制色值(形如 `#dxxxxx`),会被 ⑥ 号闸读成「引用了某个决议编号」而拒掉。**色值写小写**;
2. ⑥ 号闸**只看本工作树的 `DECISIONS.md`**。引用别人刚取的号会被拒 ⇒ **先 rebase**,别去写草案豁免一个真号;
3. ⑤ 号闸会对你「**只是碰过**」的文件报**既有**缺陷。用 `git show HEAD:<file>` 自证归属
   (扫描范围要含 `0x0B` / `0x0C`,闸给的提示里漏了这两个);是既有的就按字节修掉,别绕过。

## 11 · 我没能验证的(如实列出来,别当成事实)

   和已存在的路径**推**出来的,不是我照着走了一遍。我验过的是:那些脚本存在、参数长什么样、
   端口绑在哪、失败分支写着什么;
