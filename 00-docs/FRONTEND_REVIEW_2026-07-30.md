## 4. 我认为值得你决策的问题(按重要性)

### ★ P0:数据全在内存,重启即失
`ChatCenter` / `ProjectCenter` / `TodoCenter` 都是 `List<T>` in-memory。**关掉客户端,项目、会话、聊天记录、待办全没了**。
现在做的所有"30 天回收站""置顶""项目状态"在重启后都归零 —— 这是目前前端与"可用产品"之间最大的一道坎。
**建议**:P3c 收尾时给这三个中心加本地 JSON 落盘(`${state}/client/`),中枢接入后再改为同步。工作量不大(它们的 API 已经很干净),但**必须先定**:落盘要不要加密?按 D21/D22 现状是明文,聊天记录明文落盘是个需要你点头的隐私决定。

### ★ P1:两套"模态"机制并存
`Overlay`(单浮层:抽屉 + Flyout)+ `ConfirmDialog`(独立模态窗)。今晚这么改是**对的**(浮窗自杀问题),但要记住这条边界:**从抽屉里弹出的确认,一律用 ConfirmDialog,不要用 Flyout**。已在 `ConfirmDialog` 顶部注释写清成因。

### ★ P1:`HomeView`(824 行)与 `ChatView`(774 行)偏胖
两者都混了"布局 + 数据 + 交互 + 动画"。目前还读得动,但再加功能就该拆:
- `HomeView` → 天气拖拽区、待办区各自成 View(日历早就独立了,是个好样板)。
- `ChatView` → 会话列表 / 会话区 拆开。
不紧急,但**在接数据源之前拆,比之后拆便宜**。

### P2:仍有 1 处系统弹窗 —— 这是**故意**的
`Program.cs:43` 提权拒绝(D46 护栏)。它在 WPF App 与皮肤字典**初始化之前**执行,自绘对话框依赖 `Application.Current.Resources`,那时还不存在。**保留系统 MessageBox 是正确选择**,已注释说明。

### P2:项目/会话的"可见范围"字段尚未真正过滤
`ProjectScope` 字段带着走,但"只列自己的 + 家庭的"这条 D45 规则**还没实装过滤**(等成员会话打通)。现在是单人单机,看不出差别;**多成员上线前必须补**,否则 D45 就成了摆设。

### P3:`Ui.Panel` 之外仍有少量手搓卡片
`ChatView` 里我用 `Ui.Card` + 手改 Padding 来收紧间距。可以给 `Ui.Card` 加个 `compact` 参数收敛(和 `Ui.Panel` 一样),避免以后各处手改 Padding 又走样。
