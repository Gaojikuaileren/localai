### ④-2 · 出包形态下客户端**少说约 1155 条**,而输出**说不出是哪一千多条**(B)

★ 而这恰恰把本条要说的事又坐实了一次:**连「少了多少」都要先问「哪两趟」,何况「少了哪些」。**

**这不是缺陷** —— 发布产物旁边没有源码,结构/接线判据整段跳过是**设计如此**(第 11 条),

- `SKIP` 计的是**组**(客户端全仓 `Skip("...")` 调用点 **11 个**,管理端 **19 个**),不是条;
- `SRCMISS` 计的是**读取落空次数**(出包形态实测 ≈256),不是条;
- **没有任何一条判据把这个差额与上面那两个数对上。**

⇒ 今天能回答的是「少了一千多条」,**不能回答「哪一千多条」**,更不能回答
「这一千多条里有没有本该跑得了却没跑成的」—— 而后者正是 `OWED` 这个字段被发明出来要回答的问题。

   (客户端 3 处 / 管理端 6 处)。一条判据**根本没意识到自己在这个形态下不说话**时,它不会去调 `Owed`。
2. 「差额是不是可以由 SRCMISS 推出来?」——不能。一次 `TryReadSource` 落空可能带走
   **一条**断言,也可能带走**几十条**(整个 `if (src is not null) { … }` 块)。两个数不是同一个量纲。

**★ 这一条为什么是 B 而不是 C**:见下面 ④-3。

### ④-4 · STATE 那张表里,客户端出包形态那一格**只记了 PASS/FAIL**,而机器其实产出了 SKIP/OWED(C)

- 客户端哨兵实际写的是 `PASS= FAIL= SRCHIT= SRCMISS= SKIP= OWED=`(`Selftest.cs:9557`);
- 管理端多一个 `LIFE=`(`admin/Selftest.cs:704`);
- `build-client.ps1:544-546` **三个字段都解析**。

**⇒ 是记账没记全,不是机器没产出。** 同一张表的管理端那一格(⑥)记了 `SKIP=11 · OWED=0 · LIFE=1`,
客户端那一格(⑤)只有 `1060 / 1059 · FAIL=0`。**同一件事,两个 exe 两套口径。**
读表的人因此**无法判断客户端那趟出包自检有没有 OWED > 0**。
