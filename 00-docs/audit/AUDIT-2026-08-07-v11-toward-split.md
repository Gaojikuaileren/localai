### A2 · 「优雅退出」在 Windows 上**实测不优雅**:`os.kill(self, SIGINT)` = TerminateProcess

`_stack_shutdown_sweeper()` 里 `os.kill(os.getpid(), signal.SIGINT)`,上方注释写着
「★★ 不用 `os._exit` —— 那会跳过 shutdown 钩子,后端全成孤儿」。

**实测**(本机 Python 3.12.10 / Windows 11):子进程注册 `atexit` + `signal.signal(SIGINT, handler)`,
调 `os.kill(os.getpid(), SIGINT)` 后 **EXITCODE=2,标记文件里只有 `BEFORE_KILL`
—— `ATEXIT_RAN` 与 `SIGINT_HANDLER_RAN` 一条都没有**。
CPython 在 Windows 上对非 `CTRL_C_EVENT`/`CTRL_BREAK_EVENT` 的信号走 TerminateProcess。

**影响**:同一次提交新加的 `@app.on_event("shutdown") _reap_backends_on_shutdown`(坑 3 的落点)
**不会被调用** ⇒ 自动关栈把网关杀掉,而按需装载起来的后端**继续占着显存**
—— 关栈的全部目的落空,并留下一批孤儿进程。
且网关被硬杀 ⇒ 所有租约当场作废,而这正是判据自己说「误关的代价是切断别人」时要防的事。

★ 反驳过两次(uvicorn 自己的 handler / 有控制台时会不会走 `GenerateConsoleCtrlEvent`),都不成立
—— TerminateProcess 是内核级终止,任何用户态 handler 都不执行;而 `CreateNoWindow=true` 连控制台都没有。

> **★ 撤回后仍然成立的部分(A2)**:发 SIGINT 的那个 sweeper 已删除 ⇒ **这条不再有触发路径**。
> 但**两件事留下来了**:
> ① **`shutdown` 钩子被有意保留**(注释原文:「坑 3(孤儿后端)**与架构无关,照修**」)——
>    它现在由 uvicorn 的正常退出触发,**那条路是好的**;
> ② ★★ **那条 Windows 平台事实值得单独留档**:
>    `os.kill(os.getpid(), signal.SIGINT)` 在 Windows 上**是 TerminateProcess**,
>    `atexit` 与 `signal handler` **一个都不跑**(本轮实测:EXIT=2,两个标记都没写出来)。
>    ⇒ **建议并入 `ASSERTION-PITFALLS.md` 或等价的平台事实清单** ——
>    下一个想在 Windows 上写「优雅自杀」的人会再踩一次,而这次是有实测数据的。
> ⇒ **本条从 A 降为 D(已随代码撤销),只留那条平台事实。**
