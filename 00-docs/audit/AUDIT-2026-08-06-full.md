### A1 · ★★★ LeaseKeeper 从未持住过任何租约 —— 目标一条没达成,副作用一条不少 【1 号车道】

**这是本轮最重的一条,也是整个审计里最典型的一条。**

`baf9c5c` 的标题是「S16-b:客户端真的持租约了 —— 『有没有人在用』终于是个可以为假的判据」。
实测:**它一次都没持住过。**

**证据(只读复现,不碰服务)**
- 服务端 `10-core/gateway/gateway.py:977-979` 返回
  `{"status":"ok", "lease": lease.to_json(), "fence_token": …, "generation": …}`
  —— `lease_id` 在 **`body["lease"]["lease_id"]`**。
- 客户端 `20-client-win/app/Services/LeaseKeeper.cs:155-157` 取的是
  `root.TryGetProperty("result") ? … : root`,然后在**那一层**找 `lease_id`。
- 用 `Broker.grant` 造出一字不差的响应体重放:
  `响应顶层键 = ['fence_token','generation','lease','status'] / 客户端解析出的 lease_id = None`
  ⇒ 走进 `:160` 的分支,`AcquireAsync` 返回 false,`State` 停在 `None`。

**连锁五条**
1. **`RenewAsync` 从不执行** —— `RunAsync:93` 的 `LeaseId is null` 恒真。
   这批提交刚开的 `/v1/gpu/lease/renew` 端点**零调用者**;它注释里写的
   「任何一台客户端续一次租,`_last_activity_at` 就刷新一次」这个基座**没接上**。
2. **租约泄漏** —— 中枢那边 `grant` 是真成功的(200),租约真实存在、TTL 90 秒;
   客户端退避封顶 30 秒 < 90 秒 ⇒ **稳态并存约 3 份同名 `client_session` 幽灵租约**,
   而客户端手上没有 `lease_id`,**结构上无法主动释放**。
3. **世代号每 ≤30 秒无缘无故涨一次**(`grant` 里 `_generation += 1`)⇒
   任何「缓存快照再提交」的路径都会莫名撞 409 `generation_conflict`。
4. **每次「点确定」先卡 5 秒,再弹一句假的「有任务正在跑」** ——
   实跑复现:`apply_intended(["llm.assistant.8b@16k"])` → `needs_user_choice`,
   消息是「有任务在跑:client_session(SENIORBIRDS,已 0 秒・不可驱逐)。请选『优雅中断』或『等它跑完』」。
   对话框给的两个选项**一个是假的、一个是错的**:「等它跑完」永远不会跑完;
   「优雅中断」让用户以为自己打断了一个正在跑的推理。
   ★ 而这正是上一轮 C4 刚做好的「占用者信息」**第一次上场就在说假话**。
5. **`recalibration` 独占租约结构上永远拿不到** —— `grant` 要求 `not self._leases`,
   只要任意一台客户端活着就恒回 `EXCLUSIVE_HELD`。B10⑥ 从「没写流程」变成「就算写了也拿不到闸」。
6. **全程静默** —— `LastError` 写了「中枢没给 lease_id」,而**没有任何订阅者**。

**为什么两边的断言都没抓住**
服务端测「顶层有哪些键」,客户端测「拿这个形状能不能解析」——
**各测各的,中间那条缝谁也没看**。门禁里那条 `needs_user_choice` 的用例还把
`DRAIN_WINDOW_S` 临时改成 0.01,**5 秒代价整个被盖住**,并且把
「`client_session` 挡住用户自己的变更」当成**正确行为**钉死了。

**修法**
1. `LeaseKeeper.cs:155` 先取 `lease` 子对象;或让 gateway 把 `lease_id` 平铺一份到顶层。
2. `AcquireAsync` 解析失败时**先把刚拿到的那份放掉**,否则失败路径必然泄漏。
3. **跨语言的响应形状必须有一条成对断言**:服务端钉「顶层键集合」、客户端钉「拿这个形状能解析出 lease_id」。
4. 把 `blocking_leases()` 加一条「租约必须点名了组件」——
   `components` 为空的 `client_session` 声明的是「有人在」,不是「有活在跑」;
   或新增 `client_presence`(`blocking=BLOCKING_NONE`)。
   ★ 后者与 `LeaseKeeper.cs` 文件头自述**完全一致**:「它声明的是『有人在』,不是『我要用哪个模型』」。
5. 门禁那条用例改回真实 `DRAIN_WINDOW_S`,并补一条**会红**的断言:
   持空 `components` 的 `client_session` 时 `apply_intended` **不得**返回 `needs_user_choice`。

### A2 · 门禁从不编译客户端工程 —— 38 分钟编译断裂,而它连报两次绿 【跨车道 / ops】

**事故已经真实发生过一次。**
- `aa2b310`(08-06 01:32)在 `20-client-win/transport/ClientTransport.cs` 里调用了
  `TlsFailure.LocalCertNotAfter` / `CertLifecycle.Phase` / `CertLifecycle.ShouldRenew`,
  而同一提交的 `localai-client.csproj` 的显式 `Compile` 名单里**既没有 `TlsFailure.cs` 也没有 `CertLifecycle.cs`**
  ⇒ 客户端工程结构上编不过。
- 修它的 `baf9c5c` 提交于 02:10。**窗口 38 分钟。**
- 窗口内 `20a06b0`(01:42)的提交信息末尾写着「门禁:**PASS=3126 FAIL=0**」。

**三层根因,一层比一层深**
1. 陈旧判据的扫描根写死 `20-client-win\app`(`run-tests.ps1:264`),
   **不含** `20-client-win/transport` 与 `10-core/identity` —— 而客户端 csproj 直接 `Compile` 那八个文件。
2. 它的 `-Include` 只认 `*.cs` 与 `*.xaml`,**把 csproj 本身排除在外** —— 而历史上炸的那次改的正是 csproj。
3. ★★ **最根本的一层:门禁从不 `dotnet build` 客户端工程**,只跑预构建 exe
   (`:288-296` 三个分支里没有任何一支调 build)。
   对照:identity / lan-edge / transport 三个套件**都是真编的**,唯独 app 不编。
   **时间戳是「产物旧」的代理,它代理不了「编不过」。**
   ⇒ app 是唯一装到用户机器上的工程,却是唯一不被编译验证的工程。

配套:`.githooks/pre-commit` 的自检触发范围是 `^10-core/(gateway|gpu-broker|memory)/`,
**改 identity 不触发任何自检**。而 `run-tests.ps1` 的 `dotnet build` 又丢弃退出码与全部输出,
编译失败被降级成「没有 PASS= 汇总行」。

**修法**:`-Full` 段加 `dotnet build 20-client-win/app/localai-client.csproj -c Release`(只 build 不 publish,十几秒),
检查退出码,非 0 直接判红并打印编译器错误 · 扫描根改成**解析 csproj 得到的路径集合** ·
配一条元断言:csproj 里每个 `Compile Include` 必须落在扫描根集合内(与 `ROUTE_TIERS` 反向全表同款)。
