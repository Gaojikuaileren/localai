## 0. 定位变更(本次最重要的改动)

**v1 的定位**:三个场景并重(日常 / 资产 / 交易)。

**v2 的定位**:

> **一个真正的私人助理。** 记忆是它的核心,不是附加功能。
> 资产生成与投资研究是**围绕这个核心的能力扩展**,不是并列的三条腿。

这个转变有实质后果:**记忆系统从"以后再说的记忆层"变成第一优先级子系统**,并因此获得独立的架构章节、独立的数据模型和独立的隐私红线。资源(显存 / 开发时间 / 打磨精力)按这个优先级分配。

## 4. ★ 记忆系统(本项目的核心)

### 4.1 五层记忆

| 层 | 内容 | 存续 | 存储 |
|---|---|---|---|
| **L0 工作记忆** | 当前会话上下文窗口 | 易失 | LLM context |
| **L1 会话摘要** | 每轮 / 每会话结束的滚动压缩 | 数天 | PostgreSQL |
| **L2 情节记忆** | 带时间戳的事件:"7月26日你说打算买 4TB 硬盘" | 长期 | PostgreSQL + Qdrant |
| **L3 语义记忆** | 关于你的**结构化事实**:偏好 / 人际关系 / 进行中的项目 / 习惯 | 长期 | PostgreSQL(结构化) |
| **L4 程序记忆** | 学会的工作流:"整理下载文件夹" = 这几个确定步骤 | 长期 | 版本化 Spec / 脚本 |

### 4.2 ★ 双轨检索 — 最关键的设计决定

> **只做向量 RAG 的记忆系统,会在最需要精确的地方失败。**

| 轨道 | 回答的问题 | 技术 |
|---|---|---|
| 向量检索(Qdrant) | "**相关的**是什么" — 模糊、联想、上下文 | bge-m3 + rerank |
| 结构化查询(PostgreSQL) | "**确切**是什么" — 精确事实 | SQL over 实体表 |

举例:"我妹妹叫什么名字"——向量检索会返回一堆"关于妹妹的对话片段",但答不出名字;这必须走结构化实体查询。反过来"上次我们聊过的那个关于灯光的问题"必须走向量。

**两轨都要,且由编排器根据问题类型选择或并用。**

### 4.3 实体图谱(做到"家人"级别的前提)

```
Person      你 / 家人 / 朋友        ── 关系边(称谓 · 亲疏 · 重要日期)
Project     .localAI / UE5 项目 / 投资计划
Device      这台工作站 / 手机 / 未来的第二台 PC
Place       家 / 常去的地方
Thing       设备 / 物品 / 订阅
Event       带时间戳,可关联到以上任意实体
Preference  带置信度与时效性
```

### 4.4 写入把关(Memory Gate)

**不是什么都记。** 每条候选记忆需通过判断:

- 是否是关于用户的**持久**事实(而非一次性任务细节)?
- 是否会影响未来的行为?
- 是否用户明确要求记住?

写入后**必须**满足:
- **用户可见** — 有一个记忆面板可以浏览全部记忆
- **用户可编辑 / 可删除**
- **记录来源** — 哪次对话、什么时间、原文片段

### 4.5 时效、冲突与可解释性

**每条事实携带**:`asserted_at` · `confidence` · `source_ref` · `superseded_by`

**冲突处理**:新事实与旧事实矛盾时**不覆盖**,新增一条并将旧条标记为 superseded,保留完整历史。因为"曾经如此"本身是有价值的信息。

**时效性**:部分事实天然会过期("我最近在减肥""我在找工作")→ 定期 review 提示,由你确认仍然有效或标记结束。

**★ 可解释性是信任的前提**:当助理说"我记得你提过 X",必须能一键展开看到:**来源对话 · 时间 · 原文片段**。没有可解释性的记忆既不敢信任,也无法纠错。

### 4.6 隐私红线

| 规则 | 说明 |
|---|---|
| 静态加密 | 记忆库是整个系统里最敏感的数据 |
| **永不出境** | 即使使用 `escalate.cloud`,也**只发送当前任务的脱敏上下文,绝不发送记忆库内容** |
| 备份分级 | 记忆备份与资产备份分离,采用更高保护等级 |
| 不进日志 | 记忆内容不写入常规运行日志 |

### 4.7 克制的主动性

私人助理与聊天机器人的差别在于**主动**,但主动必须极度克制:

| | 行为 |
|---|---|
| ✅ | 基于时间 / 日历的提醒(**你曾明确让它记的**) |
| ✅ | 状态变化通知(任务完成 · 磁盘水位 · 模型下载完毕) |
| ✅ | 明确承诺的跟进("下周提醒我买硬盘") |
| ❌ | "我觉得你可能想知道"式的主动打扰 |

**原则:只在你曾明确请求过的事情上主动。**

### 4.8 多模态写入通道

随口一句"记一下,下周要交房租"应当直接进入 L2/L3——这要求**语音层与记忆层打通**,也是本版把语音提前并设为常驻的主要理由。

## 5. 资产工作室(重构)

### 5.1 事实澄清:nano-banana 不做 3D

> **nano-banana(Google Gemini 2.5 Flash Image)是 2D 图像生成 / 编辑模型,不生成 3D 网格。**

它的强项恰好契合你要的交互:**原生接受参考图 + 指令式编辑**,角色一致性好,迭代修改自然。所以它非常适合概念阶段。

**但 3D 仍需另找出路**,三个选项:
1. 本地 Hunyuan3D / TRELLIS(显存 10–14GB,独占,且 sm_120 编译需趟)
2. 云端 3D 生成 API(另一条数据出境路径)
3. **本期不做 3D,先把 2D 与交互打磨好** ← **建议采用**

### 5.2 双轨分工与出境闸门

| 阶段 | 走哪条 | 理由 |
|---|---|---|
| **概念图 / 风格探索 / 迭代修改** | ☁️ nano-banana | 交互自然,参考图原生支持,不占显存,不占磁盘 |
| **批量生产 / 风格锁定 / 精确控制** | 🏠 本地 ComfyUI | 可复现 · 不花钱 · 不出境 · 已有 ControlNet 基础 |
| **贴图 / PBR / de-light** | 🏠 本地 ComfyUI | 需要确定性管线 |
| **3D** | ⏸ 本期不做 | 见 §5.1 |

**这个划分同时给了数据出境闸门一条清晰规则**:概念阶段的参考图通常是公开素材或自己的草图,出境风险可接受;涉及项目专有素材的生产阶段留在本地。**闸门在提交前明示将发送什么,由你逐次确认。**

### 5.3 ★ 模型管家(Model Curator)

> **建在已有的 ComfyUI-Manager 之上,不重造下载与安装。**

ComfyUI-Manager 已解决:按名称搜索 · 下载 · 安装 · 更新。
**缺的是语义层与治理层**,这正是本模块要补的:

```
你的自然语言需求("我想要能画等距像素风建筑的")
   ↓ 意图理解(LLM)
结构化检索条件(底模类型 · 风格标签 · 用途 · 许可证要求)
   ↓ 查询 Civitai / HuggingFace API
候选列表 + AI 解读
   "这个是 SDXL 的 LoRA,擅长等距建筑,但许可证禁止商用"
   "这个是 Flux 的,和你现有的 Juggernaut 底模不兼容"
   ↓ 你选择
调用 ComfyUI-Manager 安装 → 校验哈希 → 写入模型注册表
```

**模型注册表额外记录(ComfyUI-Manager 不记的):**

| 字段 | 用途 |
|---|---|
| 许可证 / 商用条款 | 游戏资产若要商用,许可证链条必须可追溯 |
| 底模兼容性(SDXL / Flux / SD1.5) | 避免装了用不了 |
| 最后使用时间 · 使用次数 | 清理决策依据 |
| 重获成本(下载大小 · 是否仍可获取) | 决定该不该删 |
| 你的评价笔记 | 半年后你不会记得哪个更好用 |

**清理助手**(与 §7 的 GC 联动):
- "这 12 个 LoRA 三个月未使用,共 3.2GB,建议清理"
- **引用计数保护**:仍被任何 Asset Spec 引用的模型不建议删除
- **只提示,不自动删**(重下成本高)

### 5.4 ★ 提示词转译器(Prompt Translator)

**你不写硬核 prompt。** Asset Spec 是唯一的人机接触面,不同目标由编译器处理:

```
中文自然语言 + 参考图
   ↓
Asset Spec(结构化,与目标模型无关)
   ↓ 多目标编译器
   ├→ SDXL prompt        (tag 堆叠 + 权重语法)
   ├→ Flux prompt        (自然语言长句)
   ├→ nano-banana 指令   (指令式编辑描述)
   └→ ComfyUI workflow JSON(模板填槽)
```

**不同底模的 prompt 风格差异巨大**——SDXL 吃 tag 堆叠,Flux 吃自然语言句子,nano-banana 吃编辑指令。手写就意味着换模型要重写全部提示词;**编译器让 Asset Spec 跨模型可移植**。

**反向能力(同样重要):**
- 贴进别人的 prompt → 解析成 Asset Spec → 逐段解释在做什么 → 存为可复用模板
- 这是学习与复用的主要途径

### 5.5 ComfyUI 集成方式

现状 `D:\ComfyUI`,23.89GB,git 安装,自带 venv。

| 决策 | 做法 |
|---|---|
| 不重装,不迁移存量 | 现有 16.92GB 模型留在原地,零风险 |
| 配置 `extra_model_paths.yaml` | **额外**读取 `D:\AI\models\`;**新**模型放统一位置,存量自然消化 |
| 定位为 JOB 平面的媒体 Worker | 不作为平台核心;工作流存 JSON 模板,参数化调用 |
| 显存受 GPU Broker 管辖 | 加载前申请租约,不自行争抢 |

## 7. 显存与存储(按 v2 范围重算)

### 7.1 显存模式

砍掉 Flux FP8(12GB)与本地 3D 后,压力显著缓解:

| 模式 | 组成 | 桌面接核显 | 桌面接独显 |
|---|---|---|---|
| **`daily`(默认常驻)** | LLM 8B Q4@16K (6.2) + ASR/TTS 合并 (4.0) + 小 VLM (2.5) | **~13.0GB ✅** | ~14.7GB ⚠️ |
| `deep`(按需) | 驱逐小 VLM,加载 30B-A3B 混合 | ~15.3GB ⚠️ | ❌ |
| **`asset`(异步出图)** | 驱逐 LLM 与 VLM,**保留语音** + ComfyUI SDXL 栈 (10.4) | **~14.7GB ✅** | ❌ |

**`asset` 模式保留语音是有意的体验设计**:出图是异步 JOB,你提交后会去做别的事,此时仍应能用语音问"好了没"。

**两个优化(源自实测认知):**
- **ASR + TTS 合并为单进程** — 省一个 CUDA context(~0.4GB);生命周期一致,合并代价可接受
- **显示器接主板核显** — 释放约 1.7GB。在 v2 范围下从"前置条件"降为**强烈建议**(Flux 已不在本地跑),但 `deep` 与 `asset` 模式仍依赖它才舒适

### 7.2 存储预算(v2 大幅下降)

| 项 | v1 | **v2** |
|---|---|---|
| LLM(8B + 30B-A3B + 小 VLM) | 25GB | 25GB |
| Embedding / Rerank(跑 CPU) | 5GB | 5GB |
| 语音(ASR + TTS) | 9GB | 9GB |
| **图像** | ~42GB | **复用现有 16.9GB + 增补 LoRA ~5GB** |
| **3D** | ~35GB | **0(本期不做)** |
| 运行时(CUDA Toolkit + venv;ComfyUI venv 已占 6.5GB) | ~55GB | **~30GB** |
| 记忆库 + 数据库 | 1GB | **2–10GB(核心数据,增长慢)** |
| 候选区 | +60GB | +35GB |
| 缓存 | 40GB | ~30GB |
| **起步** | ~85GB | **~75GB** |
| **全功能就绪** | ~210GB | **~130GB** |

### 7.3 存储生命周期

五个逻辑根不变(CODE / STATE / MODELS / ASSETS / CACHE),GC 策略见 v1 §5.2,本版新增:

- **记忆库(STATE 根)进 GC 白名单**,与交易账本同级保护
- 模型清理由 §5.3 的模型管家提供交互界面,遵循"引用计数保护 + 只提示不自动删"
