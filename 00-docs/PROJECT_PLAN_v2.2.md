## 4. ★ 记忆系统

### 4.1 五层记忆

| 层 | 内容 | 存续 | 存储 |
|---|---|---|---|
| **L0 工作记忆** | 当前会话上下文窗口 | 易失 | LLM context |
| **L1 会话摘要** | 滚动压缩 | 数天 | PostgreSQL |
| **L2 情节记忆** | 带时间戳的事件 | 长期 | PostgreSQL + Qdrant |
| **L3 语义记忆** | 关于你的结构化事实 | 长期 | PostgreSQL |
| **L4 程序记忆** | 学会的工作流 | 长期 | **版本化 + 签名,见 §4.4.2** |

### 4.2 ★ 双轨检索

> **只做向量 RAG 的记忆系统,会在最需要精确的地方失败。**

| 轨道 | 回答 | 技术 |
|---|---|---|
| 向量检索 | 「**相关的**是什么」 | Qdrant · bge-m3 + rerank |
| 结构化查询 | 「**确切**是什么」 | PostgreSQL · SQL over 实体表 |

「我妹妹叫什么名字」——向量检索返回一堆相关片段但答不出名字,必须走结构化查询。反过来「上次聊的那个灯光问题」必须走向量。**两轨都要,由编排器按问题类型选路。**

### 4.3 实体图谱

`Person`(关系边:称谓 · 亲疏 · 重要日期)· `Project` · `Device` · `Place` · `Thing` · `Event`(带时间戳,可关联任意实体)· `Preference`(带置信度与时效性)

### 4.4 写入把关(Memory Gate)

#### 4.4.1 三问

- 是否是关于用户的**持久**事实?
- 是否会影响未来的行为?
- 是否用户明确要求记住?

写入后**必须**:用户可见 · 可编辑可删除 · **记录来源**。

#### 4.4.2 ★ 置信度只能由服务端可验证的信号产生(v2.2 新增)

> **审查 S1**:客户端自报 `user_explicit` 可铸造 confidence=1.0 的「用户事实」并自动 supersede 真实事实。而 L4 是可执行工作流 —— **这条链直通代码执行**。

Gate 输入必须携带 `provenance`,且 `body` 里的 `user_explicit` 字段**一律忽略**(与 `device_id` 同等对待):

| 来源 | `source_confidence` | 能否自动 supersede |
|---|---|---|
| 记忆面板上的显式点击(带票据) | 1.0 | ✅ |
| 客户端 UI 标记,且该输入经设备密钥签名 | 1.0 | ✅ |
| 助理从对话流推断 | ≤ 0.6 | ❌ |
| `tool_result` / `web_content` / `rag_chunk` 派生 | ≤ 0.4 | ❌ 且强制 `pending` |

`provenance ∈ {user_typed, user_voice_asr, tool_result, rag_chunk, web_content}`,**只有前两类可产生 explicit 候选**。

**`pending_review` 禁止批量确认。** 逐条确认,且「这条将取代哪条现有事实」是主视觉。积压上限 50 条,超限告警并**暂停接受远程候选** —— 积压本身是攻击信号。

> 这是 §6.6「计划本身要被审查」在**写侧**的对应物。

#### 4.4.3 ★ L4 是代码资产,不是记忆的一层(v2.2 新增)

> **审查 S2**:L4 程序记忆是可执行工作流,却与 L2/L3 共用写权限。

1. L4 写入**仅 `trusted-local`**,且**逐次哈希绑定批准**(与 §12.4 对批量文件操作同级)。远程档位的路由表里**不存在 L4 写端点**。
2. L4 条目**版本化并签名**。策略层在消费任何 L4 派生的提案前,校验源条目当前哈希与**你最近批准过的**哈希一致,不一致则拒绝执行。这把 §12.4 的哈希绑定从「提出到执行之间」延长到「**教会到执行之间**」。
3. L4 的 supersede = **需批准的版本升级**。§4.5 的自动裁决对 L4 一律不适用。
4. **远程档位检索默认排除 L4** —— 读工作流步骤对远程问答无价值,却给了攻击者一张可执行面的地图。

### 4.5 时效、冲突与可解释性

每条事实携带 `asserted_at` · `confidence` · `source_ref` · `superseded_by` · **`origin_device_id`** · **`write_seq`**。

**冲突**:新旧矛盾时**不覆盖**,新增一条并将旧条标记 superseded,保留完整历史。
**铁律**:**自动事实不得 supersede 用户事实**。否则任何能把文件写进授权区域的东西都能改写你的记忆。

**时效**:部分事实天然过期 → 定期 review 提示。

**★ 可解释性是信任的前提**:助理说「我记得你提过 X」时,必须能一键展开看到 **来源 · 时间 · 原文片段 · 记录设备**。没有可解释性的记忆既不敢信任,也无法纠错。

### 4.6 ★ 隐私红线(v2.2 重写强制机制)

| 规则 | 说明 |
|---|---|
| 静态加密 | 独立 BitLocker VHDX(`D:\AI\state\memory.vhdx`)。**仅覆盖关机态** |
| **运行态保护** | **OS 账户隔离 + 网关认证**(见 §6.8)。不再声称有第三层 |
| **永不出境** | 见 §4.6.1–4.6.3 的三层强制 |
| 备份分级 | 见 §8.5,**公钥加密** |
| 不进日志 | 见 §9.2 |

#### 4.6.1 三层强制(缺一不可)

> **审查 S5**:`no_export` 属性在 `r.text` 这一步就失效了。`r.text` 是 `str`,不是 `MemoryResult` —— **引用链在属性读取那一刻就断了**。而 `ctx = "\n".join(r.text for r in results)` 是 RAG 注入的标准路径,**每次都走这一步**。

| 层 | 做法 |
|---|---|
| **类型层** | `MemoryResult.text` 返回 `TaintedText`(密封,**不实现 `__str__`**,不实现 `Exportable`),只能经 `render_for_prompt(backend)` 取值;`backend.egress == true` 时抛 `MemoryExportViolation` |
| **渲染层** | 出境闸门的**最终**强制点放在**已组装完成的 prompt 字符串**上,不是组装前的类型检查 |
| **存储层** | `CHECK (no_export = true)`;`UPDATE ... SET no_export = false` 在数据库层被拒 |

#### 4.6.2 ★ 必须明文写下的一句话

> **不得声称「记忆零外发」是被证明的。**

`no_export` 作用于对象与已组装文本,**无法阻止你手动复制粘贴**。§10 的断言相应改为两条可验证的:

1. 「不存在任何程序路径使记忆文本进入出境载荷构造器」—— 否定用例须覆盖 **str 拼接 · f-string · 模板渲染 · 日志格式化** 四种取值方式
2. 「重叠检测在记忆 eval 集上的召回率 ≥ X%」—— X 由实测填,不预设

#### 4.6.3 Off 档的结构性保证

> **审查 S6**:Off 档「记忆可查 + 云端推理」若靠 UI 文案与运行时判断,用户看到的提示会与实际发生的事**恰好相反**。

按 §6.2「按会话挂载工具池而非运行时判断」落实:

- 模型别名注册表给每个后端打 `egress: true|false`
- 会话建立时若解析出的生成后端 `egress=true`,**该会话的工具池里根本不挂载 `memory.search`**
- 记忆检索由客户端走**独立的 MEMORY 平面**单独发起,结果只渲染成卡片,**永不回流进 MODEL 平面的请求体**

**「云端基于记忆推理」在会话结构上不可表达**,而不是靠运行时判断或文案。

> Off 档的正确表述是「**记忆可查 + 云端推理**」,**不是**「云端基于记忆推理」。UI 文案必须写清。

### 4.7 ★ 打扰评分(整节替换 v2.1 的「克制的主动性」)

> **本节起因**:用户于 2026-07-26 明确决定**推翻 v2.1 §4.7 放权**。原文「只在你曾明确请求过的事情上主动」与「无时无刻清醒、持续分析」的助手直接冲突。

#### 4.7.1 放权的实际含义

放权不是「随便打扰」,而是**把「能不能主动」从一条禁令,改成一个有阈值、有配额、有反馈的机制**。

原则从「只在你请求过的事上主动」变为:

> **主动性是挣来的。** 新的打扰类型从最低级别起步,靠你的反馈逐步解锁更高级别。

#### 4.7.2 四段流水线与信任边界

```
① 提名  ← Vigil(1.7B CPU)。只填受约束的槽,不给分数
② 校验  ← 确定性代码。claim_class 白名单、证据行号存在性、来源类型
③ 评分  ← 纯确定性公式。Vigil 读不到公式,也读不到自己的得分
④ 投递  ← 配额闸 + 分级路由
```

> **★ 核心难题与解法**:§6.6 说模型是不可信计划者。**如果评分由模型自己给,它就能给自己打高分来打扰你。**
> 解法不是「让模型诚实」,而是**改变模型的任务** —— 它只做分类(属哪类 / 命中哪个既有主题 / 是否新颖 / 是否命中承诺 id),判断留给它读不到的确定性公式。

#### 4.7.3 提名契约(模型只能填槽)

`title` **不是模型自由文本**,由 `claim_class` 固定模板 + `{root,rel}` + 证据行号拼装。
`claim.summary` 上限 **80 字**,必须以模板起头 ——「`{rel}` 在 `{行号}` 附近出现与 `{topic}` 相关的变化」。

> 自由文本越长,注入载荷的携带能力越强。

#### 4.7.4 五维评分与来源封顶

| 维 | 含义 | 权重 |
|---|---|---|
| U 时效性 | 错过就没用了吗 | 0.25 |
| S 后果严重性 | 由 `claim_class` 决定 | 0.30 |
| R 关联度 | 是否命中你曾表达关心的主题 | 0.20 |
| N 新颖性 | 是否重复既有信息 | 0.15 |
| C 置信度 | 证据强度 | 0.10 |

**★ 来源封顶(防操纵的核心):**

| `claim_class` 档 | 开放给 |
|---|---|
| `irreversible_loss` / `financial` / `system_degradation` | **仅 `source=deterministic`**(§4.7.6 白名单与 §9.3 告警器) |
| `self_commitment` 及以下 | `source=model_nominated` **封顶 S=0.40** |

`deadline_src=file` 的 U **上限 0.35**(与 `inferred` 同档)—— 文件里的时间戳正是攻击者最容易控制的东西,「字面出现在 quote 里」只证明它来自那个文件,不证明它是真的。

> **修复后重算注入攻击链**:Base = 100×(0.25×0.35 + 0.30×0.40 + 0 + 0.15×0.30 + 0.10×1.0) = **34.8** → ×0.925 = **32** → **L1 日报**。
> 攻击者能拿到的最好结果是「进日报」,不是「弹通知」。

#### 4.7.5 分级与配额(v1 只开两档)

| 级 | 分数 | 通道 | v1 |
|---|---|---|---|
| L0 | < 20 | 静默记录 | ✅ |
| **L1** | 20–59 | **每日 22:00 日报,每天 3 条** | ✅ |
| L2 | 60–79 | 托盘角标 | ❌ P9 之后 |
| L3 | 80–94 | 系统通知 | ❌ 需解锁 |
| **L4** | ≥ 95 | 强提醒 | ✅ **仅确定性白名单** |

**★ 硬性配额优先于一切分数**:每日主动打扰(L2 及以上)**上限 3 次**。模型再怎么给自己打高分也突破不了。**配额不依赖模型诚实,这是它相对评分公式的根本优势。**

**唯一自适应通道**:同一 `claim_class` 累计 **3 次**你标记「该早点说」→ 解锁 L3。

> **为什么 v1 砍到两档**:完整设计的自适应能力依赖一次 shadow 期末的 2–4 小时人工标注。那次标注不会被完成(单人 · 业余 · 6–12 个月跨度)。不完成则整套退化成一个拍脑袋的固定公式,而 L3 阈值在真实分布下几乎无人能过 —— 你一个月收到 2 条通知,结论是「这功能没上线」,然后关掉常驻助手。

#### 4.7.6 确定性 L4 白名单(不经模型)

磁盘水位越线 · 显存租约被拒 · 出境费用达月度上限 80%/100% · **备份任务失败** · 记忆写入失败 · 隔离区即将到期 · 你曾明确设定的时间提醒。

#### 4.7.7 反馈与可解释性

日报每条两个按钮:**「该早点说」** / **「不用告诉我」**。

每次打扰可展开看到**各维度得分与判定依据** —— 承 §4.5「没有可解释性的东西既不敢信任也无法纠错」。

#### 4.7.8 手动可调

全部参数(阈值 · 配额 · 各维权重 · 日报时间 · 各 `claim_class` 的默认级别)在设置里可手动调整。
**但配置文件位置受 CFG-1 约束** —— 见 §6.7.4。

### 4.8 多模态写入通道

随口一句「记一下,下周要交房租」应直接进入 L2/L3。这要求语音层与记忆层打通,也是本版把语音提前并设为常驻的主要理由。

**低档下语音走 CPU**(§8.1.3)。低档语音的定位是**异步的记忆随手写入**,不是对话 ——「记一下,下周三交房租」是 3 秒音频,CPU ASR 实时率 0.3–0.6 意味着 1–2 秒转写,对写记忆完全够用。**文档必须写清这个定位,不要让人以为低档能用语音对话。**

### 4.9 冷启动、评测与兜底

#### 4.9.1 冷启动

P3a 提供一次**结构化初始化会话**:助理按实体类型逐项发问(重要的人及称谓 · 常用设备 · 进行中的项目 · 明确的偏好与禁忌),你口述,它写入 L3 并当场展示、允许你改。一次约 20–30 分钟。

**★ 顺带完成敏感度定级**(§4.11.4 的 S2 标记)。§4.9.1 的初始化会话只跑一次,**错过就没有第二次**。

#### 4.9.2 评测集与四项指标

| 指标 | 含义 |
|---|---|
| 召回率 | 该记得的记住了 |
| 精确率 | 检索出来的确实相关 |
| **误记率** | 记住了错的事实 —— **最危险** |
| **溯源完整率** | 每条记忆都能展开到原始来源 |

**自动记忆(Vigil 派生)单列一组指标**,其误记率风险显著更高。

#### 4.9.3 漏记与误记的兜底

- **漏记**:你说「你怎么不记得 X」时,助理须能**即时补录**并标注「事后补录 + 补录时间」
- **误记**:每周推送一条「本周新记住的事」摘要(仅标题级),扫一眼即可发现离谱条目

### 4.10 规模增长

L2 只增不删(进 GC 白名单)。数据模型带 `last_accessed` 与 `access_count`;检索时对久未命中且低置信度的旧条目**降权**(不删除);超过 N 年的 L2 事件**归档为 L1 级摘要**,原文保留但不进主索引。

### 4.11 ★ 多设备记忆(v2.2 新增)

#### 4.11.1 拓扑:单一权威 + API 访问

记忆库**只有一份**,在工作站的 BitLocker 加密卷里。其他 PC 与手机通过 MEMORY 平面读写。

**不做分布式副本。** 理由:单人使用真并发极少;§4.5 的「不覆盖,新增并标 superseded」在单权威下是几行代码,分布式下是研究课题;多份加密副本 = 密钥管理复杂度爆炸(而「避免密钥管理复杂度爆炸」正是选这个拓扑的理由之一)。

**已接受的后果**(用户 2026-07-26 明确接受):

> **工作站关机 = 所有设备都没有记忆 + 所有机器 AI 失效无法调用。**

本文档**不偷偷改写为「工作站必须常开」**。但失效必须是**可诊断、可预期**的 —— 见 §4.11.6。

#### 4.11.2 写入路径

所有写入都经工作站的 Memory Gate。**客户端无本地队列** —— 无网即明确失败。

> **为什么不做 Outbox**:iOS 的 WebCrypto 不用 Secure Enclave,`extractable:false` 只挡 JS,**密钥材料与密文同在一个 IndexedDB 里**;而 IndexedDB 在 iOS 备份范围内,默认非端到端加密的 iCloud 备份是「你无法单方面终止访问的系统」。按 §4.11.5 的判据,**加密后的 Outbox 仍构成出境**。

**推翻条件**:`mobile-remote` 写入送达率连续 4 周 < 99% → 进 P3.5 按受控规格实现(纯素材 · 非记忆 · 72 小时 · 恢复后逐条确认)。

#### 4.11.3 `write_seq` 与冲突

- `write_seq` **全局单调**,由工作站 PostgreSQL 的 advisory lock 唯一分配。**客户端不参与分配。**
- **时间戳以服务端为准**(客户端时钟不可信)
- 冲突沿用 §4.5:不覆盖,新增并标 superseded
- **自动事实不得 supersede 用户事实**(§4.5 铁律),多设备下「用户事实」的认定见 §4.4.2

`source_ref` 扩展为携带 `origin_device_id` 与设备显示名。**记忆面板必须显示「这条是在哪台设备上记的」** —— 否则 §4.5 的可解释性在多设备下就残缺了。

#### 4.11.4 敏感度分域(两级,不是三级)

| | P3b 实装 | P3.5 启用 |
|---|---|---|
| **S2 机密** | **结构性不可见**,任何远程档位永久不可读,**无提级路径** | 不变 |
| **S0 / S1** | **不区分**。远程档位可读全部非 S2 内容 | 用一个月真实读取日志定边界后启用三级分域 |
| 约束手段 | 读取预算(首月只观察不硬停)+ 逐条全量审计 + **溯源展开需生物识别** | 增加域过滤 |

**为什么 S2 可以第一天就强制而 S0/S1 不行**:S2 的定级是**确定性的**(IBAN / 税号 / 证件号 / 地址模式 / 「密码是」/「恢复密钥」的正则族 + 用户手动标记),不需要 LLM 判断也不需要真实数据校准;量很小,不会造成「手机很傻」;而它恰恰是丢手机场景下伤害最大的部分。S0/S1 的边界**必须靠真实数据**,在没有它之前 fail-closed 会把手机压到不可用。

**结构性隔离,不是运行时过滤:**

```
PostgreSQL:  role ai_mem_local  → 基表全表
             role ai_mem_remote → 只 GRANT SELECT ON v_memory_nons2
Qdrant:      collection mem_main  ← 远程会话唯一持有的句柄
             collection mem_s2    ← local 独有,独立 loopback 端口
```

> 漏了 payload filter 是**沉默的**(返回多余结果,没人报错);漏了 collection 句柄是**响亮的**(直接异常)。§12.3 门禁第三条要的正是后者。

**「我妹妹叫什么」这条 P3 验收例句,必须在手机上也通过。** 否则这条验收是自欺。

#### 4.11.5 ★ 「出境」的精确定义

> **审查 S11**:五份设计给了「境」五个定义。

| # | 判据 | 结论 |
|---|---|---|
| **D1** | 内容离开**你控制的设备集合** | **出境**。禁止 |
| **D2** | 内容进入**你无法单方面终止访问的系统** | **出境**。禁止(涵盖 iCloud 备份、第三方云) |
| **D3** | 内容投递到**你已注册、可吊销、可审计的设备**,且**不落盘** | **不是出境** |

**D3 的三个条件必须同时满足。** 原设计的「已下发内容随之失效」是一个**已知不成立的前提**(下发出去的东西收不回来),用假前提证明「投递不是出境」是边界论证的典型失效形态。改为「**不落盘**」—— 这是可兑现的。

**明文例外条款**:

1. **iOS 应用切换器快照**属于系统行为,PWA 无法阻止。**明文接受为已知风险**,不在「禁止」与「接受」之间摇摆
2. **手动复制粘贴**无法阻止(§4.6.2)
3. **Tailscale 控制平面可见连接元数据**(不含内容),记入 §5.6 的第三方清单

#### 4.11.6 故障分类(§12.3 失败可见)

五种在客户端都表现为「用不了」,但原因与应对完全不同,**必须区分**:

| 故障 | 客户端表现 |
|---|---|
| 工作站关机 / 休眠 | 「工作站未响应 · 上次成功连接 3 小时前」 |
| 服务未起 | 「工作站在线,但记忆服务未启动」 |
| **记忆卷未挂载** | 「记忆库已上锁」+ 解锁指引 |
| 网络断 | 「网络不可达」+ 区分局域网/tailnet/互联网 |
| 工作站在完全 Off 档 | 「AI 已完全关闭」 |

> **诚实限制**:iOS 的 Tailscale 走 NetworkExtension,PWA 的 JS 拿不到 peer 状态。
> **明确合并为一态**:「无法连接 · 上次成功连接 {时间}」。§12.3 要求的是「不要伪装没事」,不是「必须诊断出根因」。

#### 4.11.7 Wake-on-LAN

**不做。** 理由:它把「工作站关机 = 全失效」这条已被接受的约束偷偷改写成「工作站必须能被远程唤醒」,而唤醒路径本身是一个新的、无认证的攻击面。若实际使用中确实频繁受阻,进 P3.5 单独评估。

## 6. ★ 安全与权限

### 6.1 核心原则

> **能力升级可以上云,权限升级永远不行。**

```
计划层  ← 可升级到云端,输出【结构化提案】
   ↓
策略层  ← 永远本地:权限校验 · 参数校验 · 额度 · 动作预览
   ↓
执行层  ← 永远本地:stdio 执行器
```

**★ 「本地」的精确定义**(v2.2 澄清):

> **策略层与执行层必须与被操控的资源同机。**

「永远本地」指的是**相对被操控资源**,不是「每台机器都有一份完整权威」。这与 §4.11 的「记忆单一权威」不矛盾:第二台 PC 对自身的操控需要本机策略层,但它的**记忆**仍走工作站。

### 6.2 权限强制:六元组

服务端按 **(用户 / 设备 / Agent / 工具 / 参数 / 额度)** 强制。

**参数级尤其关键**:同一个「写文件」工具,**路径参数决定它是安全还是灾难**。六元组里如果只实现了前四维,等于没有实现。

权限在**服务端按档位挂载工具池**,而非运行时判断。低权限档位的会话在建立时其工具池里就**不存在**高风险工具。

### 6.3 权限档位

| 档位 | 设备 | 问答/语音 | 资产 | **记忆读** | **记忆写** | 文件操作 | 电脑操控 |
|---|---|---|---|---|---|---|---|
| `trusted-local` | 本机 App | ✅ | ✅ | **全部** | ✅ 含 L4 | 逐次确认 | 逐次确认(**本机**) |
| `trusted-lan` | 局域网 PC | ✅ | ✅ | **非 S2** | ✅ 不含 L4 | 逐次确认 | 逐次确认(**仅自身**) |
| `mobile-remote` | 手机 | ✅ | ✅ | **非 S2** | ✅ 不含 L4 · 无队列 | ❌ | ❌ |
| **`resident-observer`** | Vigil | — | ❌ | **仅 `mem.exists` + 投影** | **仅 `vigil_observations`** | **只读白名单** | ❌ |

#### 6.3.1 ★ 电脑操控是二维的(v2.2 修正)

v2.1 的「电脑操控」一列把两个维度压成了一维。实际是:

| 发起 ＼ 操控 | 工作站 | 局域网 PC | 手机 |
|---|---|---|---|
| **本机 App** | 逐次确认 | ❌ | — |
| **局域网 PC** | ❌ | **逐次确认** | — |
| **手机** | ❌ | ❌ | ❌ |

**对角线 = 本机操控本机;非对角线 = 跨机操控 = 默认禁止。**

跨机必须禁的理由:§6.5 的安全边界(浏览器 profile 禁止清单、文件隐藏清单)都是**按机器**定的;远程发起时你看不到那台机器的屏幕,无法核对动作预览;允许跨机会让「丢一台设备」升级成「丢所有设备」。

**★ 操控目标必须是工具身份的一部分,不能是参数。** `execute@workstation` 与 `execute@lan-pc-2` 是**两个不同的工具**。局域网 PC 的会话工具池里只挂 `execute@self`,**根本不存在** `execute@workstation`。若做成参数,它就能被不可信的计划者操纵。

#### 6.3.2 ★ 设备身份:统一 WebAuthn(v2.2 新增)

> **审查 S12**:原设计写「手机设备密钥存 iOS Keychain(`kSecAccessControlBiometryCurrentSet`)」—— **这是原生 Security.framework 常量,PWA 调不了**。而 B1 已定不做原生 App,所以这条约束永远不会被满足;实际得到的是一个 32 字节长期 bearer 秘密躺在 IndexedDB 里,而文档上写着「生物识别保护」。

- **设备身份 = WebAuthn 平台认证器**,PC 与手机共用同一套实现(Windows 侧走 Windows Hello,私钥由 TPM 保护)
- 服务端**只存公钥与 `credentialId`**,不存任何秘密的哈希
- **不使用长期 bearer 令牌**;短寿命令牌 + `tailscale_node_id` 交叉绑定 + 双层吊销
- **配对码**:8 位 Crockford base32 · **工作站显示 / 新设备输入** · 5 分钟一次性 · 同会话失败 5 次作废 · 全局每分钟 10 次

> **方向比强度更重要**:反方向(新设备显示、工作站输入)下工作站屏幕上只有几个数字;正方向下 admin 面板可以先让你选定设备名与档位,**再完整显示你正在授予什么**。

> **`tailscale_node_id` 绑定的强度必须如实描述**:它防「密钥离机」,**不防「整机沦陷」**。文档不得用它来抵消凭据保护的弱点。

**★ RP ID 必须在 P2 之前定死。** WebAuthn 的 RP ID 一经确定不可更改 —— 若 P2 用 `localhost`,P3b 切到 `ai-box.<tailnet>.ts.net` 时工作站本机的 credential **全部作废**。因此把「定死 tailnet 名与机器名」这个 **0.2 天的命名决定**提到 P2 之前。

### 6.6 威胁模型

- **模型是不可信计划者**:网页、邮件、文档、参考图元数据、**授权区域里的文件**均可能携带提示词注入 → **计划本身要被审查**
- **资产导演 Agent 独立身份**:与日常助手共用模型别名但不共用工具池与记忆域
- **Vigil 是持续摄入不可信内容的主体**:它读的文件可能被投毒 → 见 §17.7 的隔离设计
- **记忆库是最高价值目标**:任何能读记忆的路径都是攻击面

### 6.7 ★ 权限区域(v2.2 新增,取代 §6.5 的隐藏清单)

> **本节起因**:用户明确要求「设立一个板块专门告诉 AI 哪些地方是有权限的」。

#### 6.7.1 三条基本裁决

1. **默认拒绝。** 未在白名单内的路径一律不可读。与 §6.2「按会话挂载工具池」同构。
2. **区域是分主体的。** `vigil` / `assistant.main` / `asset_director` 各有各的区域集合,不共享。
3. **黑名单优先于白名单。** 命中硬禁止清单即拒绝,不论白名单怎么写。

#### 6.7.2 数据模型

```toml
[[zone]]
id       = "proj_localai_docs"
subject  = "assistant.main"        # vigil | assistant.main | asset_director
path     = "{code}/00-docs"        # 用 paths.toml 的根变量,不写绝对路径
mode     = "ro"                    # list | ro | rw
recursive = true
purpose  = "项目文档与决策日志"
exclude  = ["**/snapshots/**", "**/worklog/**"]
```

`mode` 三级:`list`(只能看到文件名/大小/时间)· `ro`(可读内容)· `rw`(可写)。

**隔离区继承来源区域的 mode。** 从 `list` 区域移入隔离区的文件,`fs.read_head` 必须拒绝并给出 `origin_mode=list` 的理由 —— 否则隔离区会变成把 list-only 目录的正文搬进可读位置的通道。

#### 6.7.3 Vigil 的区域(最严)

| 路径 | mode | 说明 |
|---|---|---|
| `{code}/00-docs` | **元数据级** | **不给内容**。项目状态经编排器生成的结构化只读投影获取(见 §17.6) |
| `{assets}/draft` | `ro` | 自己产出的草稿 |
| 用户显式添加的工作目录 | `ro` | 默认带编译产物排除模式 |

**Vigil 永久黑名单**:`{code}/**` 的全部内容级读取 · `00-docs/snapshots/**` · `00-docs/worklog/**` · `.git/` · `.githooks/` · `config/` · `{state}/**`

> **为什么 `worklog` 与 `snapshots` 必须黑名单**:前者按定义装工具输出(第三方报错原文),后者按定义装第三方条款原文。**它们是注入载荷最自然的落点**,而 Vigil 会把「项目自身文档」当作高可信来源。

#### 6.7.4 硬禁止清单(`zones.local.toml`,不进 git)

```
%LOCALAPPDATA%\Google\Chrome\User Data\**
%LOCALAPPDATA%\Microsoft\Edge\User Data\**
%APPDATA%\Mozilla\Firefox\**
%USERPROFILE%\.ssh\**
%APPDATA%\Bitwarden\**   %LOCALAPPDATA%\1Password\**   %APPDATA%\KeePass\**
%APPDATA%\Thunderbird\**   %LOCALAPPDATA%\Microsoft\Outlook\**
%USERPROFILE%\.aws\**   %USERPROFILE%\.config\**
**/.env   **/*.key   **/*.pem   **/*.pfx   **/credentials*   **/secrets*
{state}\**                      ← 记忆库、票据、日志
<备份目标盘>\**                  ← §8.5 铁律 4
BitLocker 恢复密钥的任何存放位置
```

> **本清单只写路径模式,不探测本机是否安装了这些软件。** 写一条 `%APPDATA%\Bitwarden\**` 的禁止规则不需要知道 Bitwarden 装没装,而**探测本身就是凭证侦察的行为模式**。

#### 6.7.5 强制点与诚实说明

**强制在工具层**:`fs.read_head` / `fs.stat` 等工具自身校验区域,不信任调用方传入的路径。

> **诚实限制**:在 P6 建立专用 Windows 账户之前,**OS ACL 层是零防护**。工具层就是全部的边界。因此它必须按安全关键代码对待,**否定用例先于功能写**(§10)。

#### 6.7.6 配置文件的保护(CFG-1)

`zones.toml` / `zones.local.toml` / `vram-tiers.toml` / `interrupt-policy.toml` 全部:

- **不在任何 Agent 的可写区域内**(`self_protect` 通配 `config/*.toml`)
- 挂载时校验 `sha256`,不匹配则 `refuse_mount`
- 安全不变式(如出境级别、`counts_as_active_task`)移入 `{state}/policy/`,config 里只留只读镜像用于展示

**否定用例**:以 `assistant.main` 身份写 `config/*.toml` 必须被拒。

#### 6.7.7 变更流程

| 动作 | 审批级(§12.4) |
|---|---|
| 新增 `list` 区域 | 逐次确认 |
| 新增 `ro` 区域 | 逐次确认 + 展示该目录的文件计数与总大小 |
| 新增 `rw` 区域 | **哈希绑定批准** |
| 修改硬禁止清单 | **哈希绑定批准** |

**一键临时区域**:被拒绝时可一键授予「本次会话内只读」,会话结束自动失效。拒绝日志驱动扩权 —— 每周日报汇总「本周被拒最多的 3 个路径」。

> **诚实**:默认拒绝的头两周确实难用。这是白名单模型的固有代价。

### 6.8 ★ 账户隔离(v2.2 新增,从 P3 提前到 P2)

> **审查 S3**:ComfyUI 的第三方节点与记忆服务同一个 Windows 用户,是一条**绕过网关、六元组、预算、审计**的读全库路径。

| 账户 | 跑什么 |
|---|---|
| `ai-mem`(专用低权限服务账户) | PostgreSQL · Qdrant · embedding/rerank · memory-service |
| `ai-asset` | ComfyUI · 浏览器执行器 · 游戏自动化 |

- 挂载点目录与 VHDX 文件的 **NTFS ACL 拒绝资产侧账户**
- PostgreSQL 按 SSPI/SID 限制连接源;Qdrant 前置只认本地 token 的代理
- **任何其他本机连接尝试写审计并触发 §9.3 告警**(目前这类尝试完全静默)

> **因此 §4.6 的表述必须改**:运行态记忆库的保护 = **OS 账户隔离 + 网关认证**;BitLocker **只覆盖关机态**。不再有第三层可以拿来说嘴。

## 8. 显存、上下文与存储

### 8.1 ★ 五档显存开关(整节替换 v2.1 的三模式)

#### 8.1.1 口径(先定死,否则每个数字都会被误读)

| 术语 | 定义 |
|---|---|
| **档位 cap** | 用户设定的 **AI 进程组 GPU 分配上限**。不含桌面、不含第三方程序 |
| **静态闸** | `本次申请(peak) + AI 侧当前已用(peak) ≤ cap` |
| **动态闸** | `NVML 实测 free − 本次申请(peak) ≥ SAFETY_MARGIN(0.8 GiB)` |
| **余量核算** | ★**必须用 preset 的实际 peak 之和,不能用 cap**。cap 是上限不是占用 |

**所有预算表一律用 `peak`。Broker 按 peak 发租约。**

#### 8.1.6 切换与中断

**硬规则:一律先卸后装。** 卸载后**轮询 NVML 直到 free 回升到预期 ±0.2 GiB**(超时 10 s 报 `vram_not_reclaimed`)。

**`requires_swap` 必须有事务语义**:
1. 进入前做**整组预检**,不过直接拒绝、**不卸任何东西**
2. 卸载后若任一新组件加载失败 → 尝试回滚
3. 回滚失败 → `DEGRADED_SAFE`(等价 Off + 托盘红 + 不可忽略通知)

**降档时有任务在跑 → 弹提示让你选**「优雅中断」或「等它跑完」。先给 **5 秒排空窗口**。

`blocking_set = {USER_BLOCKING, USER_ASYNC, RESIDENT_TASKED}`。
**Vigil 的空闲观察循环不在集合内** —— 它跑 CPU、不持 GPU 租约,**天然不在,不需要特例代码**。

**ComfyUI 中断语义**:**不保存 latent,重跑不续跑**(ComfyUI 不支持跨进程恢复采样器状态)。
**批量 JOB 按产物单元**:已完成的 N 张正常入 draft 池;正在采样的第 N+1 张标 `partial=true, steps_done=18/30`;记录 `completed_units` / `next_unit`。弹窗给可验证的具体数字:

```
已完成的 12 张会保留;正在出的第 13 张作废(已算 18/30 步,重跑约 9 秒);
剩余 8 张可在升档后从第 13 张继续。
```

**MODEL 平面截断的输出不进 Memory Gate**(半句话是误记源)。

**不用「记住我的选择」复选框** —— §12.4 铁律 3:批准的是具体计划,不是一类操作。替代:设置项 `downshift.default_action`(**冷静时定的,不是着急时点的**)。

#### 8.1.7 「不做自动触发」的精确边界

| 允许 | 禁止 |
|---|---|
| 自动**拒绝租约** | 自动改变**档位** |
| 自动**通知**「疑似过订,建议降档」 | 自动降档 |
| 自动驱逐 `WARM` / `MAINTENANCE` 类租约 | 中断 `blocking_set` 成员 |

**不变式 I1**:自动机制只能拒绝新租约,**永不撤销已授租约**;只有用户显式动作才能撤销。
**不变式 I2**:`READY` 状态下,实际驻留集合必须**严格等于**该档位定义的集合。

**「检测独占全屏游戏」这条特例删除**,替换为通用规则:`free_vram` 1 Hz 采样,5 s 内降幅 > 1.0 GiB → `admission_guard`;全屏进程名**仅用于生成告知文案,不产生策略动作**。理由:这台机器上比游戏更常见的显存大户是 UE5 与多标签 Chrome。

### 8.2 上下文预算

| 上下文 | KV(FP8,8B/4B 同) | 备注 |
|---|---|---|
| 8K | 0.56 GiB | 语音模式上限 |
| 16K | 1.13 GiB | 高档默认 |
| 32K | 2.25 GiB | 深度模式上限 |
| 128K | ~9 GiB | 本机不可行 |

**三条约束:**
1. **显存** — 见上
2. **Prefill 延迟** — 32K 冷启动首 token 约 4–10 秒,语音模式不可接受。**必须开 prompt cache / prefix 复用**
3. **有效上下文 < 标称上下文** — 长上下文中段检索准确率显著下降

**隐藏杀手:一张 2560×1440 截图在常见 VLM 中是 1500–4000 tokens。** 10 步 GUI 循环仅截图就 20–40K。

> 这是「电脑操控优先 UIA 树」的**第二个理由**(第一个是显存):同一窗口的 UIA 树通常只需 200–800 tokens,且更精确。

### 8.4 存储生命周期与 GC

| 根 | 可自动删 | 策略 |
|---|---|---|
| CODE | ❌ | git 管理 |
| **STATE** | ❌ | **只归档不删。记忆库与交易账本进白名单 + 独立备份链** |
| MODELS | 🟡 | **引用计数**,非 LRU;只提示不自动删 |
| ASSETS | ✅ | 三池分级 |
| CACHE | ✅ | 纯 LRU/TTL — **但 `cache/hf` 例外,见 §8.4.1** |

**产物三池**:`draft`(TTL 后回收,永久保留 Asset Spec + seed)· `adopted`(永久 + 备份)· `exported`(只留元数据引用)

> **可复现性把「存储」变成了「缓存」。** 删掉一张 2MB 草稿只损失几 KB 记录。

**水位线**:75% 提示 · 85% 清 CACHE · 92% 回收超期 draft · 95% 拒发新 JOB 租约。

**回收器要求比人工整理更严**(它无人按确认键):永不 `delete` 只移隔离区 · 每次产出清单与释放报告 · 除 CACHE 外先报告后执行 · **备份目录对回收器不可见**。

**第一个月只观察不清理。**

#### 8.4.1 `cache/hf` 例外

`cache/hf` 语义上属 CACHE 根,但**不参与自动清理**。

| | 一般缓存 | `cache/hf` |
|---|---|---|
| 体积 | 几 GB | 十几到几十 GB |
| 重建耗时 | 秒到分钟 | **实测 ~11 MB/s,17GB 约 27 分钟** |
| 能否重建 | 一定能 | **不一定** —— 模型可能下架或改许可 |

> **分界不该只看「能不能重建」,还要看「重建的代价」。** 一个能重建但要花半小时且可能失败的东西,不该被静默删除。

### 8.5 ★ 备份与灾难恢复(v2.2 改为自动)

#### 8.5.1 为什么只有记忆非备不可

| 数据 | 丢失后果 |
|---|---|
| CODE | git 有 |
| MODELS | 可重新下载 |
| ASSETS · draft/exported | Asset Spec 可重放 |
| CACHE | 可随时清空 |
| **STATE · 记忆库** | **不可重建。没有任何来源可以重放。** |

#### 8.5.2 双轨备份

| 轨 | 目标 | 频率 | 加密 | 保留 |
|---|---|---|---|---|
| **A. 自动增量** | **C:**(Disk 0,与 state 所在的 Disk 1 跨物理盘) | **每日 04:00** | **公钥(age/X25519)** | 14 天 |
| **B. 手动全量** | 移动固态 G:(Disk 2) | 你插盘时 | BitLocker To Go | 12 代 |

> **★ 为什么轨 A 必须用公钥加密**:一个 04:00 无人值守的任务必须能自己取到密钥。
> **任何本地可读的对称密钥都能被同用户的进程取到** —— 那么「工作站被入侵时备份仍然安全」这句话就是假的。
> 公钥加密下工作站只放公钥,解密私钥离线保管。**这是唯一能让那句话为真的方案。**

**送达度接 beacon**:每台设备(含手机)每次连上时读一个只读状态端点,过期即提示「你已经 N 天没有新备份」。**这直接消解了原方案「手动备份取决于你是否记得」的推翻条件。**

轨 A 的规模估算:每日 20–200 MB(压缩后,待实测),14 天 = 0.3–2.8 GB,C: 有 392 GB。

#### 8.5.3 备份矩阵

| 根 | 内容 | 说明 |
|---|---|---|
| CODE | `git bundle --all` | 单文件,含全部历史,自带校验 |
| **STATE** | 全量,**排除 `quarantine`** | 隔离区装的是打算删除的东西,不该在 12 个备份代里继续存活 |
| MODELS | **只备清单**(路径 + 大小 + sha256 + 来源 + 许可证) | 权重可重下 |
| ASSETS · adopted | 全量 | |
| ASSETS · draft/exported · CACHE | 不备份 | |

#### 8.5.4 六条铁律

1. **备份必须加密。** `backup.ps1` 对未加密目标**拒绝执行**(唯一逃生口 `-IAcceptUnencryptedTarget`,会写审计与报告)
2. **恢复密钥离线保管**,至少两份,不同物理位置,**绝不与被加密数据同盘**
3. **恢复演练** —— **没演练过的备份不算备份**。P3a 上线前跑通一次完整恢复,此后每季度一次
4. **备份不可由助理自身的文件工具触及**(进 §6.7.4 硬禁止清单)
5. **备份失败必须告警**(进 §4.7.6 确定性 L4 白名单)
6. **校验清单必须可移植**:无 BOM · LF · 正斜杠 · GNU `sha256sum` 兼容格式。灾难恢复的典型场景就是 Windows 起不来 —— 清单只能被 PowerShell 读,等于把恢复路径限死在「Windows 还能启动」这个前提上

## 10. 测试策略

| 组件 | 风险 | 最低要求 |
|---|---|---|
| **文件回收器 / GC** | **最高** — 无人按确认键的自动文件整理器 | 单元测试 + **干跑模式** + 隔离区可恢复性测试 |
| **权限区域** | **最高** | **N1–N14 否定用例先于功能写**;区域外读取必须拒绝 |
| **出境闸门** | 最高 | 断言覆盖 **str 拼接 / f-string / 模板渲染 / 日志格式化** 四种取值方式 |
| **权限策略引擎** | 高 | 以**否定用例**为主;六元组每维都要有拒绝用例 |
| **打扰评分** | 高 | 注入用例:构造带恶意 deadline 的文件,断言最高只能到 L1 |
| **记忆系统** | 高 | eval 集;冲突/superseded 回归;**自动事实不得 supersede 用户事实** |
| **多设备** | 高 | 远程角色读 S2 必须异常;Off 档出境载荷不含 memory_id 对应文本 |
| GPU Broker | 中 | 并发申请/驱逐/档位切换事务性 |

**原则:凡是「自动执行且难以撤销」的组件,先写否定用例再写功能。**

**★ 对抗配置下重测**:出境哨兵串用例必须在**所有能翻转的开关都翻转**的配置下再跑一遍。只测默认配置等于没测。

## 12. 执行协议

### 12.1 记录协议

| 文件 | 回答 | 更新时机 |
|---|---|---|
| `STATE.md` | **现在在哪** | 每个节点结束;中断前 |
| `DECISIONS.md` | **为什么这么定** | 每次不易反悔的选择 |
| `worklog/YYYY-MM.md` | **做了什么、测出什么** | 每次实作或实测 |

`DECISIONS.md` 条目格式:背景 / 选项 / 决定 / 理由 / 代价与已知风险 / **推翻条件**。

> **「推翻条件」是本格式里最重要的字段。** 半年后你需要知道的不是「当时决定了什么」,而是「这个决定现在还成不成立」。
> **★ 不得把新决定伪装成旧决定的延续** —— 那恰好绕过了这个字段。

### 12.2 节点循环

```
1. 读 STATE.md → 2. 做一件事 → 3. 写 worklog → 4. 若有不易反悔的选择则写 DECISIONS
→ 5. 更新 STATE.md → 6. 若跨阶段则对照验收标准逐条确认
```

> **不更新 `STATE.md` 就不算做完。**

### 12.3 首轮门禁

| 门禁 | 说明 |
|---|---|
| **路径合规** | 配置全部来自 `paths.toml` |
| **显存申报** | 声明峰值;P4 后走 Broker 租约 |
| **失败可见** | **不静默降级** |
| **可回退** | 知道怎么关、怎么恢复 |
| **数据边界** | 能读什么、能写什么;出境须过闸门 |

### 12.4 审批规则

| 级别 | 适用 | 机制 |
|---|---|---|
| **自动** | 只读、可重放、无外部后果 | 事后可查 |
| **逐次确认** | 写文件、点击提交类控件、单次出境 | 执行前展示**精确动作预览** |
| **哈希绑定批准** | 批量文件操作 · GC 回收 · **L4 写入** · 交易提案 · 新增 rw 区域 | 计划哈希绑定 → 批准 → **执行前复核哈希** → 执行 → 回执 |

**三条铁律:** 永不 `delete` 只移隔离区 · 除 CACHE 外先报告后执行 · **批准的是具体计划,不是一类操作**。

## 17. ★ 常驻清醒助手 Vigil

### 17.1 它是什么

| 维度 | 定义 |
|---|---|
| Agent id | `vigil` |
| 能力别名 | `assistant.resident`(唯一) |
| 权限档位 | `resident-observer`(最低) |
| 运行时 | **CPU 独立进程**,llama.cpp,IDLE 优先级 |
| 模型 | Qwen3-1.7B Q4_K_M(备选 Qwen2.5-1.5B)· **不得选 4B 级** |
| 上下文 | **2048,硬上限**;前缀缓存是硬性要求 |
| **GPU 占用** | **0 MiB。硬断言** |
| 内存 RSS | ≈ 1.87 GB(估算待实测) |
| 工具池 | **只读三件套**:`fs.stat` / `fs.read_head`(≤4 KB,白名单内)/ `embed.query`。**无写、无删、无网、无进程、无剪贴板** |
| 记忆读 | **只有** `mem.exists`(布尔)与 `vigil_context` 投影(用户逐条勾选,≤50 条) |
| 记忆写 | **只能 INSERT 到 `vigil_observations`**。不能写 L0–L4 任何一层 |
| 出境 | **L0,永久。配置层不接受其他取值,代码里不存在通往云的路径** |
| 会话 | 单次脉冲 = 单个会话,结束即销毁 |

### 17.2 它不是什么

- **不是屏幕监控。** 它**读文件,不看屏幕**。任何未来版本引入屏幕采集必须另开一章、另走审批
- **不是记忆写入者。** `vigil_observations` 不在 L0–L4 之内。进入 L2/L3 必经:你点开交接单 → 主助手接手 → **主助手重读证据** → Memory Gate → 写入并记来源
- **不是打分者。** 模型只填受约束的槽,总分由它读不到的确定性公式合成
- **不占显存。** 五档预算表里它是恒为 **0.0** 的一行
- **不持 GPU 租约**,因此天然不在「运行中任务」集合内 —— **不需要任何特例代码**

### 17.3 「清醒」的可验收定义

| 层 | 是什么 | 恒真? |
|---|---|---|
| W0 进程存活 | 托盘进程、事件循环、DB 连接 | ✅(除完全 Off) |
| W1 事件捕获 | 文件变化进持久队列,一条不漏 | ✅(除完全 Off) |
| W2 模型驻留 | 权重已加载 | 🟡 按开关态 |
| W3 持续算力 | 真的在跑推理 | ❌ 只有脉冲 |

> **清醒 = W0 + W1 恒真。清醒的本质是「不漏事」,不是「一直在想事」。**
> **文档必须写「除完全 Off 外,无时无刻清醒」** —— 不留一句字面上不成立的承诺。

| # | 判据 | 阈值 |
|---|---|---|
| A-1 | 原始事件落进持久队列 | **< 1 s** |
| A-1b | change-set 成型(15 s 去抖 + 60 s 合并) | **≤ 90 s** |
| A-2 | 关机/休眠期间的变更,开机后由 T0 补扫产出 | **≤ 120 s** |
| A-3 | 状态可查(今日脉冲/CPU 用时/待处理/上次补扫) | 恒可查 |
| A-4 | watcher 缓冲溢出必须告警 + 立即补扫,**不静默丢事件** | 恒成立 |

### 17.4 四层漏斗

> **功耗低不是因为模型小,是因为绝大多数事件根本不进模型。**

```
文件系统事件
 ↓ 层0 授权闸(0 token):白名单∩¬黑名单 → 扩展名/大小/深度 → 去抖15s → 合并60s   过滤 ~70%
 ↓ 层1 特征提取(0 token):{root,rel} · size · mtime · sha256 · 首4KB · 结构化diff  过滤 ~20%
 ↓ 层2 语义预筛(CPU embedding,0 LLM token):bge-m3 复用,余弦 < 0.35 丢弃         过滤 ~7%
 ↓ 层3 LLM 脉冲(CPU 1.7B):受约束槽,≤160 token,GBNF 强制 JSON                  ≈3%
 ↓ 层4 打扰评分(§4.7,纯代码)+ 交接单
```

**必须自带的编译产物排除模式**(否则任何真实工程目录一加进白名单就打爆配额):

```
**/Intermediate/**  **/Saved/**  **/DerivedDataCache/**  **/Binaries/**
**/node_modules/**  **/.venv/**  **/__pycache__/**  **/target/**  **/dist/**
```

### 17.5 节奏与配额

| 触发 | 周期 | 调 LLM |
|---|---|---|
| T0 补扫 | 启动 / watcher 溢出 / 休眠恢复 | ❌ |
| E 事件脉冲 | 去抖 15 s,合并 60 s | 🟡 仅过层 2 |
| T1 轻扫描 | 每 10 分钟,纯 stat | ❌ |
| T2 小时汇总 | 每 60 分钟,**队列为空直接跳过** | 🟡 |
| T3 日终 | 每日 22:00 | ✅ |
| T4 周终 | 每周日 22:10 | ✅ |

**日预算(估算,待 P1-E5 实测)**:≈29 次脉冲 · ≈45K token · ≈6 分钟 wall clock · ≈**2088 核心秒** · < 8 Wh · **0 MiB 显存**。

**配额**:`cpu_core_seconds_per_day = 5000`(**必须高于日均 2088**,否则正常使用日就会 halt,几天后你会把配额调到无穷大或直接关掉);`pulses_per_hour = 12`;配额告警按同一原因 24h 内只报一次折叠。

### 17.6 项目状态投影(而非读原文)

Vigil 对 `{code}/00-docs` **只有元数据级权限**。项目状态经编排器每日 03:00 生成的结构化只读投影获取:

```
project_state_projection
  phase          : "P1"
  next_steps[]   : ["P1 基准测试", ...]     ← 纯字符串,≤3 条
  blockers[]     : ["G: 未加密"]
  active_topics[]: [{id, name}]
  generated_at   : ISO8601
```

**原始 markdown 永不进 Vigil 的 prompt。** 这同时消解**自指循环**(它读不到 DECISIONS.md 的「推翻条件」原文,那种句子可能被当作可执行指令)与**注入**(投影是纯字段,无自由文本)。

### 17.7 交接单(唯一输出形式)

Vigil 不直接对你说话,它产出**交接单**:

1. **交接会话不继承你当前的档位权限。** 强制挂载只读工具池(`fs.read` / `mem.search`),无写、无执行、无网。写权限需要你**看过证据之后**发起**第二次、独立的**动作
2. **`evidence` 原文默认只渲染到 UI,不进模型上下文。** 主助手确需读原文时,走一个**禁用全部工具调用**的只读子会话做结构化提取
3. **UI 上证据在上、Vigil 的说法在下**,并标注「不可信来源的转述」

### 17.8 独立开关

| 态 | W0 | W1 | W2 | 说明 |
|---|---|---|---|---|
| `on` | ✅ | ✅ | ✅ | 完整 |
| `observe_only` | ✅ | ✅ | ❌ | 只记事件,不跑 LLM,不产交接单 |
