### [问题] 一个会让猫永远走不完第一步的 bug

`Pump` 会在过渡的**最后一 tick** 用**旧状态**重新寻路 —— 因为状态要等 clip 播完才改
(`CompleteClip` 里),而 `CanExitNow` 在最后一 tick 就已为真。结果是同一段过渡被无限重启。

**15 条断言当时全挂在这一个根因上。** 修法是在 `Pump` 开头加一道闸:
过渡在飞行中(`_activeEdge is not null`)就不再解算。

> 形状是「两个判据用了不同的时间点」:一个看"clip 播完没",一个看"能不能离开"。
> 单独看都对,合起来差一个 tick,而那一 tick 恰好是重入窗口。

`CodexSandboxOffline` / `CodexSandboxOnline`,**Enabled、在 `Users` 组、不在 `LOCAL_DENY_ACCOUNTS` 里**。

★ **降档不断连**:它仍能用 chat(等价于直连 `llama-server`,不构成回归),失去的只是

### [实测] 回头补二 · `pg_ident.conf` 零看守,而它是记忆库唯一那道不依赖 NTFS 的强闸

先证明这道闸是真的 —— 以**提权的机主账户**连 PG:

```
psql -h 127.0.0.1 -U mem_rw   -d memory  →  FATAL: SSPI authentication failed
psql -h 127.0.0.1 -U postgres -d memory  →  FATAL: SSPI authentication failed
```

`pg_hba` 四行全 `sspi map=mem`;`pg_ident` 四行 SYSTEM-USERNAME **全部 `ai-mem`**。
SSPI 认连接进程的 Windows SID,**没有可窃取的秘密** —— 比 Qdrant 的 bearer key 强
(后者 `api_key` 明文在 `config.yaml`,靠 NTFS ACL 护着,**是 NTFS 防线的派生物**)。
⇒ **两者不等强,文档不得并列成一条。**

**缺陷**:`verify-isolation.ps1` 一个字不读 `pg_ident`(唯一提及是 ④ 段注释);
`install-postgres.ps1` 的重跑守卫只查 `pg_hba`、else 分支却**同时覆写两个文件**。
⇒ 往 `pg_ident.conf` 追加一行 `mem <任意账户> mem_rw`,记忆库对它全开,
**全套断言没有一条会红**,还会被一个从不读它的守卫永久保住。

**修法**:`verify-isolation.ps1` 新增 ⑤ 段 —— **反向全表断言**:SYSTEM-USERNAME 列有且只有
`ai-mem`(不写「检查 ai-mem 在不在」:那条在有人**追加**一行时不会响,而追加正是事故的形状);
另加 `pg_hba` 无 `trust/md5/password` 兜底行、每条 `sspi` 都带 `map=`。
`install-postgres.ps1` 守卫改为同时看两个文件,只缺 `pg_ident` 时**抛错而非静默跳过**。

**顺带修掉一个既存死代码**:④ 段那句 `Skip-It '连不上 —— 需以 ai-mem 身份运行'` **一次都没跑过**。
第 25 行 `$ErrorActionPreference='Stop'` 把 psql 的 stderr 每一行包成 `NativeCommandError` ⇒
终止错误 ⇒ 脚本在那一行中止,**永远走不到下面的 `if`**,⑤⑥ 两段也不执行 —— 而退出码还是 0。
「写了个优雅降级分支,它一次都不会跑」正是 `DECISIONS.md`「假断言」整节的形状。
修完后脚本**第一次跑完**:**17 PASS · 0 FAIL · 3 SKIP**。

**红测**:对假 `pg_ident`/`pg_hba` 跑同源判据(**不碰真实配置**),四条全部命中 ——
追加 `ai-op` 映射 → 反向断言红;加 `trust` 行 → 弱认证红;去掉 `map=` → 缺 map 红。

**一条要降级的表述**:`pg_ident` 第一行把 `ai-mem` 映到 PG **超级用户 `postgres`**,
超级用户绕过一切权限检查 ⇒ `roles.sql` 的 `REVOKE UPDATE, DELETE` 只对 `ai_mem_local/remote` 成立。
**不得声称 `mem.audit_log` 的 append-only 是绝对的。** 该提示已写进 ⑤ 段输出。

### [问题] ★★ 同卷 Move 保留 DACL —— 「移进隔离区」不等于「被隔离」

**归档动作本身当场暴露了一条对 §6.5 有直接影响的事实。**

移完复核那个归档目录,发现它 `Protected=True`、DACL 里赫然还有
`Authenticated Users : Modify` —— **宽泛权限跟着数据一起搬进了加固过的隔离区**。

原因:**同卷 Move 是重命名**。NTFS 为了让对象在新位置保持相同的有效访问,
会把它原先【继承来的】ACE **转成显式**带过去,并置上 Protected 位。

> **「移进一个加固过的目录」不等于「变成加固过的」。**

⇒ 对 §6.5「隔离区 = delete 的替代品,永不 delete」的直接影响:
**P6 的执行器把一个人人可写的文件移进隔离区之后,它还是人人可写** ——
隔离区看着把东西关起来了,实际只是换了个位置。这正是本项目固定审查视角
说的「看着有防护、实际没有」,而且这一次是**机制本身**的性质,不是谁写漏了。

**修法**:入区时 `icacls <目标> /reset /T`(丢掉显式 DACL、改回从隔离区继承)。
本次已对 `20260803-openwebui` 执行,复核确认现在只剩
`Zori Ma(M)` · `Administrators(F)` · `SYSTEM(F)`,且全部 `IsInherited=True`。

**已立成断言(不只是文档)**:`verify-state-acl.ps1` 新增 ⑤ 段,逐个检查隔离区条目
`AreAccessRulesProtected -eq $false` 且三个宽泛主体无写权限。
现在 **35 PASS · 0 FAIL**(顺带也验过了 7 月那条既有条目 `2026-07-26_hf-cache-from-C`)。

**ACL 表是取证出来的,不是猜的**:逐文件读 Owner —— `logs` 37 个文件里 **34 × `ai-mem`**,
`identity` 4 个全是 Administrators,`db`/`tickets` 空。⇒ 只有 `logs` 需额外授 `ai-mem`。
**授漏了服务日志会静默消失,授多了等于没加固。**

## 2026-08-04 白天 · 出包门禁修真(`8bed788`)

> 接着昨晚记的那条「第二形状 error 32 没跑起来却判通过」往下挖,
> **发现记错了根因** —— 真正的病比「退出码分不出没启动和全绿」还靠下一层。

**[实测] 门禁从来没有在等自检跑完**

客户端是 **WinExe(GUI 子系统)**,而 PowerShell 的调用运算符 `& $exe` 对这类进程
**不等待**,当场返回。于是:

```powershell
& $exe --selftest
$code = $LASTEXITCODE     # ← 拿到的是【上一条命令】的残留值,恰好是 0
```

⇒ **门禁读的根本不是自检结果**,两种安装位置的检查双双形同虚设。
昨晚看到的 `error 32` 只是让这件事露了个头:那次是子进程真的没起来,
但即使它起来了、即使它红了,门禁**同样不会知道**。

> ★ 这条比昨晚记的那版严重:昨晚以为是「判据不够细」,实际是**判据读错了变量**。
> 记账要改口径:**不是门禁太宽,是门禁没接线。**

**[实作] 三处修法**

1. **真等它结束**:改 `Start-Process -Wait -PassThru`,读 `$proc.ExitCode`;
   stdout 重定向到文件 —— 新进程没有可 `AttachConsole` 的父控制台,不重定向就什么都留不下。
2. **判据从「没有失败的迹象」改成「跑过的证据」**:自检跑到最后一行才写哨兵
