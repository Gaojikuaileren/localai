## 0. 开工前 —— 拷哪个目录、两边应该是什么版本

> ## ★★★★ 这一节我写死过三次版本戳,三次都在出包后当天就过期了
>
> 初稿 `…0113+045b5b8` → 改 `…1314+0f9fa1c` → 改 `…1640+34235d7`,而盘上已经是第四个。
> 更坏的是第三次:我把 `dist\client-pack` 称作「上一轮的残留、没人再更新」,
> **而它恰恰是当天最新的客户端包**;被我指定去拷的 `dist\client` 才是旧的那一份。
> 支撑那句话的依据也是假的 —— 我写「V22 把出包默认目录改成了 `dist\client\`」,
> 而 `build-client.ps1` 的 **`$Out` 默认值一直是 `client-pack`**,V22 **只改了 `$AdminOut`**。
>
> ⇒ **本节从此不写死任何版本戳。** 交接文档开头那句「不要引用本文件里的任何数字」
> 对这份清单同样成立,而我在同一份文件上违反了它三次。

**开工前跑这一条,它会告诉你今天该拷哪个、两边各是什么版本:**

```bash
cd "E:\.meine\.Proj_Soft\.Proj\.localAI" && for d in client client-pack admin admin-pack; do printf "%-12s " "$d"; (sed -n 2p "dist/$d/VERSION.txt" 2>/dev/null || echo "(没有 VERSION.txt)"); done && echo "--- main 在:" && git log --oneline -1
```

**怎么读这个输出**:

1. **戳里那个短哈希就是它含到哪一次提交。** 拿去 `git log --oneline -1 <哈希>` 看它是哪一轮。
2. **主机用哪一对**:`dist\admin\` 与 `dist\client\` 是**落位目录**(客户端逐字探
   `<客户端 exe 目录>\..\admin\localai-admin.exe`,见 §0.1)。
   ★ 若 `client-pack` 的戳**比** `client` 新 ⇒ **落位目录是旧的**,先把 `client-pack\` 覆盖到 `client\` 再开工。
3. **副机拷哪个**:拷**戳最新的那份客户端包**(照上面第 2 步之后,就是 `dist\client\`)。
   副机**不要**拷 `host\` 与 `admin\`。
4. ★ **两个包的戳不要求相同** —— 只重出改动的那一个是对的做法。
   要核的是「**每个包各自含到哪一次提交**」,不是「两边一不一样」。
5. ★★ **`dist\client\VERSION.txt` 里那句关于「管理端 PASS=n」的数字不可信** ——
   那是出客户端包那一刻管理端的数。**管理端的数只看 `dist\admin\VERSION.txt`。**
   同理 `dist\admin\VERSION.txt` 里那句「版本戳与旁边的 client 是同一个」也**不成立**,别照它判。

> **看到别的说明什么**:两个包的戳都**落后于 `git log` 那一行** ⇒ 有车道并入后没重出包,
> **这一趟验的是旧代码**。停下来先出包,别接着往下测。

### 0.1 ★★ 管理端的位置由代码决定 —— 而这一格**已经不用手工做了**

> ★★★ **2026-08-09 更正两次:**
> 初稿要求「手工把 `admin-pack\localai-admin.exe` 摆到 `..\admin\`」—— 那是在**绕**一个缺陷;

> V22 把 **`$AdminOut`** 默认值改成了并排的 `admin\`(管理端确实落位了),
> **而 `$Out`(客户端)默认值一个字没动,至今仍是 `client-pack`**。
> ⇒ **管理端出包即落位,客户端不是** —— 无参跑一次 `build-client.ps1`,

> `<客户端 exe 目录>\..\admin\localai-admin.exe`(喂 `HostSetup.RoleEvidence.AdminAppPresent`)。

主机上今天应当已经是这个样子(**核对一眼即可,不需要动手**):

```
<repo>\dist\admin\localai-admin.exe      ← 出包自动落位
<repo>\dist\host\localai-lan-edge.exe    ← 已有
```

> **看到别的说明什么**:`dist\admin\` 里没有 `VERSION.txt` ⇒ 那是**上一轮的残留**,
> 不是这次出的包 —— 停下来重出,别接着往下测。
>
> ★★ 另有一处**已知过期文案**(不影响功能,但会误导人):
> `安装说明.txt` 里仍写着主机判据是 `..\host\localai-lan-edge.exe` ——
> 那是 V14 裁定②**之前**的写法。看到它别照做,以本节为准。

### 0.2 ★ 这一趟的两条临时纪律(V23 修完即可删)

1. **测试中途不要手工起 llama-server。** 管理端起栈时拍的"起栈前已有的后端"快照

## 1. 管理端:三页**真的点开有东西**

> ★ V21 出包自检验过它们"接上了",但那是**自检**。
> **人亲手点一遍才算** —— 自检验的是"这一页能构造出来",不是"这一页对人有用"。

### 1.1 双击 `admin\localai-admin.exe`

- **怎么做**:双击。**不要**右键「以管理员身份运行」。
- **应该看到**:窗口打开,左边四个页签:**主机中枢 · 模型 · 记忆库 · 客户端与栈**。
- **看到别的说明什么**:
  - 提示要管理员权限 / 打不开设备密钥 ⇒ 你用提权方式启动了。**TPM/CNG 用户密钥绑定铸造时的完整性等级**,提权是另一个身份(D108 裁定④);
  - 窗口一闪就没 ⇒ 看 `%LOCALAPPDATA%\LocalAI\admin\`,并把现象记下来 —— **不要反复双击**。

### 1.2 「模型」页

- **怎么做**:点「模型」。
- **应该看到**:**真的列出模型**(不是「这一页没有接上」,也不是空白)。
- **看到别的说明什么**:
  - 显示「这一页没有接上」⇒ 那是管理端自己的占位文案,说明这一页的接线没接;
  - 空列表但没有报错 ⇒ 可能中枢没起。**先去「客户端与栈」看栈在不在跑**,别在这一页上猜。

### 1.3 「已配对设备」(在「主机中枢」页里)

- **怎么做**:点「主机中枢」。
- **应该看到**:**列出已配对的设备**(至少有副机那一台,状态 active)。
- **看到别的说明什么**:一台都没有 ⇒ 要么中枢没起,要么这一页读的是空库 ——
  **看副机能不能正常收发消息**就能分开这两种:能收发 ⇒ 是这一页的问题,不是配对的问题。

### 1.4 「记忆库」页

- **怎么做**:点「记忆库」。
- **应该看到**:记忆条目列得出来;**溯源信息还在**(来自哪个项目、覆盖几条会话、原文删没删)。
- **看到别的说明什么**:
  - ★ **溯源那几条不再是可点的链接** —— **这是有意的**(D114 裁定④):它读的是客户端独占的
    `chat.json` / `projects.json`,跨进程读会踩「每个 json 只有一个写者」那条纪律。
    **P3a 的硬线是「每条可溯源」,溯源仍然在;少掉的只是"一键跳过去"。别把这个记成回归。**
  - 条目一条都没有 ⇒ 记忆库连不上,那是另一条线(记忆套件 B 档),记下来别在这儿修。

## 3. 副机:**拉得到主机已有的共享会话**

> ★ 这是 D113(V15)那条修复的**唯一验收口径**。
> ★★ 而 V15 自己写着:**它没有在真机上复现过那句症状** —— 所以这一格是**第一次真验**。

- **怎么做**:
  1. 主机上开一个会话,把它**提升为共享**,说几句;
  2. 副机上**关掉客户端**,再打开(冷启动);
  3. 副机上看那个共享会话。
- **应该看到**:副机上**能看到整段对话**,不用等、不用手动刷新。
- **看到别的说明什么**(★ 这一列是本格的价值):
  - 副机说「已同步」而**一条都没有** ⇒ 那是 D113 §0 那三条路里的**第四格**。
    **现在它会自己说话**:界面上应有一行「**★ 还没跟中枢对齐(拉全量没成)——
    这台机器上现在可能少了对方的改动**」。**把那行原文抄下来**,并去主机
    `{state}\shared\withheld\` 看有没有被扣下的东西;
  - 副机要**手动进设置滑到底**才开始连 ⇒ 那是 08-07 实机记下的 ⚠,**这一趟要确认它还在不在**。
