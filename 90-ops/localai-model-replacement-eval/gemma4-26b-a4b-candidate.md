\## 为什么值得测



\- 更新一代推理 / 代码上限;256K 原生长上下文

\- 一个大模型可能同时服务 deep + vision(但见下方权衡)

\- QAT 文件比现 Qwen3 Q4 更小;MTP 推测解码可能提速



\## 显存约束(本机,不可绕过)



\- desktop\_floor = 6.6 GiB(实测冻结)→ 日常 AI 预算仅 8.52 GiB

\- 故 Gemma 4 不能日常全 GPU 常驻:按需加载 · CPU-MoE 混合放置 · Broker 选卸载度 · 与 ComfyUI/游戏互斥 · 空闲卸载

\- 9950X + 64GB 很适合 MoE 混合放置,本机表现可能优于多数 8GB 社区测试



\## 评测矩阵(B15 55 题 + 本项目三条补充)



| 测试 | 目的 |

|---|---|

| 32K 无 MTP | 纯模型质量与速度 |

| 32K 有 MTP | A/B:你的任务是否真加速(batch=1 收益不保证,MTP 草稿模型显存要计进 8.52) |

| GPU 驻留 \~11.9 GiB | 与 Qwen 同资源比 |

| GPU 驻留 ≤ 8.52 GiB | 能否进日常桌面预算 |

| 64K/128K | 验证长上下文(不追 256K 宣传值) |

| 中/日文 · 工具提案 · 安全题(B15) | 能否进家庭管家与 Agent |

| 补1 视觉分频率档 | "重视觉推理"vs"高频随手看图"分开测。可能结论:vlm.small 留作轻量常驻,Gemma 做重视觉按需,不是二选一 |

| 补2 冷加载延迟 | 按需+互斥模型,14.2GB 放置+CPU-MoE 初始化耗时直接决定手感。B15 原矩阵缺此维 |

| 补3 扩充视觉评测项 | B15 是为 deep(中日文/工具/安全)设计,大概率不含视觉题;竞争 vision 必须补视觉用例 |
